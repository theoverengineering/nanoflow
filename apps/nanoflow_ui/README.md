# nanoflow_ui

Приложение для macOS на Flutter: показывает граф воркфлоу из файла графа и
его сессии вживую. Что оно делает — [ТЗ интерфейса](../../docs/ui-spec.md):
стартовый экран, экран графа и окно деталей эффекта над ним.

Оно вне pub workspace, со своим `pubspec.lock`
([README](../../README.md#репозиторий)): зависимости ставит
`flutter pub get` в этом каталоге.

## Экраны

| Файл             | Что                                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `lib/app.dart`   | приложение: стартовый экран ↔ экран графа                                                                                              |
| `lib/start/`     | стартовый экран, недавние графы (в `shared_preferences`)                                                                               |
| `lib/graph/`     | экран графа (ниже)                                                                                                                     |
| `lib/theme.dart` | цвета и стили текста из [макетов](../../docs/design/); прерванное — приглушённым серым, не янтарём идущего                             |
| `lib/platform/`  | Finder, редактор, буфер обмена, `~`                                                                                                    |
| `lib/state/`     | данные экрана графа (ниже)                                                                                                             |
| `lib/widgets/`   | общие виджеты: пунктирная рамка, кликабельное, точка статуса, знак «идёт», заметка о сбое, значки, строка пути с кнопками, копирование, документация: её текст и подсказка с ней |

Шрифты макетов — Geist и Geist Mono — лежат в `assets/fonts/` (SIL OFL,
`OFL.txt`). Песочницы macOS нет: приложение читает каталог `runs`, который
пользователь не выбирал.

## Экран графа

`lib/graph/graph_screen.dart` собирает экран и владеет его `GraphModel`:
создаёт его, когда граф открыт, и освобождает вместе со слежением за
файлами, когда с экрана уходят или приложение закрывают. Приложение
выходит, дождавшись, пока лента читателя остановится (`GraphModel.close`):
с ней кончается слежение за процессами-владельцами, а Dart VM, завершаясь,
ждёт каждый свой изолят. На холсте один
уровень графа: двойной клик по вызову рисует тело его функции (у вызова
метода интерфейса — сначала выбор реализации), по копиям — тело копии;
крошка в шапке возвращает на свой уровень. Кнопка `+` на вызове или копиях
рисует то же тело на месте, в рамке (решение 6), выбор реализации — так же;
`−` рамки сворачивает её. Под холстом — `Logs`, над всем — окно деталей
эффекта.

| Файл                   | Что                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `header.dart`          | шапка: `Graphs`, файл, крошки уровней (`release › publish()`), у каждой — документация функции уровня в подсказке; крошка выше нарисованного возвращает на свой уровень, шеврон у первой выбирает воркфлоу, когда их несколько, и отмечает те, которых нет в файле; средние крошки, которым нет места, сворачиваются в `…` со списком, в самом узком окне — и крошка воркфлоу (шеврон остаётся впереди); каталог; метка `Live` (или что не так с файлом), `Reveal in Finder`, `Open in editor` |
| `sessions_column.dart` | `Current graph`, карточки сессий с полосой статуса, `Interrupted after …` с подсказкой, число эффектов; отдельной строкой под ними `1 failed`, `other code` или `not checked`, `resumed on changed code` и `Log read incompletely` (почему — в подсказке); `No sessions yet`                                                                                                                                                                |
| `session_bar.dart`     | строка сессии поверх холста (у прерванной — `interrupted after …` с подсказкой, у продолженной на изменённом коде — `resumed on changed code`), заметки — под ней; при `Current graph` её нет                                                                                                                                                                                                                                               |
| `graph_notes.dart`     | поверх холста: файл недоступен или не читается, граф может не соответствовать коду, предупреждения; у сессии — нет снимка, другой код, не проверено, эффекты не на графе; сессии воркфлоу, которых нет в файле графа                                                                                                                                                                                                                        |
| `copy_switcher.dart`   | переключатель копий в шапке рамки: `all · 1 ✓ · 2 ● · 3 ●`, подсказка из выхода первого эффекта над номером; копий больше 12 — список с поиском и фильтром `running` (у прерванной сессии — `interrupted`) / `failed` / `done`; у прерванной копии — пауза; пока рамка вокруг показывает все копии — `choose the outer pkg first`                                                                                                           |
| `split_view.dart`      | две панели с границей, которую тянут; панель можно свернуть до заголовка                                                                                                                                                                                                                                                                                                                                                                    |

Заметки о файле графа видны при `Current graph`, заметки о сессии — при
сессии: у неё на холсте её собственный снимок. Метка в шапке видна всегда.

## Logs

`lib/graph/logs/` — панель под холстом: лента эффектов сессии (при выбранной
копии — её эффектов) и детали выбранного эффекта. Строки, заголовок и шкалу дают
`lib/state/`, панель их только рисует. При `Current graph` она пуста; шеврон
сворачивает её до заголовка.

| Файл                       | Что                                                                                                                          |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `logs_panel.dart`          | заголовок `8 effects` или `copy 2 · 3 effects`, лента слева, детали справа                                                   |
| `effect_list.dart`         | строки эффектов, ошибка или `not on the graph`, `copy 2` при всех копиях, `2 starts`, конец сессии, `↑ 8 earlier effects`    |
| `effect_bar.dart`          | знак эффекта (у прерванного — пауза) и его полоса на шкале сессии, штрихованная у идущего, у прерванного — рамка без заливки |
| `effect_details_pane.dart` | имя эффекта, вкладки `Output` и `Log` (входа у эффекта нет), `following tail`, `Open`                                        |
| `log_view.dart`            | лог эффекта: держится за хвостом, пока его не прокрутили вверх                                                               |
| `document_view.dart`       | документ как JSON; что вкладка пишет вместо данных, ошибка упавшего эффекта                                                  |
| `mono_lines.dart`          | строки лога и документа: строятся только видимые, длинные не переносятся, а прокручиваются вбок; `Show all`                  |
| `file_footer.dart`         | файл открытой вкладки от каталога графа, `Finder`, `Editor`, копировать путь                                                 |

Клик по эффекту выбирает его и сдвигает холст к узлу, если тот не виден, — или
к вызову либо копиям, внутри которых эффект, а когда они раскрыты на месте, — к
узлу эффекта в их рамке (`GraphCanvasController.revealNode`); выбранная строка
всегда в поле видимости, при слежении — и строки после неё. Лог открывается на
конце — и когда к нему возвращаются с другой вкладки — и держится за хвостом,
пока его не прокрутили вверх. Большой лог показан последними 1000 строками,
большой документ — первыми, до `Show all`; строки длиннее 2000 символов до него
обрезаны — `Show all` есть и тогда, когда длинна только строка.

Кнопка `Open` открывает окно деталей выбранного эффекта.

## Окно деталей эффекта

`lib/graph/details/` — окно над всем экраном графа, вокруг — точки: один эффект.
Входа у эффекта нет: слева — место в коде и факты эффекта, справа — выход и лог,
у упавшего — ошибка со стеком. Открывают его `Open` в `Logs` (выбранный эффект)
и двойной клик по эффекту на холсте: его последний заход среди показанных
эффектов, иначе только имя и место узла. Заход, который показывает окно,
выбирается, и холст с `Logs` под окном стоят на нём. Слежение при этом идёт как
всегда: если заход — последний эффект идущей сессии, выбор переходит на новые
эффекты, а окно остаётся на своём заходе; закрыли окно (`Back to canvas`, × или
Esc) — холст и `Logs` на последнем эффекте. Что показывать, решает
`lib/state/visit_details.dart`; окно слушает `GraphModel` и часы.

## Холст

`lib/graph/canvas/` — холст графа: раскладка одного уровня
(`CanvasGraph.levels`) из `lib/layout/`. Холст слушает `GraphModel`; двойной
клик по вызову или копиям — `onOpenNode`, по эффекту — `onOpenEffect`, клик —
выбор последнего эффекта узла; `GraphCanvasController.revealNode` сдвигает
холст к узлу, если тот не виден. Тело копий нарисовано в их рамке:
стопка контуров, `each pkg in packages`, `×3 · in parallel`, переключатель
копий, внизу `done 1 of 3` или `pkg 2 · now verify`.

Узлы, раскрытые на месте (`+` — `onExpandNode`), — рамки с их телом в
раскладке уровня: у вызова серая обводка, `publish()` и `−`; у копий та же
рамка-стопка, что у открытого тела, с переключателем, подписью внизу и
`−`. Стрелка в рамку идёт сквозь её сторону дальше, к первому узлу тела
(`code-first/function-frames.html`); конец тела — планка на правой стороне
рамки, как планка входа плитки: стрелки к концу указывают на неё каждая на
своей высоте, стрелки дальше выходят из неё — кружка выхода и капсулы у
рамки нет (макет рисует кружок). В рамке всё как на уровне: отметки
эффектов, клик, двойной клик, `+`; у узла в рамке на холсте путь из id —
`5/2`. Раскрытый или свёрнутый узел остаётся на месте экрана, а пока вид
таков, каким его оставило вписывание, граф вписывается заново; то, что
меняет в рамке сессия (место под переключатель копий), вид не трогает.

## Раскладка графа

`lib/layout/` — где на холсте узлы, выходы и стрелки, по
[алгоритму](../../docs/graph-layout.md). Чистый Dart: Flutter и `dart:ui`
не импортируются, тесты идут на Dart VM.

```dart
final layout = layoutBody(body, functions: file.functions); // GraphLayout
checkLayout(layout); // нарушения правил шага 9, пусто — всё хорошо
countCrossings(layout); // сколько раз стрелки пересекаются
```

Раскладывается одно тело (`GraphBody`): маркер `start`, из которого
выходят рёбра `from: null`, узлы тела и по маркеру `end` на каждое ребро
`to: null` — путь кончается рядом с узлом, откуда выходит. Рёбра узла с
одной подписью — один выход, несколько таких рёбер — капсула.

Вызовы и копии из `expanded` раскрыты на месте (`layoutBody(…, expanded:
{'5': ExpandedNode(body)})`): узел — рамка вокруг раскладки своего тела
(`NodeBox.frame`), с местом под заголовок и по сторонам (`FrameRoom`); в
раскладке уровня он узел размером с рамку, слой — шириной с самый широкий
узел, и стрелка из более узкого поворачивает у него, если в слое ей ничто
не мешает. У тела в рамке `start` — один в первом слое, а `end` — один, после
всего остального, и оба — порты (`NodeBox.port`): точки на сторонах рамки
без ширины и без плитки. Стрелки уровня входят в левую сторону рамки на
высоте `start`, и стрелки тела идут оттуда дальше. У `end` — планка входа,
как у плитки, серединой ширины на правой стороне рамки
(`FrameBox.endBar`): стрелки тела к `end` указывают на неё каждая на своей
высоте, стрелки уровня выходят из неё — одна из середины, несколько
(капсула) вокруг середины, — и планка выступает за крайние из них, как за
крайние входы. `end` стоит там, где на уровне входов приходит больше всего
стрелок: пачка длинных стрелок, прижатая узлами тела, идёт к планке прямо
от своего поворота, а не каждая с изломом перед ней. Дорожки перед `end` —
обратных стрелок и петель последних узлов тела — держатся от правой
стороны рамки на её обводку
(`frameOutline`, такой её рисует холст) и зазор, как от подписи, мимо
которой идут (`sideClearance`); дорожки уровня перед рамкой — от её левой
стороны на зазор, контуры за копиями — отметка над рамкой и вдоль её правой
стороны. `checkLayout` находит стрелку тела или уровня, которая идёт вдоль
стороны рамки ближе. Если рамка шире тела (длинный заголовок) или имя под
узлом перед `end` заходит за него, стрелки к `end` тянутся до правой
стороны; связка от левой стороны к `start` — если за него заходит имя под
узлом после него. Рамки в рамках — так же, на любой глубине; координаты
тела в рамке — координаты раскладки вокруг.

В `GraphLayout` всё, что рисует холст: плитки, имена (длиннее 30 знаков —
с `…`) и места в коде, что написано в плитке (`start`; у вызова и копий —
`{ 3 }`, сколько эффектов может пройти ниже, через вызовы и копии, рекурсия
не считается дважды), место под метки, под плитки стопки копий и `×n`,
планки входов, выходы (точка, капсула), подписи (`true`, `each`, исходник
случая), стрелки — ломаная, остриё и куски для рисования со скруглёнными
углами. Координаты от (0, 0). Ширину текста считает
`LayoutOptions.measure`; по умолчанию — приближение моноширинным шрифтом
макета, холст передаст настоящую.

## Отступления от ТЗ

Где буква [ТЗ](../../docs/ui-spec.md) не помещается на экран или не
выполнима геометрически, приложение делает так:

- **Узкое окно.** `following tail` сжимается до жёлтой точки, слова — в
  подсказке, когда заголовок деталей эффекта уже 440 px; колонка таймлайна в
  ленте эффектов пропадает, когда ей остаётся меньше 40 px. В окне макетов
  видно всё.
- **Нет графа — нет кнопок масштаба.** При `No valid graph yet` и у сессии,
  чей граф не читается, масштабировать нечего, и кнопок нет, хотя у
  `Current graph` по ТЗ они остаются.
- **Радиус скругления меньше**, где излом короче двух скруглений: углы не
  могут занять больше половины отрезка. Так выходит, например, у развилки,
  все исходы которой ведут в один узел, — `describe` такую развилку не
  рисует, она бывает только в графах, записанных руками.

Графы для тестов — файлы графа в `test/layout/graphs/`, снятые вручную, по
одному разу; за выводом `describe` они сами не следуют:

- **`review`** — копия `examples/review/nanoflow.graph.json`; снять заново —
  скопировать её.
- **`release`, `inline`, `control` и другие образцы `nanoflow_describe`**
  (`packages/nanoflow_describe/test/fixtures/<имя>/`) — `toJson()` графа из
  `describePackage(<каталог образца>, packageName: '<имя>')`, с отступом в 2
  пробела. Скрипта для этого в репозитории нет: изменился вывод `describe` —
  снимают так же заново.
- **Прежние графы тестов раскладки** (`task` из макета, петли, капсулы,
  длинные стрелки) — записаны функциями руками, с отпечатком `sha256:0`.
- **`task-carry`** — вывод `describe` воркфлоу задачи вне репозитория:
  `task` вызывает `carry`, чей `while (true) { switch … }` возвращается от
  `work()`, `review()` и `decide()`, последних узлов перед концом. На нём
  `carry()`, раскрытый на месте, — обратные стрелки у правой стороны рамки.
  Снять заново негде: изменился формат — правят руками.
- **`chain`** — вывод `describe` того же проекта позже, с цепочкой фаз
  `lib/chain.dart`: `lead` вызывает `judgeSpec`, из глубины тела которого —
  `switch (decision.choice)`, цикл `while (refused != null)`, развилки
  `!answer.goesOn` — к концу возвращаются восемь путей. На нём
  `judgeSpec()`, раскрытый на месте, — стрелки к планке конца прямо от
  своего поворота. Снять заново негде, как и `task-carry`.
- **`chain-later`** — тот же проект ещё позже: `lead` вызывает `specify`, а
  тот — `judgeSpec`. На нём `specify()` и `judgeSpec()`, раскрытые в `lead`,
  — самый тесный размен высоты на повороты, который пропускает раскладка, и
  `write()`, `writeCut()` и `decide()` в рамке — стрелки, обходящие узел в
  середине тела, к которым подтягивается конец. Снять заново негде.

видна самая новая сессия и вся история и самый долгий кадр при загрузке и
после: новая сессия должна быть видна быстрее 3 секунд, кадр — короче
секунды при загрузке и полсекунды после. Замеры видны в причине провала;
`reportData` их тоже получает, но в файл его пишет только `flutter drive`,
а не `flutter test`.

```bash
flutter test integration_test/history_test.dart -d macos
```
