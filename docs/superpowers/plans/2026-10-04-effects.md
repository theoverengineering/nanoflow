# Effects and Passed Forks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the step to the effect everywhere, adopt the rule «any side effect but logs is inside an `effect`» with `describe` warnings, and mark on a session's graph the forks its code went through and the ways it took — derived from the journal's `after`, without the UI knowing the language.

**Architecture:** A mechanical rename across the format, the packages and the UI (graph file `format` 2). `describe` walks the code between effects — graph functions and what they call in the package — and warns about calls into `dart:io`, `DateTime.now`, `Random`, `Stopwatch`. A pure UI module `passes.dart` turns consecutive effects (`after`) into paths on the drawn body: forks on every path are passed, edges on every path are taken; `GraphMarks` and `CanvasMarks` draw them.

**Tech Stack:** Dart 3.13, `package:analyzer` 14.4 (new element model), Flutter 3.47 (macOS app), `package:test`, `flutter_test`.

**Design:** `docs/superpowers/specs/2026-10-04-effects-design.md` (Russian) — the source of truth; read it first. Main spec: `docs/superpowers/specs/2026-10-03-code-first-design.md`; owner spec: `docs/superpowers/specs/2026-10-03-session-owner-design.md`.

## Decisions

- **D1 — What «step» means.** Rename only where «step» means the unit of work (a step of a workflow). Keep it where it means something else: `stackStep` (how far a stacked tile is offset), `_zoomStep`, `_minStep` and any other spacing or increment, the path `prototypes/step_keys`, and test or plan wording like «Step 1». When unsure, read the declaration's doc comment.
- **D2 — Graph file format.** `GraphFile.format` becomes `2`; `GraphFile.fromJson` refuses any other value with a `FormatException` naming the field (`format: expected 2`), which the UI already shows as an unreadable file.
- **D3 — No migration.** Old sessions and graph files are not read. Delete `examples/review/runs/` (git-ignored) and regenerate every checked-in graph file and recorded fixture with the tools that made them (`dart run nanoflow_describe`, `tests/e2e/tool/record_copies.dart`, and the UI layout graphs' own recipe in `apps/nanoflow_ui/README.md`).
- **D4 — Side-effect detection.** Exactly design §3. The check lives in `packages/nanoflow_describe/lib/src/side_effects.dart`, called by `describePackage` after extraction; it adds `GraphWarning`s to the same list. Elements are matched by their library URI (`dart:io`, `dart:core`, `dart:math`) and name, never by source text.
- **D5 — Passes API.** In `apps/nanoflow_ui/lib/state/passes.dart`:

  ```dart
  /// The forks the shown effects went through on [body] and the edges
  /// they took (effects design §5).
  final class Passes {
    factory Passes.of(
      GraphBody body, {
      required EffectPlaces places,
      required SessionData session,
      required Iterable<EffectState> effects,
    });
    static const none = Passes._({}, {}, {});
    /// How many transitions went through the fork [nodeId]; 0 when none.
    int of(String nodeId);
    /// Whether the edge at [index] of `body.edges` was taken.
    bool taken(int index);
    /// Whether the edge at [index] leaves a passed fork and no transition
    /// took it.
    bool untaken(int index);
  }
  ```

  `EffectPlaces` is today's `StepPlaces` after the rename; `effects` is the scope the marks use today (whole session, a copy, all copies). The session is finished when its replayed status is finished (`session-finished`).
- **D6 — Marks.** `GraphMarks.of` gives every `ConditionNode` of the body `NodeMarks(state: passes > 0 ? visited : notVisited, steps: passes, running: 0)` (after the rename the field is `effects`). `CanvasMarks.edge(EdgePath e)` is `Tone.untaken` when today's rule says so or, outside the all-copies view, when `passes.untaken(e.listIndex)`. In the all-copies view a fork's count badge is not shown (as for effects whose copies all passed).

**Interfaces:**
- Consumes: `EffectPlaces` (`isIn(record, node)`, the nodes of a body), `SessionData` (`effects` records by id with `key` and `after`, replayed state and status), the shown-effects scope the marks already use.
- Produces: D5 `Passes`.

- [ ] **Step 1: Failing tests** over hand-built bodies (the test file builds small `GraphBody`s and journals with the existing helpers in `test/state/support.dart`):
  - `if`: `a → (c?) → b | d` and the session ran `a, b` → the fork passed once, edge `c→b` (`true`) taken, edge `c→d` untaken;
  - loop: the review graph (`test/layout/graphs/review.graph.json`) with effects `collect, inspect, fix, inspect, publish, notify` → `change.path.isEmpty` passed 1×, its `false` edge taken, `true` edge untaken; `report.findings.isEmpty` passed 2×, both its edges taken; the back edge `fix → inspect` taken;
  - `switch` with three cases → only the taken case's edge taken, the others untaken;
  - two forks that merge before the next effect (`a → f1 → (g | f2 → (h | g))`, effects `a, g`) → `f1` passed; `f2` not passed (it is not on every path); no edge of `f1` marked taken unless it is on every path;
  - a call with no effects on the way (`a → call(empty) → b`) → the fork after the call passed, the call node does not block the path;
  - level of a function: the body of `publish()` with its effects entered from `plan` outside → the path from the body's start; its last effect followed by an effect outside → the path to the body's end;
  - finished session: the last effect → the workflow's end (a fork after it marked); the same journal without `session-finished` (running) and with `session-failed` → nothing after the last effect;
  - copies: the copies body with three copies that take different exits of a fork → each copy (scope = its effects) marks its own exit; all copies (scope = all) → the fork passed 3×, both exits taken; the last effect of a copy → the body's end only when the session finished; at the top level a copy's effects map to the `copies` node and give no transition to the workflow's end;
  - no path (an effect at a place not on the graph, or a pair with an effect node in between) → nothing marked;
  - an effect on two nodes (a `finally` drawn twice) → transitions from both, forks on every path of every pair.
- [ ] **Step 2:** Run; see them fail (no `passes.dart`).
- [ ] **Step 3:** Implement design §5.1–§5.2 exactly: positions by `EffectPlaces`; predecessor by key; the transition table; the end-of-session rule (effect or call node only, not copies); simple paths over the body's edges (back edges included) whose inner nodes are forks, calls or copies only; intersections; counts. Memoise per (body, session change count, scope) as the other state modules do; no per-tick rescans of the whole session beyond what the marks already do.
- [ ] **Step 4:** Recorded fixture: write `record_review.dart`, run it into `apps/nanoflow_ui/test/state/fixtures/review/`, and add a `passes_test` group over it asserting the loop case above on the real library's `after` values.
- [ ] **Step 5:** All UI tests, analyzers, `tool/ci.sh` pass. Commit (why: the journal's `after` already tells which way the code went between two effects, so the forks can be marked without evaluating any condition).
