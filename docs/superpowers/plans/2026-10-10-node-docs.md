# Node Docs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `describe` puts the doc comments of functions and effects into the graph file (format 3), and the app shows them: tooltips on effect and call tiles, function frame titles and crumbs, a `Doc` section in the effect details window.

**Architecture:** `GraphFunction.doc` and `EffectNode.doc` in `nanoflow_model`, format 3, format 2 read with `doc: null` by upgrading its JSON before parsing. `extract.dart` reads a declaration's `documentationComment` and, for an effect, the `///` run right before it (its own expression or the simple statement it is the only effect of). The app parses the text into a small Markdown subset (pure Dart, `lib/state/doc_text.dart`), renders it as spans (`lib/widgets/doc_text.dart`) in a `DocTooltip` and in the details window.

**Tech Stack:** Dart 3.13 workspace, `analyzer`, Flutter 3.47 macOS app, `test`/`flutter_test`, goldens.

**Spec:** `docs/superpowers/specs/2026-10-10-node-docs-design.md` (Russian) — the source of truth.

## Global Constraints

- Every model field is always in the JSON, `null` when it has no value; `doc` is written after `place` (function: `name, place, doc, body`; effect: `id, kind, name, place, doc`).
- `graphFileFormat == 3`; `GraphFile.fromJson` reads formats 2 and 3 only; any other format: `format: expected 3, the file is N`.
- `apps/nanoflow_ui/lib/layout/` and `lib/state/` never import Flutter.
- `flutter analyze`, `dart analyze --fatal-infos`, `dart format --output=none --set-exit-if-changed .` clean; `tool/ci.sh` exits 0; test output pristine.
- Commit messages: imperative subject that says **why**; end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- TDD; look at every regenerated golden.

## Review Focus

- A session started before format 3 (its snapshot is format 2) still draws its graph — test: a format-2 snapshot in a session reads with `doc: null`, the canvas draws it (model test + `readGraphFile`).
- `///` above `await Future.wait([...])` with two effects attaches to neither — extract test.
- `///` above a `while`/`if` containing one effect does not attach to it — extract test.
- A tile with a doc tooltip still selects on click and opens on double click — widget test.
- A doc with only blank `///` lines is `null`, not `""` — extract test.

### Task 2: `describe` reads doc comments

**Files:**
- Modify: `packages/nanoflow_describe/lib/src/extract.dart` (`_Declaration.doc`, `_Effect.doc`, `docOf`)
- Create: `packages/nanoflow_describe/test/fixtures/docs/lib/docs.dart`
- Test: `packages/nanoflow_describe/test/extract_test.dart` (helper fills `doc: null` where an expectation has none; recursion and release expectations get their functions' docs; a `docs` fixture test)
- Modify: `examples/review/lib/review.dart` (`///` over each effect), `examples/review/nanoflow.graph.json` (written by `dart run nanoflow_describe`), `examples/review/README.md` if it quotes the code.
- Docs: `packages/nanoflow_describe/README.md` («Что внутри»), code-first-design §7.1.

**Interfaces — Produces:** `String? docText(List<Token> comments)` (top-level in extract.dart, `@visibleForTesting` not needed): the text of a doc comment's tokens per spec §2; `null` when empty.

Rules (spec §2):
- Function: `FunctionDeclaration.documentationComment` / `MethodDeclaration.documentationComment` → `docText(comment.tokens)`.
- Effect: from the `f.effect` invocation go up through its ancestors, stopping at the first `FunctionBody` (excluded) or `Statement`; a `Statement` is included only when it is an `ExpressionStatement`, `VariableDeclarationStatement`, `ReturnStatement` or `YieldStatement`. For each ancestor take the doc run before its `beginToken`; the first found belongs to the effect when the outermost of these ancestors starting at that token holds exactly one `isEffect` invocation; otherwise `null`.
- Doc run: walk `token.precedingComments` (linked by `next`); keep the trailing run of `///` tokens (a non-doc comment resets it) or a trailing `/** */` token.
- Text: `///` → drop `///` and one space; `/**` → drop `/**`, `*/`, and per line leading spaces, one `*`, one space; trim blank lines at both ends; empty → `null`.

- [ ] **Step 1: Failing tests.** `docs` fixture with a workflow documented by `///`, a method documented by `/** */`, and effects: documented expression statement, variable declaration, `return`, two documented list elements in `Future.wait`, `///` over a `Future.wait` statement with two effects (both `null`), `///` over `if` and over `while` holding one effect (`null`), `//` comment (`null`), a `///` run broken by `//` (only the tail), only blank `///` lines (`null`). Expect the exact `doc` strings; `review` fixture unchanged apart from `doc: null`; recursion/release functions carry their docs.
- [ ] **Step 2:** `cd packages/nanoflow_describe && dart test` — fails.
- [ ] **Step 3:** Implement; `expectedFile` writes `'format': 3`.
- [ ] **Step 4:** Tests pass. Add `///` over the example's six effects; `cd examples/review && dart run nanoflow_describe`; `--check` exits 0; look at the file: the workflow's and effects' docs are there.
- [ ] **Step 5:** Docs; commit (why: so the graph file says what each function and effect does).
