# Прямые стрелки в случаи `switch` по известному значению

Меняет [дизайн code-first](2026-10-03-code-first-design.md), §7.1
«Извлечение», и README пакета `nanoflow_describe`, «Граф тела». Решение 13
в [журнале](2026-10-02-code-first-decisions.md). Решения приняты
2026-10-08.

## 1. Зачем

В воркфлоу `agreeSpec` петля `writeSpec → reviewSpec → writeSpec` начинается
то с `writeSpec` (спек не написан), то с `reviewSpec` (написан и ждёт
ревью). Структурный код в середину цикла не входит, поэтому приходится либо
звать `writeSpec` из двух мест — две плитки одной функции, — либо нести
флаг и проверять его внутри: развилка `writer != null`, которая повторяет
решение, уже принятое развилками `!spec.written`, `session != null`,
`idea == null`.

Хочется писать «дальше — узел X»: `stage = Stage.writeSpec; continue loop`
при `loop: while (true) switch (stage) { … }`. Узел — `case`, его работа —
обычная функция, которая о соседях не знает; что идёт после узла, записано
только в его `case`, и попасть туда можно из любого места тела.

Сегодня `describe` рисует такой код как одну центральную развилку
`switch (stage)`, через которую идут все переходы: по картинке не видно, какой
переход куда ведёт, а обратные стрелки сливаются в одну. Нужно, чтобы стрелка
шла прямо оттуда, где `stage` присвоен, в тело случая, а развилки `switch`
не было.

Обсуждались и отвергнуты: узлы как сущности библиотеки с объявлением связей
(`Graph([...])`, как в первой версии) и хвостовая передача `f.go(…)`
(решение 13 в журнале). Библиотека, формат файла графа, UI и рантайм не
меняются: меняется только чтение кода.

## 2. Решение

- **Когда.** Оператор `switch`, чей предмет — локальная переменная или
  параметр этого тела (не поле, не переменная верхнего уровня, не
  выражение), и путь, приходящий к нему с известным значением: последнее на
  этом пути присваивание переменной — константа (значение `enum`,
  `true`/`false`, литерал числа или строки), или её объявление с такой
  константой и присваиваний после него на пути нет.
- **Куда.** Такой путь идёт стрелкой прямо в тело случая, которому значение
  подходит, минуя развилку: первый `case` с той же константой
  (`case Stage.coder:`); нет такого — `default` или `case _`; нет и их —
  путь идёт через развилку, как путь с неизвестным значением. Случаи без
  своих операторов делят тело со следующим, как сейчас.
- **Развилка `switch (x)`** рисуется только для путей с неизвестным
  значением; ни одного такого — не рисуется, вместе со своими исходами.
- **Откуда приходят пути.** Из кода перед `switch` и через голову цикла
  `while (true)`, тело которого — этот `switch` (сам или первый оператор
  блока): `continue` этого цикла и обычный конец его тела
  (`break` из `switch`) приходят к `switch` каждый со своим значением.
  Голова такого цикла пути не склеивает.
- **По пути, не по месту.** Ветки `if` перед циклом, каждая со своим
  `stage = …`, приходят каждая в свой случай; стрелка из развилки несёт
  подпись её исхода (`true`/`false`), как любое ребро развилки. Значение
  известно только пока путь от присваивания до `switch` не прошёл через
  голову другого цикла или конец `do`: там пути сливаются, и значение
  теряется.
- **Не отслеживается** — все значения неизвестны, рисуется как сегодня —
  переменная, которой присваивают в замыкании, локальной функции или
  выражением не в своём операторе (`f(stage = X)`); любое присваивание не
  константы (`stage = next()`, `stage ??= …`) делает значение на своём пути
  неизвестным.
- **Недостижимое не рисуется:** случай, в который не идёт ни один путь,
  развилка `switch`, которую все обошли.
- **Пример.** `agreeSpec` с `stage`, выбранным до цикла:

  ```dart
  if (!spec.written) {
    if (session != null) {
      launch = Launch.resume(session, conversationInterrupted);
    } else if (idea == null) {
      throw noIdea(name);
    } else {
      launch = Launch.fresh(begin(name), Handed('human', idea));
    }
    stage = Stage.writeSpec;
  } else {
    stage = Stage.reviewSpec;
  }
  loop:
  while (true) {
    switch (stage) {
      case Stage.writeSpec:
        final written = await writeSpec(flow, specification, actions, launch);
        session = written.session;
        stage = Stage.reviewSpec;
        continue loop;
      case Stage.reviewSpec:
        final verdict = await reviewSpec(flow, specification, actions);
        if (!verdict.passed) {
          launch = Launch.on(session, …);
          stage = Stage.writeSpec;
          continue loop;
        }
        …
        return;
    }
  }
  ```

  Узлы: развилки `!spec.written`, `session != null`, `idea == null`, вызовы
  `writeSpec()` и `reviewSpec()`, развилка `!verdict.passed`. Стрелки:
  `!spec.written` false → `reviewSpec`; `session != null` true →
  `writeSpec`; `idea == null` true — обрыв, false → `writeSpec`; `writeSpec`
  → `reviewSpec`; `!verdict.passed` true → `writeSpec` (обратная). Развилки
  `switch (stage)` нет, `writeSpec` — одна плитка с тремя входами. Макет —
  `docs/design/agree-spec.png`.

- **Что не меняется.** Формат файла графа, раскладка, UI, рантайм, ключи
  эффектов. Пройденные развилки и рёбра считаются по журналу, как прежде:
  прямая стрелка — обычное ребро уровня.

## 3. Тесты

- `describe`, фикстура `stages`: `loop: while (true) switch (stage)` с
  `stage`, выбранным ветками `if` до цикла (каждая ветка — стрелка в свой
  случай с подписью исхода); случай с одним эффектом и `stage = …;
  continue loop` (прямая стрелка, обратная — пунктир в файле не отличается,
  это обычное ребро назад); случай, где `if` выбирает один из двух
  переходов; случай с `return` и случай с `throw`; `break` из `switch`
  (путь в тот же случай); `default`, в который попадает константа без своего
  `case`; развилка `switch (stage)` не рисуется. Отдельно: путь с
  `stage = next()` — развилка нарисована, в неё ведёт только этот путь,
  остальные — прямо в случаи; `stage`, присвоенный в замыкании, — всё как
  сегодня, одна развилка; `switch` вне цикла с известным значением
  (`final x = A; switch (x)`) — прямая стрелка без развилки; `switch` по
  полю — как сегодня. Файл одинаков байт в байт при повторе.
- Фикстуры `describe` и файл графа примера перечитаны `describe`;
  `--check` проходит (у них таких `switch` нет — ничего не меняется).
- README пакета `nanoflow_describe` («Граф тела») и §7.1 дизайна —
  по абзацу о прямых стрелках; README корня — одна строка в «Извлечение
  графа».
