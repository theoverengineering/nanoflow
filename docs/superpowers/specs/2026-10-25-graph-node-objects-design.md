# Узел — `node(...)`, переход — функция

Заменяет форму графа из узлов из [дизайна графа](2026-10-08-graph-nodes-design.md):
узлы-функции, карты `{ключ: цель}`, множества в `.next`, `otherwise` и `Exit`
(§2–§5, §7, §9–§10 там). Что там не названо ниже — схождение (§6), ключи
эффектов, граф как воркфлоу, проверки при создании, — остаётся, если ниже не
сказано иначе. Решения приняты 2026-10-25.

## 1. Зачем

- Граф цепочки run-spec в scheduleme нарисован из кода функций воркфлоу: 70
  развилок на 72 эффекта. Технические случаи — агент отказал, оборвался, не
  дал вердикта — стоят на экране рядом со смысловыми. Нужно, чтобы на экране
  были только узлы и понятные связи и сразу было видно, что делается.
- Нынешний граф из узлов ветвит картой `{Passed: x, Failed: y}`. Её не
  проверяет компилятор; ради неё узел возвращает классы-обёртки `Exit`;
  следующий узел получает выход целиком или его груз, а не то, что ему нужно.
- Поэтому: **узел** — `node('имя', (вход) async { … })`, единица работы, как
  эффект; **переход** — обычная функция Dart со `switch` (или любым кодом),
  которая говорит, какой узел следующий и с каким аргументом. Компилятор
  проверяет и полноту `switch`, и тип аргумента.

**Цели.**

- Граф из узлов, где ветвление и аргументы следующего узла — код, проверенный
  компилятором.
- Цепочку run-spec можно переписать так, что её верхний уровень — узлы и
  подписанные стрелки. Само переписывание — следующий, отдельный проект.

**Не цели.**

- Шаги внутри узла со своими записями в журнале: узел, упавший посередине,
  при продолжении начинается заново целиком.
- Копии «по элементу списка» на графе: параллель — объявленная (§4, §5).

**Анти-цели.**

- Переход, который сам делает работу: при продолжении он выполняется заново
  (§7), поэтому всё, что меняет мир, — в узлах.
- Способ «кодом» (функция воркфлоу, решение 13 и раньше) ломается или
  меняется. Код и узлы — два равных способа.

## 2. Как выглядит

```dart
/// The change of the branch, or Empty when it changes nothing.
final collect = node('collect', (String branch) async { … });   // Collected: Empty | Found
final inspect = node('inspect', (Change change) async { … });   // Report
final fix = node('fix', (Report report) async { … });           // Change
final discard = node('discard', (String branch) async => print('nothing to review'));
final publish = node('publish', (Report report) async { … });   // String
final notify = node('notify', (Report report) async { … });     // String
final report = node('report', ((String, String) sent) async { … });

/// Reviews the change of a branch.
final review = Graph<String, void>('review', [
  Graph.start(collect).next((collected) => switch (collected) {
    Empty(:final branch) => discard(branch),
    Found(:final change) => inspect(change),
  }),
  Graph.part(inspect).next((r) => r.findings.isEmpty
      ? {publish(r), notify(r)}
      : fix(r)),
  Graph.part(fix).next((change) => inspect(change)),
  Graph.join([publish, notify]).next(((String, String) sent) => report(sent)),
]);

await flow.run(review.run, 'feature/parse-config');
```

`Empty` и `Found` — обычный `sealed`-класс выхода `collect`, без `Exit`.

## 3. Узел

- `Node<I, O> node<I, O>(String name, FutureOr<O> Function(I input) body)` —
  функция верхнего уровня `package:nanoflow`. Узел объявляется в переменной
  верхнего уровня.
- **Выполняется как эффект сессии:** имя эффекта — `name`, работа —
  `body(input)`, результат пишется в журнал и при продолжении берётся из
  него. Узел, не кончившийся до падения, при продолжении выполняется заново
  целиком.
- **Внутри — обычный Dart:** `exec`, вывод в лог эффекта, вопросы человеку на
  терминале. Своих эффектов внутри нет: у тела нет `Flow`.
- **Тип результата для журнала — `O`**, параметр типа узла: кодек ищется для
  `O`, как для `f.effect<O>` (code-first §4.4; перечисления через
  `flow.addEnum`, записи из двух полей — прежние правила). Поиск типа выхода
  по типу функции (`узел is FutureOr<X> Function(Never)`) уходит.
- **`узел(вход)`** — `Node.call(I input)` — узел не выполняет, а даёт переход
  `Next`: «дальше этот узел с этим входом». Выполняет его библиотека.
- **`узел.body`** — тело, чтобы вызвать работу узла в тестах без графа.
- **Имя** — литерал строки; имена узлов одного графа различны. Документация
  узла — комментарий над его переменной.
- **Узел может быть в нескольких графах** (например, «спросить тебя» — и в
  цепочке, и в графе задачи внутри неё): у каждого графа своя плитка.
- **Место эффекта узла** — место узла в этом графе: строка, где он впервые
  назван в объявлении графа (начало куска или вызов в переходе). Берётся из
  файла графа в каталоге проекта по имени графа и узла, как сейчас; нет
  файла или узла в нём — `null`. У одного узла в двух графах места разные,
  поэтому UI, который сопоставляет эффект плитке по месту и имени, их не
  путает.

## 4. Стрелки и переход

- `Graph.start(узел)` — кусок от узла, с которого начинается граф, его вход —
  вход графа; стартов может быть несколько, они начинаются одновременно.
  `Graph.part(узел)` — кусок от любого узла. Узел здесь — `Node` или `Graph`.
  Кусок типизирован выходом узла: `Graph.part(inspect)` — `Part<Report>`.
- **`.next(Object? Function(O output) route)`** — единственный вид стрелок.
  Когда узел дал выход, библиотека вызывает `route` с ним; результат:
  - `Next` — `узел(вход)` или `граф(вход)`: дальше он, с этим входом;
  - множество переходов `{a(x), b(y)}` — все одновременно (параллель);
  - `null` — ветка кончается, выход узла идёт в результат графа (§6);
  - что-то другое — ошибка графа (`StateError` с именами графа и узла и тем,
    что дал переход).
- **Простая стрелка** — тоже переход: `.next((w) => writeSpec(w))`.
- **Стрелки узла объявляются один раз;** `.next` кончает кусок: второй `.next`
  на нём — ошибка при создании, как стрелки, объявленные дважды. Узел без
  стрелок кончает ветку.
- **Переход должен быть чистым:** он вычисляется заново при каждом
  продолжении по выходу из журнала, и по тому же выходу должен дать то же.
- **Узлы, до которых доходят только переходы** (например, последний, без
  стрелок), заранее перечислять не надо: библиотека узнаёт узел, когда
  переход его вернёт. Узел из перехода с именем, которое в этом графе уже у
  другого узла, — `StateError` при выполнении.

## 5. Схождение

- `Graph.join([a, b, …])` — как в §6 дизайна графа: 2–6 разных узлов, выходы
  копятся по порядку, неполное схождение не наступает, продолжение — из
  ветки первого узла.
- **Переход после схождения** получает запись выходов в порядке списка.
  Кусок схождения не знает её типа, поэтому тип параметра пишется явно:
  `.next(((String, String) sent) => report(sent))`; `describe` сверяет его с
  выходами узлов схождения (§9). Записан не тот тип — `StateError` при
  выполнении: имя графа, узлы схождения и текст `TypeError` вызова.

## 6. Граф целиком

- `Graph<I, O>(String name, List<Part> parts)` — в переменной верхнего
  уровня; документация графа — комментарий над ней.
- **Граф как узел:** `граф(вход)` — `Graph.call(I input)` — переход, как у
  узла. Граф-узел выполняется на месте: его узлы — свои эффекты в журнале,
  граф целиком не одна запись.
- **Граф как воркфлоу:** `Future<O> run(Flow f, I input)` —
  `flow.start(review.run, input)`, `flow.run`, `flow.resume`,
  `flow.unfinished`; из функции воркфлоу — `await review.run(f, x)`. Было
  `call`; `call` теперь — переход. Имя сессии — имя графа.
- **Узлом может быть только `Node` или `Graph`.** Функция воркфлоу узлом не
  бывает; граф из функции воркфлоу вызывается через `run`.
- **Результат** — выход, который никуда не пошёл, последним по времени: узла
  без стрелок и не из схождения или узла, чей переход дал `null`. Узел
  схождения без своих стрелок концом не считается: его выход ушёл в
  схождение (как сейчас). Само схождение без перехода или с переходом, давшим
  `null`, — конец: его запись выходов — результат. Нет такого — `null`;
  результат не `O` — `TypeError`.
- **Граф-узел с концами, идущими одновременно,** — например, параллель без
  схождения или несколько стартов: при продолжении оба конца берутся из
  журнала сразу, и «последний по времени» может оказаться другим, а с ним —
  путь внешнего графа. Правило не меняется; `describe` предупреждает о таком
  графе, когда он узел другого графа (§9).
- **Конец и ошибки** — как сейчас: граф кончается, когда кончились все ветки;
  ошибка узла или перехода — ошибка графа после того, как кончились
  остальные ветки. Ошибки переходов называют граф: один узел бывает в
  нескольких графах.
- **Проверки при создании** (`ArgumentError` со списком): нет старта;
  стрелки узла объявлены дважды; два разных узла одного имени среди начал
  кусков; схождение меньше чем из двух узлов, больше чем из шести или с
  узлом дважды. Что начало куска — `Node` или `Graph`, проверяет компилятор
  (`Nodelike` запечатан). Проверку «до узла не дойти» библиотека больше не
  делает — она не знает, куда ведут переходы, до их выполнения; её делает
  `describe` (§9).

## 7. Журнал, ключи, продолжение

- **Ключи эффектов узлов** — как сейчас: граф выполняется кодом библиотеки,
  который ждёт узлы так же, как написанная рукой функция (`await` узла,
  `Future.wait` ветвей), поэтому ключи и `after` одинаковы при каждом запуске.
- **Продолжение:** граф выполняется заново; кончившиеся узлы берутся из
  журнала, переходы вычисляются заново по их выходам; узел, который не
  кончился до падения, выполняется заново целиком.

## 8. Файл графа

Формат прежний, `3`; новых видов узлов нет, UI не меняется.

- **Узел** — `effect`: `name` — имя узла, `place` — его место в этом графе
  (§3), `doc` — комментарий над его переменной.
- **Граф-узел** — `call` (`functions` — id графа).
- **Граф** — запись `functions` с id `путь#<переменная>`, `doc` — комментарий
  над переменной.
- **Переход** сводится к узлам тела по правилам извлечения функции
  (code-first §7.1): его `if`, `switch`, `?:` — `fork` с прежними подписями
  (условие; `switch (collected)`); рёбра — `true`/`false` и шаблон случая
  без того, что он связывает (`Empty` для `Empty(:final branch)`; поле с
  условием остаётся: `Draft(text: '')`); каждый `узел(…)` или `граф(…)` в том, что
  переход возвращает, — ребро к этому узлу; множество — рёбра к каждому;
  `null` — ребро в конец. Развилка, все исходы которой ведут в одно место, не
  рисуется (прежнее правило), поэтому простая стрелка — одно ребро.
- **Схождение** — рёбра от каждого узла схождения к развилке или узлу его
  перехода, как сейчас — к цели.
- **Старт** — ребро от входа; узел без стрелок и не из схождения — ребро в
  конец.
- id узлов — по порядку появления в объявлении.

## 9. `describe`

- Находит переменные верхнего уровня с `node(...)` и `Graph(...)` из
  `package:nanoflow` и читает куски графа; переход — литерал функции в
  `.next` или ссылка на функцию верхнего уровня, читается его тело.
- **Предупреждения:**
  - узел или граф не в переменной верхнего уровня; имя — не литерал строки;
  - два узла одного имени в графе;
  - переход, который не прочесть: не литерал функции и не функция верхнего
    уровня;
  - в том, что переход возвращает, — значение, которое не прочесть как
    переход к узлу (не `узел(…)`, не `граф(…)`, не множество их и не
    `null`);
  - переход — `async` или генератор: он вернул бы `Future` или `Iterable`, а
    не `Next`; такой переход не читается, его рёбра не рисуются;
  - узел, до которого не дойти;
  - тип параметра перехода после схождения не совпадает с записью выходов
    его узлов;
  - побочный эффект в переходе — по тем же правилам, что вне эффектов в
    функции воркфлоу (время, `Random`, `dart:io`);
  - граф, который служит узлом другого графа, и при этом может кончиться
    несколькими концами одновременно (§6): параллель без схождения или
    несколько стартов.
- Тела узлов на побочные эффекты не проверяются: узел — эффект.

## 10. Что ещё меняется

- **Уходит:** узлы — функции верхнего уровня и функции воркфлоу; карты,
  множества и узлы как цели `.next`; `otherwise`; `Exit`; поиск типа выхода
  по типу функции; цепочки `.next(b).next(c)`.
- **Пример `examples/review`:** `lib/review_graph.dart` и `bin/graph.dart` —
  по §2; файл графа примера; e2e — граф доходит до конца и продолжается
  после падения.
- **Документы:** README, README пакетов `nanoflow` и `nanoflow_describe`,
  code-first §4.1, §6.1, §7.1 — под новую форму. Журнал решений: решение 14
  переписывается под узлы `node(...)` и переход-функцию со ссылкой на этот
  дизайн. В дизайне графа 2026-10-08 — пометка в начале: форма узлов и
  стрелок заменена этим дизайном.

## 11. Тесты

- **`nanoflow`:**
  - узел — эффект: имя, результат в журнале, кодек по `O`, перечисление,
    запись из двух полей; при продолжении кончившийся узел берётся из
    журнала, не кончившийся выполняется заново целиком;
  - переход: `switch`, `if`/`?:`, множество (параллель), `null`, петля,
    неверное значение перехода, узел с занятым именем при выполнении;
  - схождение — прежние случаи под новую форму, включая петлю и неполное;
  - граф как узел и граф из функции воркфлоу через `run`;
  - `start`/`resume`/`unfinished` графа, результат графа;
  - проверки при создании;
  - ключи одинаковы при случайных задержках (нынешний тест под новую форму);
  - место эффекта узла по файлу графа.
- **`describe`:** фикстура с узлами и графами — тела, рёбра и подписи от
  `switch`, `if`, `?:`, множества, `null`; схождение; граф-узел;
  документация узлов и графов; каждое предупреждение §9.
- **Пример и e2e** — как в §10.

## 12. Решения, которые принял исполнитель, а не пользователь

От пользователя: узел — `node(...)` и начинается заново целиком; переход —
функция со `switch`, где вызов узла с нужными аргументами означает «дальше
он»; нынешняя форма заменяется целиком; параллель и схождение нужны.
Остальное решено при написании дизайна:

- имя узла — строкой, как у `f.effect` (в собранной программе зеркал нет);
- `.next` принимает только функцию, простая стрелка — лямбда
  `(x) => b(x)` (неявный `.next(b)` через `call` компилируется, но
  рекомендованные линты помечают такой отрыв `call`);
- `Graph.call` — переход, воркфлоу графа — `Graph.run`;
- функция воркфлоу узлом не бывает;
- проверка «до узла не дойти» — только в `describe`;
- после схождения тип параметра перехода пишется явно;
- `узел.body` — для тестов;
- переход даёт `null`, чтобы кончить ветку;
- подпись ребра случая — шаблон случая без того, что он связывает (тип, поля
  с условием, `when`);
- место узла — его первое упоминание в объявлении графа, а не строка его
  переменной: так один узел живёт в нескольких графах без правки UI;
- результат графа с одновременными концами — прежнее правило, плюс
  предупреждение `describe`, когда такой граф — узел;
- узел схождения без своих стрелок — не конец графа (как сейчас).
