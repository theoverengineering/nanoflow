# Документация функций и эффектов в графе и в UI

Меняет [README](../../../README.md) («Файл графа», «Тело»),
[ui-spec.md](../../ui-spec.md) («Граф», «Экран графа», «Окно деталей
эффекта»), [code-first-design](2026-10-03-code-first-design.md) (§6.1,
§7.1, §9). Решения приняты 2026-10-10.

## 1. Зачем

Что делает шаг воркфлоу, сейчас видно только в коде: на холсте у эффекта
имя и место, у вызова — имя функции. Документация в Dart пишется в коде
комментариями `///`; пусть `describe` кладёт её в файл графа, а UI
показывает у того, к чему она относится.

- **Документация функции — у функции.** Это `///` над её объявлением. В UI
  она видна там, где на холсте функция: у вызова, у рамки функции,
  раскрытой на месте, у крошки её уровня в шапке.
- **У эффекта — только своя документация:** `///` прямо над эффектом.
  Документацию функции из замыкания эффекта (`() => collect(branch)`)
  эффект не берёт.
- **У развилок и копий документации нет.**

## 2. Документация в коде

```dart
/// Reviews the change of [branch].
Future<void> review(Flow f, String branch) async {
  /// Takes the change of the branch: the one file named after it.
  var change = await f.effect('collect', () => collect(branch));
  …
  await Future.wait([
    /// Puts the change out.
    f.effect('publish', () => print('published ${report.change.path}')),
    /// Tells the author it is accepted.
    f.effect('notify', () => print('${report.change.id}: accepted')),
  ]);
}
```

- **Функции** — комментарий документации объявления, как его видит Dart:
  строки `///` или блок `/** … */` над функцией верхнего уровня или
  методом.
- **Эффекта** — комментарий документации прямо перед эффектом: перед самим
  вызовом `f.effect` (и выражением, которое с него начинается), или перед
  простым оператором, в котором этот эффект — единственный эффект:
  выражение (`await f.effect(…);`), объявление переменной
  (`final r = await f.effect(…);`), `return`, `yield`.
  - **Перед оператором с несколькими эффектами** комментарий не относится
    ни к одному из них (`/// …` над `await Future.wait([…])` с двумя
    эффектами).
  - **Перед составным оператором** — `if`, циклом, `switch`, `try`,
    блоком — комментарий не относится к эффектам внутри.
  - **Подъём к оператору не выходит из тела функции:** у эффекта в
    замыкании, вызванном на месте, — оператор внутри замыкания.
- **Комментарий документации** — последние подряд идущие строки `///`
  перед токеном (обычный комментарий `//` между ними прерывает ряд, пустые
  строки — нет) или последний блок `/** … */`. Обычный комментарий `//`
  документацией не бывает.
- **Текст** — строки без `///` и одного пробела за ним; у блока — без
  `/**`, `*/` и `*` с одним пробелом в начале строк. Пустые строки в
  начале и в конце отброшены; Markdown остаётся как есть. Пустой текст —
  документации нет.

## 3. Файл графа: формат 3

- **`doc`** — у функции в `functions` и у узла `effect`: текст
  документации или `null`. Ключ есть всегда, как все поля модели.

  ```json
  "lib/review.dart#review": { "name": "review", "place": "lib/review.dart:47", "doc": "Reviews the change of [branch].", "body": { … } }
  { "id": "1", "kind": "effect", "name": "collect", "place": "lib/review.dart:49", "doc": "Takes the change of the branch: the one file named after it." }
  ```

- **`format: 3`.** `describe` пишет только формат 3.
- **Формат 2 читается:** у его функций и эффектов `doc` — `null`. Снимки
  графа в сессиях, начатых до формата 3, остаются читаемыми. Другой
  формат, как прежде, — `format: expected 3, the file is N`.
- **`stamp`** переписывает файл в формате 3.
- **Отпечаток исходников не меняется:** документация — часть исходников,
  её правка и так меняет `sources` и `fingerprint`.

## 4. UI

### 4.1. Как показан текст

Документация — Markdown, показанный упрощённо:

- **Абзацы** разделены пустой строкой; переводы строк внутри абзаца —
  пробелы.
- **Пункты списка** (`- `, `* `, `1. ` в начале строки) — каждый с новой
  строки, `•` вместо `-` и `*`, номер как есть.
- **Блок кода** между строками ```` ``` ```` — моноширинным шрифтом,
  строки как есть.
- **`` `код` ``** — моноширинным; **ссылка Dart `[name]`** — моноширинным,
  без скобок; **ссылка Markdown `[текст](url)`** — текст; **`**жирный**`**
  и **`*курсив*`** — жирным и курсивом. Остальное — как написано.

### 4.2. Где

- **Плитка эффекта** — подсказка при наведении: документация эффекта.
- **Плитка вызова** — подсказка: документация функции. У вызова метода
  интерфейса с несколькими функциями — каждая функция с документацией:
  её заголовок (`MailNotifier.notify()`) жирным моноширинным, под ним
  текст; функции разделены пустой строкой.
- **Заголовок рамки функции**, раскрытой на месте, — подсказка:
  документация функции.
- **Крошка в шапке** — подсказка: документация функции уровня (у
  воркфлоу — его). У уровня копий — нет.
- **Окно деталей эффекта** — раздел `Doc` над `Place in code`: текст
  документации эффекта, выделяемый. Нет документации — нет раздела. Так
  же при `Current graph` (окно с именем и местом узла).
- **Нет документации — нет подсказки.** Подсказка с именем, обрезанным у
  плитки, остаётся на имени, как была.

Подсказка появляется через полсекунды наведения, шириной не больше
420 px, в цветах карточки приложения. Сессия показывает документацию из
своего снимка, `Current graph` — из файла графа.

## 6. Тесты

- **Модель:** `doc` туда и обратно; формат 2 читается с `doc: null` (и в
  теле копий); у формата 3 без `doc` — ошибка с путём поля.
- **Извлечение:** `///` и `/** */` у функции и метода; `///` над
  эффектом-выражением, объявлением, `return`, элементом списка
  `Future.wait`; над оператором с двумя эффектами, над `if` и циклом,
  `//` — `null`; ряд `///`, прерванный `//`, — только хвост.
- **UI:** разбор текста (абзацы, списки, код, ссылки, жирный, курсив);
  подсказки на плитке эффекта, вызова (одна и несколько функций), рамке,
  крошке — и нет их без документации; раздел `Doc` в окне деталей (сессия
  и `Current graph`); клик и двойной клик по плитке с подсказкой работают
  как прежде. Золотая картинка окна деталей — с документацией.
- **Проверка на настоящих графах:** `describe --check` у
  `examples/review`; `describe` у копии
  `~/Projects/scheduleme/nanoflow-task-graph/workflow` пишет файл, который
  читает UI.
