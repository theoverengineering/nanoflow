# nanoflow: граф кодом — спецификация

Источник правды для реализации нового направления. Почему принято так, а
не иначе, — в [журнале решений](2026-10-02-code-first-decisions.md) (дальше
«решение N»). Где спецификация и журнал расходятся, права спецификация: она
закрывает вопросы, которые журнал оставил открытыми.

## 1. Что это

- **Воркфлоу — обычная асинхронная функция Dart.** Эффект — вызов
  `f.effect('имя', () => …)`. Развилки — `if`/`switch`, петли — циклы,
  параллельность — `Future.wait`.
- **Библиотека `nanoflow` ведёт сессию в процессе приложения:** пишет журнал,
  после падения продолжает сессию, беря готовые эффекты из журнала. Отдельного
  движка, протокола `--graph`/`--input`/`--call`, YAML и `nanoflow check` нет.
- **Граф извлекается из кода статически** (`nanoflow_describe`, анализатор
  Dart) в отдельный файл графа. Исполнение от графа не зависит; приложение
  читает файл графа только чтобы положить снимок в сессию.
- **UI** читает файл графа и хранилище сессий и показывает граф, сессии и
  эффекты. UI ничего не запускает и не знает, на каком языке написан граф.

## 3. Каталог проекта

**Каталог проекта** — каталог, где лежат файл графа `nanoflow.graph.json` и
каталог сессий `runs/`.

- При разработке это корень пакета приложения (где `pubspec.yaml`):
  `describe` пишет туда файл графа, библиотека пишет туда `runs/`.
- У собранного приложения это каталог бинарника: `stamp` кладёт туда копию
  файла графа, библиотека пишет туда `runs/`.

Библиотека находит каталог проекта так: `Flow(directory: …)`, если задан;
иначе в собранной программе (`const bool.fromEnvironment('dart.vm.product')`)
— каталог `Platform.resolvedExecutable`; иначе, если `Platform.script` —
снимок `dart run` в `<корень>/.dart_tool/pub/bin/<пакет>/` (в pub workspace
`.dart_tool` лежит в корне workspace), — каталог `<пакет>` по его `rootUri`
в `<корень>/.dart_tool/package_config.json`; иначе — ближайший к
`Platform.script` предок с `pubspec.yaml`, а если такого нет — каталог
`Platform.script`.

## 4. Библиотека `nanoflow`

### 4.1. API

```dart
final flow = Flow()                     // каталог проекта — §3
  ..addCodec(Change.fromJson)
  ..addCodec(Report.fromJson);

final session = await flow.start(review, 'feature/parse-config');
print(session.id);
final result = await session.result;   // результат функции воркфлоу

// то же одной строкой:
final result2 = await flow.run(review, 'feature/parse-config');

// после падения процесса:
final again = await flow.resume(review, sessionId);
await again.result;

// незаконченные сессии воркфлоу:
final ids = await flow.unfinished(review);

flow.stop();   // остановить сессии этого Flow: их программы exec убиваются, эффекты больше не стартуют
```

```dart
Future<String> review(Flow f, String branch) async {
  final change = await f.effect('collect', () => git.changeOf(branch));
  …
}
```

- `Flow({String? directory})`; `addCodec<T>(T Function(Map<String, Object?>) fromJson)`.
- Функция воркфлоу: `Future<R> Function(Flow f, I input)`. Внутри неё `f` —
  тот же `Flow`: эффект находит свою сессию по зоне.
- `start<I, R>(workflow, I input)` → `Future<FlowSession<R>>`: сессия
  создана и записана, функция запущена; `FlowSession.id`, `FlowSession.result`.
  `run` = `start` + `result`.
- `resume<I, R>(workflow, String sessionId)` → `Future<FlowSession<R>>`.
  Законченная сессия не выполняется: `result` сразу отдаёт сохранённый
  результат или сохранённую ошибку.
- `unfinished(workflow)` → id незаконченных сессий этого воркфлоу.
- `effect<T>(String name, FutureOr<T> Function() body)` → `Future<T>`.
  Вне сессии — `StateError`.
- Имя воркфлоу — имя функции. Библиотека узнаёт его из `toString()`
  замыкания функции верхнего уровня или статического метода
  (`Closure: (Flow, String) => Future<String> from Function 'review': static.`
  — так и под `dart run`, и в собранной программе); если имя не извлечь —
  `ArgumentError`: воркфлоу — функция верхнего уровня или статический метод.
  UI сопоставляет сессию с воркфлоу файла графа по имени: id воркфлоу
  кончается на `#<имя>` или `.<имя>`.

### 4.2. Что требуется от кода

- Эффект вызывается как `f.effect(…)` внутри сессии.
- Вход воркфлоу, результат воркфлоу и результат эффекта превращаются в JSON
  (§4.4).
- **Любой побочный эффект, кроме логов, — внутри `effect`**
  ([дизайн эффектов](2026-10-04-effects-design.md), §2). Сохраняются только
  эффекты; код между эффектами при продолжении выполняется заново.
  - Побочный эффект — всё, чем код касается мира за пределами функции:
    читает время, случайные числа, окружение, файлы, сеть; пишет файлы,
    ходит в сеть, запускает программы.
  - Логи (`print`, логгер) — где угодно: на путь не влияют, при продолжении
    сессии просто печатаются ещё раз.
  - Следствие: код между эффектами при тех же входе и выходах эффектов идёт
    тем же путём. Продолжение на том же коде идёт тем же путём; развилки
    выводятся из журнала ([дизайн эффектов](2026-10-04-effects-design.md),
    §5).
  - Правило — соглашение; `describe` предупреждает об очевидных нарушениях
    (§7.1). Рантайм ничего не запрещает.

### 4.3. Ключи эффектов

Ключ находит сохранённый результат эффекта при продолжении. Устройство —
решение 1, доказательство — `prototypes/step_keys`.

- Код сессии идёт в зоне библиотеки. У каждого исполняемого кусочка есть
  **контекст** — строка; у корня сессии — `""`.
- Каждый обратный вызов, который код регистрирует в зоне в контексте `c`,
  получает свой контекст с номером, по двум независимым счётчикам, — по
  числу аргументов обратного вызова:
  - с аргументом (продолжение асинхронной функции — одно на вызов, при
    первом `await`; `then`; `onData`/`onError` потока) — `h(c + "/~" + k)`;
  - без аргумента (`Timer`, `Future.delayed`, `scheduleMicrotask`,
    `Future(…)`, `whenComplete`, `onDone` потока) — `h(c + "/~t" + k)`;

  `k` — номер среди зарегистрированных этого рода в `c`, с 1. Сама постановка
  микрозадачи или таймера в очередь номера не берёт: функция идёт в
  контексте того, кто её поставил (так продолжение `await` уже завершённого
  future не сдвигает номера). Обратные вызовы без аргумента считаются
  отдельно, потому что потоки Dart ставят служебные микрозадачи в
  зависимости от тайминга — от них не должны сдвигаться номера вызовов
  функций и копий.
- Гарантия: ключ эффекта одинаков при любом тайминге, если на пути к нему
  (по контекстам) последовательность регистраций не зависит от тайминга.
  Нарушают её: код, который сам решает по таймингу (`Future.any`, гонки);
  эффект, вызванный прямо из обратного вызова без аргумента (таймер,
  микрозадача, `async*`-генератор после `yield`), созданного в контексте,
  который читает поток с внешним темпом. Такие эффекты при продолжении могут
  выполниться заново; чужой результат они не получают (§4.6).
- Эффект с именем `N`, вызванный в контексте `c`, получает номер `n` — который
  по счёту эффект с этим именем в `c` — и ключ `N#n@` + `h(c)`.
- Вызов функции, возобновлённый ровно результатом эффекта (тот же объект, что
  вернул эффект), получает контекст, равный ключу этого эффекта.
- `h(s)` — первые 16 шестнадцатеричных знаков sha256 от UTF-8 строки `s`.
- Эффект из журнала и эффект вживую ставят в очередь в контексте вызова одно и
  то же, чтобы номера после продолжения не сдвигались:
  - тело эффекта с ключом `K` выполняется в контексте `h(K + "/~0")` — не в `K`:
    иначе обратные вызовы тела делили бы счётчик `K` с кодом, который примет
    результат эффекта, а у эффекта из журнала тела нет;
  - будущее, которое возвращает `f.effect`, принадлежит зоне, из которой
    сессия запущена, а не зоне ключей: позднее `await` уже завершённого эффекта
    не ставит в очередь лишнего в контексте вызова.
- У эффекта есть **предшественник** (`after`) — ключ последнего эффекта,
  результат которого принял контекст, где эффект вызван; `null`, если такого
  нет. Новый контекст обратного вызова наследует предшественника родителя.

### 4.4. Кодеки

- JSON-типы (`null`, `bool`, `int`, `double`, `num`, `String`, `List` и
  `Map<String, …>` из них) проходят как есть.
- Свой тип — `addCodec(Report.fromJson)`. Регистрация `T` регистрирует и
  `T?`, `List<T>`, `Map<String, T>`. Кодируется `jsonEncode` (он вызывает
  `toJson()`), раскодируется зарегистрированной функцией.
- При первом выполнении эффекта (и для входа и результата воркфлоу) значение
  кодируется, раскодируется обратно и проверяется `is T`. Нет кодека, нет
  `toJson`, не сходится — эффект падает с `CodecException` (сообщение называет
  тип); это обычное исключение эффекта.
- При продолжении сохранённое значение эффекта, которое больше не
  раскодируется нынешним типом (класс изменили), — чужой результат: эффект
  выполняется заново в прежней записи. Сохранённый вход воркфлоу, который не
  раскодируется, — ошибка `resume` (`CodecException`), в сессию ничего не
  пишется.
- У типа сохранённого значения эффекта при продолжении нет кодека (его не
  зарегистрировали) — эффект не выполняется заново: сессия кончается, как при
  сбое хранилища (§4.6), с `CodecException`; с кодеком её можно продолжить.

### 4.5. Лог эффекта и внешние программы

- `print` внутри тела эффекта пишет строку в лог этого эффекта (`effect.log`).
  `print` вне эффектов идёт в обычный `print`.
- `exec(executable, arguments, {workingDirectory, environment})` →
  `Future<String>` (stdout). Поведение `exec` из нынешнего пакета сохраняется
  (группа процессов, обёртка perl с SIGPIPE по умолчанию, остановка группы
  SIGTERM, через 5 с SIGKILL, `ExecException` при ненулевом коде), с двумя
  изменениями:
  - stderr программы дописывается в лог того эффекта, внутри которого вызван
    `exec`; вне эффекта — в `stderr` процесса;
  - программа умирает вместе с процессом приложения: обёртка следит за
    трубой от процесса и, когда та закрылась, останавливает группу.
- `flow.stop()` останавливает группы `exec`, запущенных в сессиях этого
  `Flow`. Программа, запущенная вне сессии, умирает вместе с процессом.

### 4.6. Ход сессии

**Создание (`start`).** Вход кодируется (§4.4) → сессия создаётся целиком,
атомарно: `session.json`, документ входа, журнал с `session-started`. Потом
берётся блокировка сессии, потом запускается функция.

**Эффект вживую.** Ключ (§4.3) не найден среди готовых:
1. запись эффекта (`effect.json`, каталог) — если эффекта с этим ключом ещё нет
   в сессии; иначе используется прежняя запись;
2. `effect-started`;
3. тело выполняется в собственном контексте; `print` — в лог;
4. успех → проверка кодека → документ выхода → `effect-finished` →
   `effect.json` с `outputId`; исключение → `effect-failed` с текстом и стеком,
   исключение уходит в код воркфлоу.

**Эффект из журнала.** Ключ есть среди эффектов с `effect-finished` **и**
записанный предшественник (`after`) этого эффекта равен предшественнику
нынешнего вызова → значение раскодируется из документа, тело не
выполняется, в журнал ничего не пишется. Ключ совпал, а предшественник нет —
эффект выполняется вживую (новая запись эффекта не создаётся, если запись с этим
ключом уже есть, — пишется новый `effect-started` в неё): лучше повторить
эффект, чем отдать ему чужой результат.

**Конец.** Функция вернула значение → документ результата →
`session-finished`. Бросила → `session-failed` с текстом и стеком.

**Продолжение (`resume`).** Блокировка → журнал читается (обрезается
недописанная строка) → готовые эффекты (по `effect-finished`) становятся картой
«ключ → документ» → `session-resumed` с хэшем кода и, если хэш не совпал с
последним записанным, новым снимком графа документом → функция запускается
заново с сохранённым входом. Упавший или незавершённый эффект выполняется
заново и пишет новый `effect-started` в ту же запись эффекта.

**Повтор эффекта в прежней записи** (упавший, незавершённый, с другим
предшественником или чьё значение больше не раскодируется): сначала
`effect-started`, потом `effect.json` переписывается с нынешним `after` —
предшественник записи может меняться.

**Блокировка.** Сессию ведёт один процесс: исключительная блокировка ОС
(`fcntl`) от создания или открытия до конца сессии; ОС снимает её при
падении. Блокируется один байт `<сессия>/.owner.lock` — по смещению
`ownerLockOffset` (`1 << 30`, `nanoflow_model`), а не весь файл:
содержимое файла не под блокировкой и читается и там, где блокировки
обязательные. Блокировка всего файла прежней версии этот байт покрывает —
они по-прежнему исключают друг друга. Занятая сессия →
`SessionBusyException` — и когда ею владеет этот же изолят (блокировки ОС
действуют на процесс, поэтому библиотека помнит свои сессии сама; другой
изолят того же процесса этой памяти не видит). Продолжение упавшей сессии →
`SessionFailedException` с сохранённым текстом ошибки и стеком.

**Запись владельца.** Взяв блокировку, процесс пишет в `.owner.lock` себя —
`Owner`: свой pid и время своего старта по ОС (формат — §5.1). Пара — ключ
процесса: один pid не уникален, ОС отдаёт номер умершего процесса другому.

- **Кто я.** `Flow` узнаёт владельца раз на изолят через порт
  `nanoflow_process` и отдаёт его `FsStore(runsDir, owner: …)` как данные;
  хранилище только пишет и очищает. `FsStore` без владельца оставляет файл
  пустым.
- **Запись** — JSON с позиции 0, затем файл обрезается по его длине:
  прежняя запись видна, пока не записана новая, и хвоста более длинной
  старой не остаётся. Переименовывать файл нельзя: блокировка привязана к
  открытому файлу. `resume` пишет владельца заново, поверх прежнего.
- **Отпуск.** Отпуская сессию — в конце её хода, как бы он ни кончился
  (результат, ошибка, `stop()`, сбой хранилища), — процесс обрезает файл до
  нуля и только потом закрывает его, снимая блокировку. Упавший процесс
  файл не очищает: в нём остаётся его запись.
- **Читать `.owner.lock` в процессе-владельце нельзя.** Блокировка `fcntl`
  — на процесс, и закрытие любого его дескриптора файла, даже открытого
  только на чтение, молча её снимает: другой процесс сможет взять сессию,
  которую первый ещё ведёт. Поэтому читатель (§8) не запускают в процессе,
  который ведёт сессии того же `runs/`; UI — другой процесс.

**Сбой хранилища.** Не удалось записать или прочитать сессию → дальнейшие
эффекты не стартуют (`f.effect` бросает `StorageException`), программы `exec`
останавливаются, `result` завершается с `StorageException`. После сбоя в
сессию ничего не пишется.

**Остановка (`flow.stop()`).** Эффекты больше не стартуют (`f.effect` бросает
`FlowStoppedException`), программы `exec` останавливаются; в журнал ничего не
пишется — сессию можно продолжить.

### 4.7. Хэш кода и снимок графа

- **Снимок.** При создании сессии библиотека читает
  `<каталог проекта>/nanoflow.graph.json`. Есть — весь файл кладётся в
  `session.json` как `graph`; нет — `graph: null`.
- **Хэш кода.** В собранной программе — `sha256:` + sha256 байтов
  `Platform.resolvedExecutable`. Иначе — отпечаток исходников (§6.2) пакета в
  каталоге проекта. Не удалось посчитать — `null`. Пишется в
  `session-started` и `session-resumed`.

## 5. Хранение

### 5.1. Файлы

```text
runs/
  review-2026-10-03T10-00-00-<id>/        сессия: <воркфлоу>-<время создания>-<id>
    session.json
    log.jsonl                              журнал сессии
    .owner.lock                            владелец сессии и его блокировка
    documents/<id>.json
    effects/
      2026-10-03T10-00-00-482-collect-<id>/
        effect.json
        effect.log
```

- Время в именах — UTC, у эффекта с миллисекундами; монотонно растёт в пределах
  сессии. Имя эффекта в имени каталога — знаки вне `[A-Za-z0-9._-]` заменены на
  `_`.
- Каталог находят по id — последние 36 знаков имени.
- Атомарная запись: временное имя с `.` в том же каталоге и переименование.
  Сессия строится целиком под `runs/.tmp-<id>/` и переименовывается.
- JSON-файлы — с отступом 2 пробела и переводом строки в конце; `log.jsonl` —
  по объекту в строке.
- `.owner.lock` — владелец сессии, процесс, который её ведёт (§4.6):
  `{"pid":4242,"started":"2026-10-03T07:43:34.651Z"}` — JSON одной строкой,
  без пробелов и перевода строки.
  - Ключи в этом порядке, оба всегда есть. `started` — время старта
    процесса по ОС в формате времени событий (UTC, ровно три знака дробной
    части, `Z`), младшие разряды отброшены; `null`, когда адаптер ОС его не
    знает.
  - Пустой файл (или его нет) — владельца нет: сессия отпущена, или её
    писала прежняя версия.
  - Не JSON — запись идёт (новое начало поверх хвоста старой): читатель
    ждёт следующего прохода.

### 5.2. Модели

У модели всегда есть все поля; нет значения — `null`. Id — UUID v4.

| Модель | Поля по порядку |
| --- | --- |
| Сессия | `id`, `workflow` (имя функции), `graph` (снимок файла графа или `null`), `inputId` |
| Эффект | `id`, `sessionId`, `name`, `key`, `after`, `place`, `outputId`, `log` (`"effect.log"`) |
| Документ | `id`, `sessionId`, `value` |

`place` — место вызова `f.effect`: `путь:строка`. Путь — относительно каталога
проекта, если файл внутри него; файл библиотеки корневого пакета
(`package:<пакет>/x.dart`) — `lib/x.dart`; иначе — как в стеке вызовов.
Берётся из кадра стека, вызвавшего `f.effect`; не удалось — `null`.

### 5.3. События журнала

Поля любого события: `time` (UTC, ISO-8601, ровно три знака дробной части,
`Z`), `event`. Остальные — по событию:

| `event` | Свои поля | Когда |
| --- | --- | --- |
| `session-started` | `code` | первое событие, пишется при создании |
| `session-resumed` | `code`, `graphId` | каждое продолжение; `graphId` — документ с новым снимком графа, если хэш кода изменился, иначе `null` |
| `effect-started` | `effectId` | эффект начал выполняться (вживую) |
| `effect-finished` | `effectId`, `outputId` | эффект вернул значение |
| `effect-failed` | `effectId`, `error`, `stack` | эффект бросил исключение |
| `session-finished` | `outputId` | функция воркфлоу вернула значение |
| `session-failed` | `error`, `stack` | функция воркфлоу бросила |

- Хэш кода изменился, а файла графа нет — снимок не пишется: `graphId` —
  `null`.
- `error` — одна строка: `toString()` исключения с переводами строк,
  заменёнными на пробелы. `stack` — текст стека.
- Незнакомое событие читается как есть; событие с неверными полями — как
  незнакомое.
- `session-finished` и `session-failed` — последнее событие сессии.

### 5.4. Состояние (проигрывание журнала)

- **Сессия:** `running` — нет последнего события; `finished`, `failed`.
  `startedAt` — время `session-started`, `finishedAt` — время последнего
  события у законченной. `codes` — хэши кода по порядку (`session-started`,
  потом каждый `session-resumed`); `graphIds` — документы снимков из
  `session-resumed`.
- **Эффект:** порядок — по первому `effect-started`; `status` — `running` (после
  последнего `effect-started` нет итога), `finished`, `failed`; `starts` —
  число `effect-started`; `startedAt`, `finishedAt`; `error`.

## 6. Файл графа

### 6.1. Формат

`nanoflow.graph.json`, один на пакет:

```json
{
  "format": 2,
  "package": "review_example",
  "fingerprint": "sha256:7d3e…",
  "sources": { "bin/main.dart": "sha256:aa11…", "lib/review.dart": "sha256:9f2c…" },
  "builds": { "review": "sha256:c07e…" },
  "workflows": ["lib/review.dart#review"],
  "functions": {
    "lib/review.dart#review": { "name": "review", "place": "lib/review.dart:21", "body": { "nodes": [], "edges": [] } }
  },
  "warnings": [ { "place": "lib/review.dart:40", "message": "effects in a closure passed on are not drawn" } ]
}
```

- `format` — 2. Файл другого формата не читается: UI говорит о нём, как о
  любом неверном файле.
- `functions` — функции с эффектами, по id `путь#имя` (метод — `путь#Класс.имя`;
  метод безымянного расширения — `путь#<extension>.имя`, второго
  безымянного расширения файла — `путь#<extension 2>.имя` и т. д.). Граф
  функции описан один раз, сколько бы раз её ни вызывали.
- `workflows` — функции, переданные первым аргументом в `Flow.start`,
  `Flow.run` или `Flow.resume`; у каждой есть запись в `functions`, даже
  без эффектов.
- `body` — граф одного уровня:

```json
{
  "nodes": [
    { "id": "1", "kind": "effect", "name": "collect",             "place": "lib/review.dart:22" },
    { "id": "2", "kind": "fork",   "label": "change.path.isEmpty", "place": "lib/review.dart:23" },
    { "id": "3", "kind": "call",   "functions": ["lib/release.dart#publish"], "place": "lib/release.dart:23" },
    { "id": "4", "kind": "copies", "label": "pkg in packages",     "place": "lib/release.dart:20", "body": { "nodes": [], "edges": [] } }
  ],
  "edges": [
    { "from": null, "to": "1", "label": null },
    { "from": "2",  "to": "3", "label": "true" },
    { "from": "2",  "to": null, "label": "false" }
  ]
}
```

- `from: null` — вход тела, `to: null` — выход из тела (`return` или конец).
- Узлы: `effect` (вызов `f.effect`, `name` — литерал имени или исходник
  выражения), `fork` (условие; `label` — исходник условия, у цикла и
  `switch` — с ключевым словом: `for x in xs`, `while (c)`, `for (; c;)`,
  `switch (e)`), `call` (вызов функции с эффектами; несколько `functions` —
  реализации интерфейса), `copies` (тело, которое `Future.wait` выполняет
  копиями: `for` внутри списка или `map`; `label` —
  `<переменная> in <выражение>`; `body` — тело копии).
- Подписи рёбер из развилки: `if`, `while`, `for(;;)`, `&&`/`||`,
  `?:` — `true`/`false`; цикл `for … in` — `each`/`done`; `switch` —
  исходник случая или `default`. У остальных рёбер `label: null`.
- Несколько рёбер из одного узла без подписи или с одной подписью —
  разветвление `Future.wait` над списком; узел, в который входят ветки, ждёт
  все.
- `place` — `путь:строка` относительно корня пакета.
- id узлов — строки, уникальные в пределах тела.

### 6.2. Отпечаток исходников

Исходники пакета — файлы `.dart` под `lib/` и `bin/`, кроме каталогов,
начинающихся с `.`, и `build/`. Для каждого: путь относительно корня пакета
(через `/`) и `sha256:` + sha256 содержимого с `\r\n` → `\n`. Строки
`<путь> <хэш>\n`, отсортированные по пути, хэшируются целиком →
`fingerprint`. `sources` — хэши файлов по пути.

### 6.3. `builds`

`stamp <бинарник>` дописывает `builds[<имя файла бинарника>] = sha256 байтов`.

## 7. `nanoflow_describe`

```text
dart run nanoflow_describe            # пишет nanoflow.graph.json в корне пакета
dart run nanoflow_describe --watch    # и перезаписывает при каждой правке исходников
dart run nanoflow_describe --check    # код 1, если файл не совпадает с тем, что был бы записан
dart run nanoflow_describe stamp build/review   # §6.3; копия файла графа рядом с бинарником
```

- Запускается из корня пакета (или с `--package <каталог>`).
- `stamp` сначала проверяет, что `fingerprint` файла совпадает с исходниками,
  иначе — код 1 и ничего не пишет.
- `--watch` печатает строку на каждую перезапись и на каждую ошибку
  разбора; файл с ошибками компиляции не перезаписывается.
- Пишет файл, только если содержимое изменилось; пока отпечаток не
  изменился, обычный запуск сохраняет `builds`.

### 7.1. Извлечение

По исходникам `lib/` и `bin/` с разрешением типов (`package:analyzer`),
выполнения кода нет. Метод, функция или замыкание, где есть вызов
`Flow.effect` (из `package:nanoflow`) или вызов функции с эффектами, — функция с
эффектами. Граф тела — граф потока управления, сведённый к узлам §6.1:

- последовательность, `if`/`else`, `if-case`, `switch` (исчерпывающий по
  `enum`, `bool`, `sealed`, записи из них или с `case _` — без `default`) и
  `switch`-выражение, `while`, `do`, `for(;;)`, `for … in`,
  `break`/`continue`, `return`, `throw` (путь кончается; брошенное внутри
  `try` и пойманное его `catch` идёт дальше после `try`, через `finally`, —
  если есть `catch` без типа или с типом, к которому подходит брошенное, и
  его блок может закончиться обычно, а не `throw`, `rethrow` или `return`;
  ветка `?:` или `switch`-выражения, которая бросает, тоже кончает путь),
  `?:`, `&&`/`||` с
  эффектами справа; выход из `try` (`return`, `break`, `continue`) идёт через
  `finally`;
- `Future.wait` над списком: элементы — ветки; элемент `for` — `copies`;
  `Future.wait(xs.map((x) async {…}))` — `copies`; поля записи в
  `(a, b).wait` — тоже ветки;
- замыкание, вызванное на месте, — его тело на месте вызова;
- вызов функции с эффектами из исходников пакета — узел `call`; вызов метода
  интерфейса — `call` со всеми реализациями из исходников пакета;
- развилка, у которой все исходы ведут в одно и то же, не рисуется;
- `try` — тело и `finally`; ветки `catch` не рисуются (предупреждение).

Предупреждения (`warnings`): имя эффекта — не литерал; эффекты в замыкании,
переданном дальше; эффекты в локальной функции; вызов функции с эффектами вне
исходников; `catch`; побочный эффект вне эффекта (правило §4.2):

- **Где ищет.** В телах функций графа (воркфлоу и функции с эффектами) и во
  всём, что они вызывают из исходников своего пакета (функции, методы,
  конструкторы, геттеры, замыкания, вызванные на месте, локальные функции) —
  транзитивно, каждую функцию один раз. Тело замыкания, переданного в
  `Flow.effect`, — сам эффект, его не проверяют, как и то, что вызывается
  только из таких тел. Чужие пакеты и SDK не обходят.
- **Что считается нарушением** — по разрешённому элементу, не по тексту:
  `DateTime.now`, `DateTime.timestamp`, конструктор `Stopwatch`; конструкторы
  `Random` из `dart:math` (`Random()`, `Random(seed)`, `Random.secure()`);
  любой элемент библиотеки `dart:io` (класс, конструктор, функция, геттер
  верхнего уровня, статический член), кроме `stdout`, `stderr` и членов
  `Stdout`/`IOSink`, вызванных на них.
- **Не нарушение:** `print`, `stdout`/`stderr`, таймеры и `Future.delayed`
  (ожидание данных снаружи не приносит), всё из чужих пакетов.
- **Текст и место.** В теле функции графа — на месте выражения:
  `side effect outside an effect: <исходник выражения>`. Внутри вызываемой
  функции пакета — на месте вызова в функции графа, о первом нарушении, до
  которого вызов дотягивается, по порядку обхода:
  `side effect outside an effect: <исходник вызова> reaches <исходник выражения> at <путь:строка>`.
  Каждое предупреждение — один раз (по месту и тексту), в общем списке
  `warnings`.

## 8. Чтение (`nanoflow_reader`)

`FsReader(runsDir: <каталог проекта>/runs)`: лента изменений сессий в `runs/`
и данные по запросу.

| `change` | Свои поля |
| --- | --- |
| `session-added` | `session` |
| `effect-added` | `effect` |
| `effect-changed` | `effect` (запись переписана: появился `outputId` или при повторе — новый `after`) |
| `event-added` | `sessionId`, `event` |
| `document-added` | `sessionId`, `documentId` |
| `log-corrupted` | `sessionId`, `line`, `text` |
| `owner-changed` | `sessionId`, `owner` (запись `.owner.lock` или `null`), `alive` (`true`, `false` или `null`) |

По запросу: значение документа, лог эффекта (накопленный, потом дописанное).
События сессии — в порядке журнала; недописанное не выдаётся. Сессия
закончена, когда прочитано последнее событие.

**Владелец сессии (`owner-changed`).** Жив ли владелец (§4.6), читатель
узнаёт у ОС через порт `Processes` из `nanoflow_process`:
`FsReader({runsDir, pollInterval, processes})`; без `processes` — адаптер
этой ОС (`Processes.forPlatform()`), который читатель закрывает, когда
ленту отменили; переданный закрывает вызывающий.

- **`alive`:** `true` — идёт процесс с этим pid и этим временем старта;
  `false` — владельца нет (файл пуст или его нет), процесс вышел или pid у
  другого процесса; `null` — неизвестно: у владельца `started: null`, порт
  не поддерживается (не macOS) или следить за выходом не вышло.
- **Когда.** Только для сессии, журнал которой не кончился: в первом чтении
  — после её прочих изменений; потом при каждой смене пары (`owner`,
  `alive`). Кончилась сессия — `owner-changed` для неё больше нет.
- **Как.** Каждый проход читает `.owner.lock` незавершённых сессий до чтения
  журнала, а сообщает после, и только если журнал не кончился: владелец
  пишет последнее событие до того, как отпустит сессию или выйдет, поэтому
  штатно законченная сессия даёт `session-finished`, а не «владельца нет» и
  не `alive: false`. Не JSON — остаётся сказанное прежде.
- **Новый владелец:** сначала подписка на выход процесса (`exitOf(pid)`),
  потом сверка `startOf(pid)` с `started` — выход между ними не потеряется,
  чужой pid даёт `alive: false`.
- **Выход процесса** будит проход сразу, без опроса (macOS — kqueue); тот
  же владелец — `alive: false`.
- **Не в процессе-владельце.** Читатель не запускают в процессе, который
  ведёт сессии того же `runs/`: чтение `.owner.lock` сняло бы блокировку
  этого процесса (§4.6).

## 9. UI

Меняется по решениям 6, 8, 10, 11 и разделу 12 журнала:

- **Открыть** — файл `nanoflow.graph.json` (стартовый экран и недавние).
  Сессии — `runs/` рядом. Файл перечитывается при изменении.
- **Граф** — функции воркфлоу файла; одна — сразу, несколько — выбор.
  Узлы `call` — плитка-стопка функции; двойной клик — граф функции, путь
  вверху; кнопка на плитке — раскрыть на месте в рамке с серой обводкой.
  `copies` — рамка-стопка с подписью и `×N`, переключатель копий
  («все» и номера).
- **Свежесть.** Есть исходники рядом — UI считает отпечаток (§6.2 по
  `sources` файла) и подсвечивает «граф может не соответствовать коду» со
  списком изменённых файлов. Рядом лежит бинарник из `builds` — сравнивает
  его хэш. Предупреждения файла — списком. Сессии воркфлоу, которого нет в
  файле графа (добавили новый, а `describe` не запускали), не прячутся:
  заметка называет такие воркфлоу и говорит, что файл графа может быть
  устаревшим.
- **Сессия** — граф из её снимка (последний из `session-resumed` или из
  `session.json`); хэш кода сессии ищется среди `fingerprint`/`builds`
  снимка: не нашёлся — «сессия шла на другом коде», `null` — «не проверено».
  Нет снимка — граф из файла, с отметкой «у сессии нет снимка». Хэши кода
  `session-started` и какого-то `session-resumed` известны и различаются —
  отметка «продолжена на изменённом коде» (решение 7) в карточке и строке
  сессии.
- **Interrupted.** Сессия, журнал которой не кончился, а владельца нет
  (`owner-changed` с `alive: false`, §8), — «Interrupted», а не «Running»:
  процесс, который её вёл, упал или отпустил её, не закончив (`stop()`,
  сбой хранилища), и её можно продолжить. Переход — по ленте, без опроса;
  `alive: true` или `null` и пока `owner-changed` не пришло — как раньше.
  Подробно — в [ТЗ интерфейса](../../ui-spec.md).
- **Эффекты на графе** — по `place` эффекта: узел `effect` с тем же местом (путь
  сравнивается по окончанию), а из узлов этого места — с тем же `name`; нет
  такого (имя задано выражением, у узла — его исходник) — все узлы места.
  Два эффекта на одной строке (`dart format` оставляет так короткие
  параллельные эффекты) так различаются по имени. Эффект без места или без узла
  — в списке «не на графе». Одно место и имя может быть у нескольких узлов
  (`finally`, нарисованный на каждый выход из `try`): эффект отмечается на
  всех.
- **Копии.** Копия рамки `copies` — цепочка эффектов внутри рамки по `after`:
  первый эффект копии — тот, чей предшественник вне рамки; номер копии — по
  времени первого `effect-started`. Подсказка — начало значения выхода первого
  эффекта.
- **Логи** — эффекты сессии по первому `effect-started`; при выбранной копии —
  её эффекты. Строк «унаследовано» и «прогон разделился» нет.
- **Окно эффекта** — выход, лог, место в коде, ошибка со стеком; входа нет.
- Уходят: запуск программ графа, `nanoflow check`, поиск `PATH`, выбор
  `.yaml`, переключатель прогонов.

## 10. Пример, проверки, документы

- `examples/review` — граф из README функцией воркфлоу, `bin/main.dart`
  запускает её, по Ctrl+C вызывает `flow.stop()`; `nanoflow.graph.json`
  в репозитории, CI проверяет `describe --check`.
