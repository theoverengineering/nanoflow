# Переход по падению: `.failed(…)` у куска

Дополняет [лимит вызова](2026-11-02-call-limit-design.md) и
[граф из узлов](2026-10-25-graph-node-objects-design.md). Решено
2026-11-02.

## Зачем

Сейчас исключение узла или перехода — ошибка ветки. Перехода после неё нет:
остальные ветки доходят до конца, сессия кончается падением, а при
продолжении упавший узел выполняется снова.

ideaforge переводит ночные циклы в графы (дизайн ночи ideaforge,
`docs/superpowers/specs/2026-11-02-night-graphs-design.md`, «Чего не хватает
в nanoflow: переход по падению»). Цикл ночи ловит падение
каждого пункта сам, а граф так не умеет:

- копия `developIdea` упала и не дошла до `settle`: идея остаётся «в
  разработке», у строки отчёта нет исхода, ночь ждёт копию до жёсткого срока
  или вечно;
- упавший `generateIdeas` обрывает цепочку ночной генерации, и остальные
  пункты не делаются;
- ночь оборвали после падения копии: продолжение выполнит упавший узел снова
  — над идеей, которую уже отдали.

## Цели

- `Graph.part(developIdea).next(settle).failed((request, failure) =>
  giveBack(…))`: когда вызов `developIdea` падает, дальше идёт переход по
  падению. Он получает вход упавшего вызова и падение (текст ошибки и имя её
  типа) и даёт, что дальше, как обычный переход.
- Падение вызова узла — исключение его эффекта. Падение вызова подграфа —
  любое исключение внутри его прогона, которое не поймали его куски: узла,
  перехода, схождения, неверный тип результата.
- Пойманное падение не роняет сессию. Ветки без перехода по падению ведут
  себя как раньше.
- Пойманное падение окончательно. При продолжении упавший узел не
  выполняется снова, а переход по падению идёт по журналу.
- В копии с лимитом переход по падению и то, что за ним, — часть копии:
  слот держится до их конца.
- describe пишет переход по падению ребром с подписью `failed`, холст рисует
  его выходом `failed` со стрелкой. Сессия показывает пойманное падение:
  упавший узел красный, выход, которым код не пошёл, темнее.
- Ключи и `after` эффектов от перехода по падению не зависят и одинаковы при
  каждом запуске.

## Не цели

- Ловить остановку (`FlowStoppedException`) и конец сессии по сбою
  хранилища или кодека. Это не падение: сессию можно продолжить, и дальше
  она пойдёт с места остановки.
- Повтор упавшего вызова (`retry`). Его можно написать переходом по падению,
  который вызывает тот же узел ещё раз.
- Отменять остальные ветки упавшего подграфа на первой ошибке.
- Переход по падению у схождения: схождение ничего не вызывает, падать
  нечему.
- Отдельное событие журнала для пойманного падения.

## Анти-цели

- Пойманное падение при продолжении выполняется снова.
- Переход по падению ловит остановку, и сессия идёт дальше после
  `flow.stop()`.
- Ключи эффектов вокруг вызова меняются от того, есть ли у него переход по
  падению.
- Ветки и графы без перехода по падению ведут себя иначе, чем раньше.
- При продолжении переход по падению получает другую ошибку, чем до обрыва.

## Решено

1. **Форма — `.failed(…)` у куска.** `Graph.part(x).next(ok).failed((input,
   failure) => …)` или `Graph.start(x).failed(…)`; порядок `.next` и
   `.failed` любой. Кусок знает тип входа своего узла (`Part<I, O>`), поэтому
   параметры перехода выводятся сами: `input` — `I`, `failure` —
   `CallFailure`.

   Почему не `next(ok, failed: …)`. У куска бывает переход по падению без
   своего `next`: узел кончает ветку или входит в схождение, а падение надо
   отдать. `next` остаётся прежним, а `.failed` читается, как граф: «после
   выхода — это, после падения — то». describe находит его в той же цепочке
   куска, что и `next`.

   Переход по падению объявляется у узла один раз, как его стрелки. Второй
   раз или у схождения — `ArgumentError` при создании графа.
2. **`CallFailure`** — `error`, текст исключения в одну строку, как его
   пишет `effect-failed`, и `type`, имя его рантайм-типа (`StateError`); у
   падения из журнала, записанного до этого решения, `type` — `null`. Имя
   рантайм-типа у ошибок SDK бывает закрытым (`_Exception`, `_TypeError`), а
   в обфусцированной сборке искажено, поэтому переходу стоит сверять `type`
   только со своими классами исключений. Кроме текста и
   типа, в журнале ничего нет, а при продолжении переход должен получить то
   же, что до обрыва. Поэтому само исключение он не получает.
3. **Что дальше.** Как у `next`: `Next`, множество, `null`, другое —
   `StateError` с именем графа. `null` кончает ветку без выхода: у упавшего
   вызова выхода нет, и в результат графа ничего не идёт. В схождения
   упавший узел ничего не кладёт.
4. **Что ловится.** Всё, что бросил вызов, пока сессия идёт: эффект узла
   упал (тело бросило или результат не кодируется), в подграфе бросил узел,
   переход, схождение, тип результата не тот. Когда флоу остановлен или
   сессия кончилась по сбою хранилища или кодека, переход не ловит ничего,
   и дальше идёт то, чем она кончилась. Поэтому падение, которое совпало с
   остановкой, ловится при продолжении, по журналу.
5. **Окончательность — по журналу эффектов.** Эффект, падение которого
   поймает переход, — узла, вызванного с переходом по падению, или любого
   узла подграфа, вызванного с ним, на любой глубине, — при продолжении не
   выполняется снова, если его последний исход в журнале — `effect-failed`
   и предшественник тот же. Он ничего не пишет и падает снова тем же текстом
   и типом. Переходы при продолжении вычисляются заново и бросают то же: они
   чистые. Поэтому подграф по журналу падает тем же падением, и переход по
   падению идёт по журналу. Эффект без перехода вокруг упавший при
   продолжении выполняется снова, как раньше.

   Падение в журнале у вызова, у которого переход по падению есть сейчас,
   окончательно, даже если записано, когда перехода не было: процесс ушёл
   раньше, чем сессия кончилась, а код с тех пор изменился.

   Обратное не так. Окончательность держит код, который продолжает сессию,
   а не журнал: в журнале нет записи, что падение поймано. Если, пока сессия
   с пойманным падением не кончилась, переход по падению убрали, перенесли в
   другой кусок (вызов, вокруг которого его нет) или nanoflow откатили на
   версию без переходов по падению, при продолжении упавший узел выполнится
   снова — поверх того, что переход по падению уже сделал: идея уже отдана,
   строка отчёта уже записана. Убирать переход по падению можно только
   тогда, когда незаконченных сессий с пойманными падениями нет.
6. **Эффекты, что шли при падении подграфа.** Идут до конца, как в любом
   графе, и их ветки тоже: узлы, что шли, кончаются, их переходы ведут
   дальше. Подграф падает, и его падение ловится, когда кончились все его
   ветки. Что они закончили, лежит в журнале, поэтому после пойманного
   падения продолжение не выполняет из подграфа ничего. Если процесс ушёл
   раньше, чем подграф кончился, продолжение повторяет падение по журналу и
   снова выполняет то, что шло, как любой незаконченный эффект.

   Отменять остальные ветки на первой ошибке отвергнуто: успела ли ветка
   пройти узел до падения соседней, решает тайминг, и при продолжении было бы
   иначе.
7. **Какое падение, если упало несколько веток.** В прогоне, падение
   которого поймает переход, — падение ветки, первой в порядке графа: старты
   по порядку, узлы множества перехода по порядку, схождения после них. Не
   первое по времени: при продолжении падения из журнала приходят в другом
   порядке. Вне перехода — как раньше: первое по времени.
8. **Ключи и `after`.** Вызов с переходом по падению отдаёт падение своей
   ветке значением, а не исключением. Ветка идёт дальше там же, где пошла бы
   после выхода. После узла — в контексте его эффекта: эффекты перехода по
   падению идут после упавшего эффекта (`after` — его ключ), как эффекты
   `next` идут после узла. После подграфа — в своём контексте, как после его
   выхода. Сверх того, что регистрируется без перехода, не регистрируется ни
   одного колбэка, поэтому ключи эффектов в вызове и вокруг него те же, что
   без перехода.
9. **Лимит.** Переход по падению внутри копии — часть копии. Копия — весь
   прогон вызванного подграфа, и её слот держится, пока он не кончится, а
   кончается он после перехода по падению и того, что за ним. Так ночь
   оборачивает `developIdea` в `nightIdea`: `claim → developIdea → settle`,
   падение → `giveBack`, и вызывает копии `nightIdea` с лимитом.

   Переход по падению на куске самого вызова с лимитом идёт после вызова, как
   `next`: копия к этому времени кончилась. Вызовы перехода по падению —
   своё место вызова, не то же, что у `next` того же куска.
10. **Файл графа.** У ребра — необязательное поле `failed: true`, у ребра
    перехода по падению, которое выходит из узла; подпись такого ребра —
    `failed`. Пишется, только если есть, номер формата тот же. Старый UI
    рисует такое ребро выходом с подписью `failed`, и это читается верно.
    Поле отличает выход перехода по падению от случая `switch` с тем же
    текстом.
11. **Холст.** Выход по падению — выход узла с подписью `failed`, как другие
    выходы: точка или капсула, стрелки, подпись на подложке. Выход
    объединяет рёбра по подписи и признаку падения, так что случай `failed`
    у `switch` и переход по падению — два выхода.
12. **Сессия на холсте.** Упавший узел красный, как любой упавший эффект.
    Узел с переходом по падению решает, куда идти, как развилка. Переход от
    эффекта на нём идёт рёбрами падения, если эффект упал, и остальными, если
    кончился. Когда код ушёл из такого узла, его выходы, которыми не мог
    пойти ни один переход, темнее, как у пройденной развилки.

    У вызова подграфа исхода в журнале нет: упавший эффект внутри мог быть
    пойман там же. Поэтому переход от вызова идёт любыми рёбрами, и выход
    темнеет, только если по переходам видно, что код им не шёл: выход и
    падение ведут в разные узлы. Если оба ведут в один узел (`pick` ночной
    генерации), не темнеет ни один.

## Подходы

1. **Падение — значение у вызова с переходом, окончательность — по журналу
   эффектов** (выбран). Прогон знает, поймает ли его падение переход
   (`Failures`): нет, переход снаружи, переход у этого вызова. Эффект в
   прогоне с переходом при продолжении берёт падение из журнала. Вызов с
   переходом отдаёт падение значением `Caught`, и ветка ведёт его в переход
   по падению.
2. **Новое событие журнала для пойманного падения** (`call-failed` по ключу
   вызова) — отвергнут. У прогона подграфа нет ключа, он не эффект. Новое
   событие — это хранилища, читатели и UI, а исходы эффектов и так решают,
   чем кончится прогон.
3. **`try`/`catch` вокруг `await` в ветке** — отвергнут. Ветка шла бы
   дальше в контексте колбэка ошибки, а не там, где после выхода: эффекты
   перехода по падению шли бы после того, что было до вызова, а UI видел бы
   их рядом с ним. Обёртка `.then(…, onError: …)` регистрирует лишние
   колбэки и сдвигает ключи соседних веток.
4. **Упавший подграф как эффект** — отвергнут. Лишний эффект на холсте, а
   ключи всех эффектов подграфа зависели бы от того, есть ли переход.

## Как устроено

### `packages/nanoflow/lib/src/failure.dart`

- `CallFailure` (экспортируется): `error`, `type`, `==`, `toString`.
- `Failures`: `thrown` — перехода нет; `kept` — переход снаружи: падение
  окончательно и бросается дальше; `caught` — переход у этого вызова:
  падение окончательно и отдаётся значением.
- `Caught` — падение, которое вызов с переходом отдаёт вместо выхода.
- `ReplayedFailure` — то, чем падает эффект из журнала в прогоне `kept`.
- `failureOf(error)` — `CallFailure` исключения: текст, как пишет журнал, и
  имя типа; у `ReplayedFailure` — сохранённые.

### `packages/nanoflow/lib/src/graph.dart`

- `Part<I, O>`, `Part.failed(route)`; `Graph.start<I, O>`,
  `Graph.part<I, O>`; `Graph.join` даёт `Part<Never, Never>`.
- `ShapeNode.failed` — переход по падению; проверки при создании: «the
  failure route of x is declared twice», «the join of a, b has a failure
  route: a join calls nothing».
- `GraphRun.runWith(…, failures:)`.

### `packages/nanoflow/lib/src/graph_run.dart`

- `_Run` знает свои `Failures`. `_call` отдаёт узлу или подграфу `caught`,
  если у куска есть переход по падению, иначе `kept` в прогоне с переходом,
  иначе `thrown`.
- `_branch`: выход `Caught` ведёт в переход по падению с входом вызова; ни в
  схождения, ни в результат он не идёт. Место вызова перехода по падению —
  `(кусок, падение, цель)`.
- В прогоне `kept` или `caught` ветка не бросает, а записывает падение с
  местом в порядке графа (путь индексов); прогон, когда кончились все ветки,
  бросает первое по месту. Прогон `caught` вместо этого проверяет, что сессия
  идёт, и отдаёт `Caught`. Тип результата проверяется там же.
- `Future.wait` и регистрации колбэков те же, что без перехода.

### `packages/nanoflow/lib/src/flow.dart`

- `nodeEffect(…, failures:)` → `_Session.effect(…, failures:)`.
- В журнале — падения по ключу: последний исход `effect-failed`, его
  `after`, текст и тип.
- `effect`: при `kept` или `caught` падение из журнала с тем же `after` —
  `Future.error(ReplayedFailure)` или `Caught`; копии помечаются
  проигранными.
- `_live`: `effect-failed` пишет и `errorType`; при `caught`, если сессия
  идёт, отдаёт `Caught`.
- `checkGoesOn(flow, what)` — бросает остановку или падение сессии.

### Модель

- `EffectFailed.errorType` (`String?`, пишется, только если есть) и
  `EffectState.errorType`.
- `GraphEdge.failed` (`bool`, пишется, только если `true`).

### describe

- Цепочка куска: `.next` и `.failed` в любом порядке, по одному. Переход по
  падению читается от узла с исходом `failed`: его первый `switch` или `if`
  — развилка, а не выходы узла (они у `next`). Рёбра, выходящие из узла по
  этому исходу, — `failed: true`. `.failed` у схождения — кусок не
  нарисован.

### UI

- `GExit.failed`: выходы — по подписи и признаку.
- `passes.dart`: у переходов от одного эффекта — его исход; первые рёбра от
  узла эффекта с рёбрами падения выбираются по исходу. Узел с рёбрами
  падения, из которого ушёл переход, темнит выходы, как пройденная
  развилка. Ветки множества в выходе узла — как у развилки: рядом.

## Тесты

`packages/nanoflow/test/failure_route_test.dart`:

1. Узел упал: переход по падению получает вход и `CallFailure` (текст, тип),
   ведёт в `giveBack`; сессия кончилась результатом, в журнале
   `effect-failed` и `session-finished`.
2. Подграф упал глубоко (узел в подграфе подграфа): ловит переход у вызова
   внешнего подграфа; ловит и падение перехода в подграфе.
3. Пойманное падение окончательно: после обрыва в ветке за переходом
   продолжение не выполняет упавший узел, переход по падению получает то же
   падение, `giveBack` из журнала; так же для подграфа.
4. Остановка не ловится: `flow.stop()` во время узла с переходом — сессия
   кончается `FlowStoppedException`, переход не вызван; при продолжении узел
   выполняется снова.
5. Сбой хранилища не ловится; падение сессии по кодеку при продолжении не
   ловится.
6. Лимит: копия `nightIdea` с `limit: 1`, у первой падает `develop`, а
   `giveBack` медленный — `claim` второй начинается после конца `giveBack`.
7. `for`: падает одна копия из трёх — переход только у неё, остальные идут
   по `next`.
8. Без перехода — как раньше: сессия падает, при продолжении узел
   выполняется снова.
9. Ключи и `after`: эффекты перехода по падению идут после упавшего узла;
   ключи те же при любом тайминге; ключи эффектов вокруг вызова те же, что
   без перехода.
10. Несколько упавших веток подграфа: переход получает падение первой по
    порядку графа и до обрыва, и после.
11. Переход по падению даёт `null`: ветка кончается, результат графа — выход
    другой ветки.

`graph_test.dart` — `.failed` дважды, у схождения, у `Graph.start`.
Модель — `errorType` и `failed` туда и обратно, старый JSON без ключей.
describe — фикстура с `.failed` (узел, подграф, `.failed` раньше `.next`,
`switch` в переходе по падению, `for` с лимитом). UI — выход `failed`
отдельно от случая `failed`; затемнение выходов узла с переходом по падению
по исходу эффекта.

## Мои решения

- `.failed`, а не параметр `next` (п. 1). Имя `failed` — то же слово, что
  подпись ребра и статус эффекта.
- `Part<I, O>`: тип входа нужен, чтобы параметры перехода по падению
  выводились; в ideaforge `Part<…>` никто не называет.
- Падение — текст и тип, а не исключение (п. 2). Тип пишется в
  `effect-failed` новым необязательным полем `errorType`.
- Переход по падению ловит, только пока сессия идёт (п. 4), а не по типу
  исключения: эффект с `StorageException` из своего тела — обычное падение,
  и при продолжении он из журнала был бы пойман, а сейчас — нет.
- Падение подграфа — после конца всех его веток (п. 6), как и сейчас
  падает граф.
- Переход по падению у куска вызова с лимитом — после копии (п. 9), как
  `next`.
