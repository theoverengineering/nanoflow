# Граф из узлов рядом с функцией воркфлоу

Дополняет [дизайн code-first](2026-10-03-code-first-design.md) (§4.1 API,
§4.4 кодеки, §6.1 формат, §7.1 извлечение) и
[журнал решений](2026-10-02-code-first-decisions.md) (решение 13). Ничего из
нынешнего не убирает. Решения приняты 2026-10-08.

## 1. Зачем

Сейчас узел графа — место в коде: эффект или вызов функции, а что после
него — решает код вокруг (`if`, `while`, `return`). Сослаться на узел нельзя:
у вызова функции продолжение — там, откуда её вызвали. Нужен второй способ:
узел — самостоятельная функция «вход → выход», которая не знает, что было до
неё и что будет после; кто после кого, решает объявление графа. Ветвление и
схождение — забота библиотеки, а не узла.

Функция воркфлоу остаётся как есть. Граф — альтернатива рядом, и оба
вкладываются друг в друга: узлом графа может быть функция воркфлоу или другой
граф, а функция воркфлоу может вызвать граф.

## 2. Как выглядит

```dart
// узлы — обычные функции верхнего уровня или статические методы
Future<Collected> collect(String branch) async { … }   // Empty() или Found(change)
Future<Inspected> inspect(Change change) async { … }   // Clean(report) или Findings(report)
Future<Change> fix(Report report) async { … }
Future<void> discard(void _) async => print('nothing to review');
Future<String> publish(Report r) async { … }
Future<String> notify(Report r) async { … }
Future<void> report((String, String) sent) async { … }

final review = Graph<String, void>('review', [
  Graph.start(collect).next({Empty: discard, Found: inspect}),
  Graph.part(inspect).next({Clean: {publish, notify}, Findings: fix}),
  Graph.part(fix).next(inspect),
  Graph.join([publish, notify]).next(report),
]);

await flow.run(review, 'feature/parse-config');
```

## 3. Узлы

- **Узел** — одно из трёх:
  - **функция** `I → O` (`FutureOr<O> Function(I)`): выполняется как эффект
    сессии; имя эффекта — имя функции, результат пишется в журнал и при
    `resume` берётся из него;
  - **функция воркфлоу** `Future<O> Function(Flow f, I input)`: вызывается
    как есть, её эффекты — свои;
  - **граф** `Graph<I, O>`: вызывается как есть.
- **Имя узла** — имя функции из её `toString()`, как у воркфлоу (§4.1):
  функция верхнего уровня или статический метод; у графа — его имя. Имена
  узлов одного графа различны.
- **Узел — один на функцию**: та же функция в нескольких стрелках — один
  узел (так рисуются петли).

## 4. Стрелки

- `Graph.start(узел)` — кусок от узла, с которого начинается граф; его вход —
  вход графа. Стартов может быть несколько: они начинаются одновременно.
- `Graph.part(узел)` — кусок от любого узла.
- `Graph.join([a, b, …])` — схождение 2–6 узлов (§6).
- `.next(цель, {otherwise: цель})` — стрелки из узла куска. Возвращает кусок
  на цели, если цель — один узел (`Graph.start(a).next(b).next(c)`); после
  множества и карты кусок кончается.
- **Цель** — одно из:
  - **узел** — получает выход целиком;
  - **множество `{a, b}`** — все узлы получают выход целиком и идут
    одновременно;
  - **карта `{ключ: цель}`** — ветвление (§5); цель в карте — узел или
    множество.
- `otherwise:` — только с картой: цель для выходов, которых нет в карте.
- **Стрелки узла объявляются один раз.** Узел без стрелок кончает свою ветку.

## 5. Ветвление

Узел выполняется один раз, его выход разбирает библиотека, один раз.

- **Предмет и груз.** Из выхода `v` берутся предмет (что сравнивается с
  ключами) и груз (что получает цель ключа):
  - `v` — запись из двух позиционных полей `(k, p)`: предмет `k`, груз `p`
    (`(Verdict.pass, report)`);
  - `v` — наследник `Exit<T>` библиотеки: предмет `v`, груз `v.value`;
  - иначе — предмет и груз `v`.
- **Ключ** — тип или значение. Тип совпадает, когда тип предмета во время
  выполнения — ровно он (`Found`); значение — по `==` (`Verdict.pass`,
  `true`, `null`). Берётся первый совпавший ключ в порядке карты.
- **Совпал ключ** — его цель получает груз. **Не совпал** — цель
  `otherwise` получает выход целиком; без `otherwise` ветка кончается.
- **`Exit<T>`** — `abstract class Exit<T> { const Exit(this.value); final T
  value; }`: выход с грузом, `final class Found extends Exit<Change>
  implements Collected`.

## 6. Схождение

- `Graph.join([a, b]).next(c)`: `c` получает запись выходов `(выход a,
  выход b)` в порядке списка, когда каждый из узлов дал выход.
- **Очереди.** Выходы каждого узла схождения копятся по порядку; когда у
  всех есть по выходу, берётся по первому, и цель запускается. В петле
  схождение срабатывает столько раз, сколько полных наборов набралось.
- **Неполное схождение не наступает:** когда больше ничего в графе не
  выполняется, а набор не полон, ветка кончается.
- **Где идёт продолжение.** Цель запускается из ветки первого узла списка,
  после его выхода — так ключи эффектов цели не зависят от того, какая ветка
  кончилась последней.

## 7. Граф целиком

- `Graph<I, O>(String name, List<Part> parts)` — объявляется в переменной
  верхнего уровня; `name` — имя воркфлоу и узла, обычно имя переменной.
- **Проверки при создании** (`ArgumentError` со списком): узел не функция с
  одним параметром, не функция воркфлоу и не граф; функция — не верхнего
  уровня и не статический метод; два узла с одним именем; стрелки узла
  объявлены дважды; нет старта; узел, до которого не дойти; схождение меньше
  чем из двух узлов, больше чем из шести или с узлом дважды; `otherwise`
  без карты; цель не узел, не множество узлов и не карта; `next` после
  множества или карты.
- **Граф — функция воркфлоу:** `Future<O> call(Flow f, I input)`. Поэтому
  `flow.start(review, input)`, `flow.run`, `flow.resume`, `flow.unfinished`
  принимают граф как функцию, а функция воркфлоу вызывает граф как функцию:
  `await review(f, change)`. Имя сессии — имя графа.
- **Конец.** Граф кончается, когда кончились все ветки; ошибка узла — ошибка
  графа после того, как кончились остальные ветки (как у `Future.wait`).
- **Результат** — выход узла, который никуда не пошёл (у узла нет стрелок, он
  не в схождении, или карта его не разобрала), последним по времени. Нет
  такого — `null`; результат не `O` — `TypeError`. Обычно `O` — `void`.

## 8. Журнал и кодеки

- **Выход узла-функции** пишется как результат эффекта. Его тип библиотека
  узнаёт из типа функции, спрашивая «подтип ли?», как кодеки узнают тип (§4.4):
  `узел is FutureOr<X> Function(Never)` для `X` из типов JSON, типов с
  кодеком и их `List`, `Map<String, …>`, `…?`, записей из двух полей; берётся
  самый узкий. Функция, возвращающая `Future<Collected>`, раскодируется кодеком
  `Collected`. Тип, которого так не найти, — как `Object?`: JSON как есть.
- **Перечисления:** `flow.addEnum(Verdict.values)` — значение пишется именем
  и читается по нему. Работает и для `f.effect<Verdict>`.
- **Записи из двух позиционных полей** пишутся списком `[a, b]` — и для узлов,
  и для `f.effect<(A, B)>`.
- **Место эффекта узла** — место объявления графа из файла графа в каталоге
  проекта (`functions[…].place` графа с этим именем); нет файла или графа в
  нём — `null`. Стек тут не годится: в собранной программе кадры
  инициализаторов верхнего уровня путаются.
- **Ключи** — как у функции: граф выполняется кодом библиотеки, который
  ждёт узлы так же, как написанная рукой функция (`await` узла, `Future.wait`
  ветвей), поэтому ключи и `after` одинаковы при каждом запуске.

## 9. Файл графа

Формат прежний, `2`. Граф — запись в `functions` с id `путь#<переменная>`,
`name` — имя графа, `place` — строка имени переменной, `body` — тело из
прежних видов узлов:

- узел-функция — `effect` (`name` — имя узла, `place` — место графа);
- узел — функция воркфлоу или граф — `call` (`functions` — его id, `place` —
  место графа);
- стрелка-карта — `fork` после узла: `label` — `switch (<имя узла>)`,
  `place` — строка карты; рёбра подписаны исходником ключа, `otherwise` —
  `otherwise`; без `otherwise` и не на все значения (`bool`, перечисление,
  `sealed`, запись из них в первом поле) — ребро `otherwise` в конец;
- множество — рёбра к каждому; схождение — рёбра от каждого узла к цели;
- старт — ребро от входа; узел, чей выход никуда не идёт, — ребро в конец;
- id узлов — по порядку появления в объявлении.

`workflows` — и графы, переданные в `Flow.start`/`run`/`resume`. Граф всегда
в `functions`, как и функции воркфлоу, служащие узлами. Вызов графа из
функции — узел `call`. `GraphFile.workflowNamed` ищет воркфлоу по `name`.

UI берёт тело как есть: новых видов узлов нет, и он ничего не меняет.

## 10. `describe`

- Находит переменные верхнего уровня с `Graph(...)` из `package:nanoflow`
  и читает список кусков: `Graph.start`/`part`/`join`, цепочки `.next`,
  цели — ссылки на функции и графы, литералы множеств и карт.
- **Предупреждения:** граф не в переменной верхнего уровня; имя графа — не
  литерал строки; кусок, который не прочесть; узел — не функция верхнего
  уровня, не статический метод и не граф; несовпадение типов: цель не
  принимает груз (`report takes (String, String), not the String of
  publish`); ключ-тип не подтип предмета, ключ-значение не того типа.
- Узлы-функции не проверяются на побочные эффекты: каждая — эффект.

## 11. Ограничения

- **Данные идут только через выходы:** что нужно дальше, узел возвращает.
- **Каждая стрелка с узлом-функцией — запись в журнал:** выход должен
  кодироваться (§8).
- **Параллель статическая:** множество и схождение объявлены; копий «по
  элементу списка» нет — это функция воркфлоу.
- **Ключ-тип совпадает ровно:** подкласс подкласса ключом-родителем не
  ловится; ключи — классы-листья.
- **Две стрелки в узел без схождения** — два запуска узла; на рисунке это не
  отличить от схождения, как и у функции.
- **Метки пройденного в UI** выводятся из журнала, как у функции; у
  схождения предшественник цели — первый узел списка, второй виден как
  законченный без продолжения.

## 12. Тесты

- `nanoflow`: проверки создания; ветвление по типу, значению, `null`,
  `bool`, `Exit`, паре и `otherwise`; множество, схождение (в том числе в
  петле и неполное), петля; узлы — функции воркфлоу и графы; граф из функции;
  `start`/`resume`/`unfinished` графа: выходы из журнала раскодируются
  кодеком, перечислением, записью; результат; место эффекта узла по файлу
  графа; ключи одинаковы при случайных задержках.
- Кодеки: `addEnum`, записи из двух полей, тип выхода функции.
- `describe`: фикстура с графами — тела, рёбра, подписи, исчерпывающие и
  нет карты, схождение, граф из функции, граф-узел; предупреждения.
- `nanoflow_model`: `workflowNamed` по `name`.
- Пример `examples/review`: тот же ревью графом (`lib/review_graph.dart`,
  `bin/graph.dart`), его файл графа проверяет `--check`; e2e — граф доходит
  до конца и продолжается после падения.
