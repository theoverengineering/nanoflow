# Граф кодом: принятые решения

Решения нового направления: воркфлоу — обычная функция с шагами, граф
извлекается из её кода, UI его показывает. Записываются по мере принятия;
из них потом собирается спек.

## 1. Для исполнения граф не нужен

**Решение.** Исполнение от графа не зависит: ключи шагов и повтор после
падения работают без него. Приложению граф нужен ровно для одного — записать
снимок графа в сессию (решение 8). Устаревший или отсутствующий граф не может
сломать исполнение: в худшем случае снимок в сессии не тот или его нет, и UI
это показывает.

**Зачем граф был нужен.** Чтобы найти сохранённый результат шага после
падения, у шага должен быть ключ, который не зависит от того, какая из
параллельных копий быстрее. Казалось, что для этого нужны области из графа:
шаг после `Future.wait` иначе попадал бы в копию, закончившую последней.

**Как без него.** Библиотека выполняет функцию воркфлоу в своей зоне, и у
каждого вызова асинхронной функции своя метка:

- **Номер среди соседей.** Стартуя, вызов получает метку того, кто его
  запустил, плюс свой номер там: `~4`, `~9`. Код идёт в одной метке за раз и
  в одном порядке при каждом запуске, поэтому номера одинаковые при любых
  задержках. Две копии из одного цикла различаются сразу, даже если первым
  делом ждут не шаг, а `http.get`.
- **После шага — метка шага.** Получив после `await` ровно результат шага,
  вызов берёт метку этого шага: копия `core` после своего `upload` —
  `upload#1`, копия `tool` — `upload#2`.
- **После любого другого ожидания** — `http.get`, `Future.wait` — метка не
  меняется. Поэтому после `Future.wait` родитель продолжает со своей меткой,
  какая бы копия ни закончила последней.
- **Ключ шага** — метка плюс имя и номер: `upload#2/verify#1`,
  `~4/upload#1`, `~15/announce#1`.

Номер достаётся каждому обратному вызову, который код ставит в очередь:
продолжению `await`, микрозадаче, таймеру. Виртуальная машина Dart
регистрирует продолжение один раз на вызов функции, при первом `await`,
поэтому метка принадлежит вызову, а не отдельному `await`. Шаг из журнала и
шаг вживую ставят в очередь одно и то же, чтобы номера после продолжения не
сдвигались.

**Проверено.** Прототип — [`prototypes/step_keys`](../../../prototypes/step_keys),
14 видов кода:

- копии замыканием на месте, через `map`, функцией с `return` без `await`;
- последовательный `for`, петля «inspect → fix» из README, рекурсия;
- одиночные шаги в `Future.wait`, копии внутри копий;
- копии, чьи шаги возвращают один и тот же объект (`true`, `null`, строку);
- шаг, запущенный раньше, чем его ждут;
- сбой шага, пойманный в копии, после которого идёт другой шаг;
- шаги в `await for` по потоку;
- копии, запущенные по одной с ожиданием между стартами;
- копии, которые первым делом ждут не шаг.

На каждый — 20 живых запусков со случайными задержками (ключи одинаковые) и
20 падений в случайном месте с продолжением (каждая копия получает свои
результаты). Всё проходит под `dart test` и в собранном `exe`
(`tool/check_exe.dart`).

**Цена.** Номера `~k` зависят от того, сколько обратных вызовов код поставил
в очередь до них. Если код изменили и продолжили сессию, у шагов с `~` в
ключе ключ может сдвинуться, и они выполнятся заново, а не возьмутся из
журнала. Шаги, ключ которых начинается с шага (`collect#1/inspect#1`),
сдвигаются только от правок в шагах.

**Отвергнуто:**

- **Области по стеку вызова.** `return future` без `await`, который советует
  линт `unnecessary_await_in_return`, обрывает цепочку в стеке: в 3
  продолжениях из 20 копии молча получили чужие результаты.
- **Области из графа.** Работает, но привязывает исполнение к графу: нужен
  граф в работающем приложении и проверка, что он от того же кода.
- **Пропускать завершения шагов по одному.** Не нужно: метка вызова
  различает копии и без этого.
- **Метка только от шагов, без номеров вызовов.** Копии, которые первым
  делом ждут не шаг, вызывают свой первый шаг с одинаковой меткой родителя,
  в порядке прихода: копии внутри копий и копии после `http.get` молча
  получали чужие результаты.

## 2. Воркфлоу — обычная функция, библиотека — внутри приложения

**Решение.** Воркфлоу — обычная асинхронная функция Dart, шаг —
`f.step('имя', () => …)`. Отдельного процесса движка, протокола
`--graph`/`--call` и YAML нет: прогон ведёт библиотека в процессе
приложения. Граф из README выглядит так:

```dart
Future<void> review(Flow f, String branch) async {
  var change = await f.step('collect', () => git.changeOf(branch));
  if (change.path.isEmpty) {
    await f.step('discard', () => print('nothing to review'));
    return;
  }
  while (true) {
    final report = await f.step('inspect', () => inspect(change));
    if (report.findings.isEmpty) {
      await Future.wait([
        f.step('publish', () => publish(report)),
        f.step('notify', () => notify(report)),
      ]);
      return;
    }
    change = await f.step('fix', () => fix(report));
  }
}

Future<void> main() async {
  final flow = Flow(store: FsStore('runs'))
    ..addCodec(Change.fromJson)
    ..addCodec(Report.fromJson);

  await flow.run(review, 'feature/parse-config');
  // после падения: await flow.resume(review, sessionId);
}
```

Развилки — `if` и `switch`, петли — циклы, разветвление — `Future.wait`;
всё это обычный Dart, отдельного языка графа нет.

## 3. Что требуется от кода

Для исполнения — только два правила:

- **Шаг вызывается как `f.step(…)` внутри `flow.run`.** `f` приходит в
  функцию воркфлоу; шаг вне `run` — ошибка.
- **Результат шага и вход воркфлоу превращаются в JSON.** Встроенные
  JSON-типы — как есть, свои классы — через `toJson` и `addCodec` (решение 4).

Для графа в UI — ещё одно: **имя шага — строковый литерал.** Иначе
извлекатель не знает, как подписать узел, и предупреждает; исполнению это не
мешает.

Остальное свободно: любые `async`, `Future.wait`, циклы, замыкания,
функции, классы, DI, `await` чего угодно между шагами.

**Не правило, но свойство:** сохраняются только шаги. Код между шагами при
продолжении после падения выполняется заново. Если он решает по времени,
случайному числу или ответу `http.get`, продолжение может пойти другой
дорогой — тогда сессия получает ту же отметку, что при изменённом коде
(решение 7).

## 4. Кодеки задаёт пользователь

**Решение.** Свой тип результата шага регистрируется одним методом:
`flow.addCodec(Report.fromJson)`; `toJson` библиотека вызывает у значения
сама. Тип выводится из `fromJson`, перепутать тип и функцию — ошибка
компиляции. При первом выполнении шага библиотека делает `toJson` →
`fromJson`: нет кодека или не сходится — ошибка сразу, а не при повторе после
падения. Извлекатель графа подсвечивает тип без `fromJson`/`toJson` заранее.

Генерация кодеков (`build_runner`) и `dart:mirrors` — возможные дополнения
поверх, отдельными пакетами; ядро о них не знает. Пока — только `addCodec`.

**Отвергнуто:** карта `{Report: Report.fromJson}` — компилятор не проверяет
тип; `decode:` в каждом шаге — повторяется в каждом шаге с этим типом.

## 5. Граф извлекается из кода, файл графа пишет разработчик

**Решение.** Граф строится статически, `package:analyzer`, без выполнения
кода: граф потока управления функции воркфлоу, сведённый к вызовам
`f.step`. Первая версия понимает `if`/`switch`, циклы, `Future.wait`, `map`,
замыкания, вызванные на месте, и заход в вызываемые функции той же
библиотеки; на остальное — предупреждения. Прототип —
[`prototypes/static_graph`](../../../prototypes/static_graph): граф из README
извлекается один в один.

`dart run nanoflow:describe --watch` держит запущенным разработчик; он
перезаписывает файл графа при каждой правке. UI только читает этот файл и
ничего не запускает, поэтому не знает, на каком языке написан граф: для JS
или Python свою команду `describe` даст их библиотека, формат файла общий.

**Граф — отдельный файл, и строится он только там, где есть исходники и
инструменты языка:** при разработке и при сборке. Работающее приложение его
никогда не строит, только копирует в сессию (решение 8).

**Отвергнуто:**

- **Строить граф в приложении.** Под `dart run` mirrors отдают исходник
  функции, и анализатор мог бы работать в процессе — ценой тяжёлой
  зависимости и секунд на старте сессии. В `exe`, Flutter release и вебе
  исходников нет, а программа с `dart:mirrors` не компилируется в `exe`.
  Файл для них нужен всё равно — второй путь к тому же результату лишний.
- **Встраивать граф в бинарник генерацией кода** (`build_runner`). Нужен
  запущенный `build_runner watch`, а UI граф из бинарника не прочитает.
- **Build hooks.** Ассеты данных в Dart 3.13 — эксперимент
  (`--enable-experiment=data-assets`), читать их во время работы обычного
  Dart-приложения нечем.
- **Живой канал от `describe` к UI.** Только для разработки; для `exe` и
  истории файл нужен всё равно.

## 6. Функция на холсте — плитка, раскрывается на месте

**Решение.** Функция с шагами рисуется плиткой «стопкой» с числом шагов
внутри (`{ 3 }`) и текущим шагом прогона. Двойной клик — провалиться в её
граф, вверху путь `release › publish() › upload()`. Кнопка — раскрыть на
месте: рамка с серой сплошной обводкой без фона, одинаковая на любой
глубине. Вложенность не ограничена: на холсте один уровень плюс то, что
раскрыто.

## 7. Ожидание и изменённый код

- **Долгое ожидание** — живой процесс: шаг — обычный `await`, ждёт сколько
  нужно. Упал процесс — при продолжении незавершённый шаг выполняется
  заново. Парковка прогона (`waitFor`, `sleep`) — не сейчас.
- **Продолжение на изменённом коде** — по ключам: шаг, чей ключ есть в
  журнале, берёт сохранённое, новые выполняются, лишние остаются в истории.
  Сессия получает отметку «продолжена на изменённом коде» и новый снимок
  графа с новым хэшем кода (решение 8); прежний снимок остаётся.

## 8. Снимок графа в сессии и отпечатки кода

**Снимок.** Правило README остаётся: сессия хранит снимок графа, на котором
шла. Создавая сессию, приложение читает файл графа — рядом с исходниками под
`dart run`, рядом с бинарником или в ассетах — и копирует граф в сессию.
Файла нет — сессия создаётся без снимка, с отметкой.

**Отпечаток исходников.** Каждый исходный файл проекта хэшируется по
содержимому (переводы строк приведены к `\n`); строки «путь хэш»
сортируются по пути; этот текст хэшируется целиком. Какие файлы входят,
решает библиотека языка.

**Файл графа** кроме самого графа хранит:

```json
{
  "fingerprint": "sha256:7d3e…",
  "sources": { "bin/main.dart": "sha256:aa11…", "lib/review.dart": "sha256:9f2c…" },
  "builds": { "review": "sha256:c07e…" }
}
```

- `fingerprint` и `sources` пишет `describe`;
- `builds` — шаг после компиляции (`nanoflow:stamp`): проверяет, что
  `sources` совпадают с исходниками, и добавляет хэш собранного файла.

**Сессия** хранит хэш кода, который выполнялся: под `dart run` — отпечаток
исходников, собранное приложение — хэш собственного файла.

**UI, одинаково для любого языка:** хэш байтов — исходников на диске или
записанный в сессии — должен найтись в `fingerprint` или `builds` графа.
Не нашёлся — граф показывается как есть, с подсветкой «может не
соответствовать коду» и списком изменённых файлов, если они известны. Хэша
нет — «не проверено».

## 9. Где сессии, сбой шага, вход шага

- **Сессии лежат в `runs/` рядом с файлом графа.** UI открывает файл графа и
  видит сессии рядом; у собранного приложения — рядом с бинарником.
- **Сбой шага — обычное исключение Dart.** Его можно поймать в коде
  воркфлоу; не пойманное роняет сессию. Сбойный шаг в журнал как готовый не
  попадает, поэтому `resume` выполняет его заново.
- **У шага нет входа, только выход.** Данные шаг берёт из замыкания. В окне
  шага остаются выход, лог и место в коде.

## 10. Параллельные копии — рамка-стопка

**Решение.** Тело, которое выполняется копиями одновременно
(`Future.wait` над циклом или `map`), рисуется рамкой, за которой видны ещё
две — «несколько копий». Над рамкой — над чем копии и сколько их:
«каждый pkg в packages · ×3 · одновременно». Из рамки одна стрелка дальше —
«все готовы». Во время прогона на шагах внутри — сколько копий сейчас на
шаге, внизу рамки — «готово 1 из 3». Рамка сворачивается в плитку-стопку
`×3` и раскрывается так же, как функция (решение 6).

**Отвергнуто:** развилка с `true`/`else`, как сейчас, — читается как `if`;
отдельные узлы «разделиться» и «собраться», как в BPMN, — что внутри идут
копии, видно только по подписи.

## 11. Одна копия — переключатель в шапке рамки

**Решение.** В шапке рамки копий — «все» и номера копий со статусом:
«все · 1 ✓ · 2 ● · 3 ●». Номер — порядок старта копии; рядом короткая
подсказка из результата её первого шага, чтобы узнать копию, не зная кода.

- **«Все»** — вид по умолчанию: на шагах цифры, сколько копий сейчас на
  шаге, внизу рамки «готово 1 из 3», панель логов показывает шаги всех копий
  по времени с номером копии в каждой строке, путь не подсвечивается.
- **Номер копии** — внутри рамки виден только её путь: пройденные шаги с
  галочкой, текущий подсвечен, непройденные приглушены; внизу рамки «копия 2
  · сейчас verify»; панель логов показывает шаги только этой копии.
- **Копий много** — вместо кнопок список с поиском и фильтром «идут / упали
  / готовы».
- **Копии внутри копий** — выбор задаётся путём: «копия 2 › сборка 1».

**Отвергнуто:** список копий по клику на цифру шага — пока не нужен.

## 12. Доработки текущей реализации

По ветке `implementation` на 8357263. «Остаётся» — берётся как есть или с
переименованием, «переделывается» — та же роль, другое содержание, «уходит» —
удаляется.

### Пакеты

**`nanoflow_model`** — договор библиотеки и UI, остаётся пакетом.

- Остаётся: `ids`, `time`, `json_fields`; устройство событий (`KnownEvent` /
  `UnknownEvent`, `fromJson` без исключений, незнакомое событие читается как
  есть); остов `replay` (порядок шагов по первому `step-started`, `starts`,
  статус по последнему событию); раскладка `runs/` в `storage_layout`;
  словарь ленты изменений.
- Переделывается:
  - **Граф** (`graph.dart`) — вместо формата README (`start`, `nodes`,
    `then`/`else`, `types`) — граф из файла графа: шаги, развилки с
    подписями-условиями, рамки функций и рамки копий, места в коде, плюс
    `fingerprint`/`sources`/`builds` (решение 8). `GraphDescription` уходит.
  - **Сессия** — снимок графа остаётся; добавляется хэш выполнявшегося кода.
    Вход воркфлоу — документ.
  - **Прогона больше нет.** Исполнение не знает, какие вызовы — копии: это
    знает только граф. Сессия — один вызов функции воркфлоу с одним
    журналом; копии выводит UI по графу и по предшественнику шага (`after`).
  - **Шаг**: без `inputId`; с ключом (решение 1), предшественником и местом
    вызова; `outputId` — результат.
  - **События** — события сессии, а не прогона: `step-finished` без
    `exitCode`, ошибка шага — отдельное событие с текстом и стеком;
    `run-split` уходит; продолжение — `session-resumed` с хэшем кода и, если
    код изменился, новым снимком графа (решение 7).
  - Лог шага — `step.log` вместо `command.log`.

  Точные формы — в [спецификации](2026-10-03-code-first-design.md) §5.

**`nanoflow_store`** — запись сессий, теперь из библиотеки, а не из движка.

- Остаётся: атомарная запись (`atomic.dart`); блокировка сессии
  (`engine_lock.dart`, переименовать в блокировку владельца сессии) — один
  процесс ведёт сессию, второй `resume` получает отказ; обрезка недописанной
  строки журнала при открытии; монотонное время в именах; `StepLog` с
  противодавлением; защита от записи в удалённую сессию.
- Переделывается: `createSession` (вход, снимок графа, хэш кода; один
  журнал сессии вместо прогонов), `createStep` (имя, ключ, предшественник,
  место; без `inputId`), запись ошибки шага; `createRun` уходит.

**`nanoflow_reader`** — остаётся.

- Остаётся: `tail.dart` целиком, обход каталогов, пропуск точечных имён,
  `LogCorrupted`, живое чтение лога шага.
- Переделывается: журнал — один на сессию, а не на прогон; сессия закончена
  по её последнему событию; имя файла лога.

**`nanoflow`** — библиотека, переписывается целиком.

- Уходит: DSL графа (`vertex`, `graph`, `build`, `naming`), типы через mirrors
  (`dart_types`), протокол `--graph`/`--input`/`--call` (`serve`, `call`,
  `watch`).
- Новое: `Flow` (`run`, `resume`, `step`, `addCodec`) с зоной меток и ключей
  из [`prototypes/step_keys`](../../../prototypes/step_keys); запись сессии
  через `nanoflow_store`; `print` внутри шага — в лог шага через зону (зона
  из `serve.dart` уже уводила `print` в лог); перехват необработанных ошибок
  шага (`runZonedGuarded` из `call.dart`); отпечаток кода под `dart run` и
  хэш своего файла в собранном приложении (решение 8).
- `exec` остаётся — им шаг запускает внешние программы: группа процессов,
  обёртка на perl с SIGPIPE по умолчанию, остановка группы по TERM/INT/HUP.
  Переделывается: stderr программы — в лог своего шага, а не в общий
  `stderr` процесса; остановка — программ своего шага, а не всех в изоляте.

**`nanoflow_describe`** — новый пакет: извлекатель из
[`prototypes/static_graph`](../../../prototypes/static_graph) и команды
`describe` (`--watch`) и `stamp`. Подключается как `dev_dependency`, чтобы
`package:analyzer` не попадал в зависимости приложения; запуск —
`dart run nanoflow_describe --watch`. Выбор файлов для отпечатка — по
правилу `watch.dart` (`.dart` пакета, без `build/` и точечных каталогов).

### Программы

**`apps/nanoflow_cli` — уходит целиком:** `run`, `--resume`, `check`, запуск
программы графа, шаг-подпроцесс, перенос данных между шагами, маршрут по
`then`/`else`, разветвления прогонов, восстановление разветвлений, чтение
входа с fd 0. В библиотеку переносятся приёмы, а не код: флаг остановки и
`guard()`, превращающий сбой файловой системы в сбой хранилища; ничего не
писать после остановки; порядок «документ выхода → `step-finished` →
`step.json`»; остановка с тайм-аутом по SIGINT/SIGTERM.

**`apps/nanoflow_ui`** — остаётся.

- Уходит: `state/graph_source.dart` (запуск `nanoflow-yaml` и `check`),
  панель «nanoflow check нашёл», значок «живого» графа, поиск `PATH` для
  программ графа в `platform/shell.dart` (Finder и редактор остаются), выбор
  `.yaml` на стартовом экране, колонка входа в окне шага, строки
  «унаследовано» и «прогон разделился» в логах.
- Новое: чтение файла графа и слежение за ним; подсветка «может не
  соответствовать коду» и «не проверено» по хэшам (решение 8);
  предупреждения извлекателя вместо ошибок `check`; рамки функций с
  проваливанием и раскрытием (решение 6); рамки копий и переключатель копий
  (решения 10, 11).
- Переделывается: разметка шагов прогона на графе (`graph_marks` — по месту
  вызова шага, а не по `then`/`route` и коду завершения), детали визита и шага
  (ошибка вместо кода завершения, место в коде вместо команды),
  переключатель прогонов → переключатель копий, `runs.dart` и `log_rows.dart`
  без разветвлений и наследования, `session_feed` и `graph_model` — на новый
  граф.
- Остаётся: виджеты холста, панель логов, просмотр данных, выбор, лента
  сессий, `widgets/*`, `theme`, недавние графы.
- **Раскладка** (`layout/`, чистый Dart): алгоритм остаётся (слои, порядок,
  порты, координаты, полосы, маршруты, проверки); связь с графом узкая
  (`LayoutGraph.of`, `GNode`, `GExit`), меняется на новый граф. Новое — рамки
  функций и копий: вложенная раскладка, рамка как узел уровня выше.
