# Эффекты вместо шагов и пройденные развилки

> **2026-10-29:** воркфлоу — только графы из узлов
> ([решение](2026-10-29-nodes-only-design.md)); эффект — узел, развилки по
> журналу — развилки переходов.

Дополняет [дизайн code-first](2026-10-03-code-first-design.md) и меняет его
там, где сказано. Решения приняты в разговоре 2026-10-04.

## 1. Зачем

Развилки на графе сессии серые, даже когда процесс через них прошёл: журнал
хранит только шаги, у `if`/`while`/`switch` следа нет. Под правилом «всё,
что касается мира снаружи, — в эффекте» путь по коду между двумя эффектами
определён входом и записанными выходами эффектов, поэтому пройденные
развилки и их выходы выводятся из `after` — без вычисления условий и без
знания языка.

Шаг переименовывается в эффект: имя говорит, что внутри — побочный эффект.

## 2. Правило

> **Любой побочный эффект, кроме логов, — внутри `effect`.**

- Побочный эффект — всё, чем код касается мира за пределами функции: читает
  время, случайные числа, окружение, файлы, сеть; пишет файлы, ходит в
  сеть, запускает программы.
- Логи (`print`, логгер) — где угодно: на путь не влияют, при продолжении
  сессии просто печатаются ещё раз.
- Следствие: код между эффектами при тех же входе и выходах эффектов идёт
  тем же путём. Продолжение на том же коде идёт тем же путём; развилки
  выводятся из журнала (§5).
- Правило — соглашение; `describe` предупреждает об очевидных нарушениях
  (§3). Рантайм ничего не запрещает.

Спека code-first, §4.2: «Всё остальное свободно (решение 3)» заменяется
этим правилом.

## 3. Предупреждения `describe`

- **Где ищет.** В телах функций графа (воркфлоу и функции с эффектами) и во
  всём, что они вызывают из исходников своего пакета (функции, методы,
  конструкторы, геттеры, замыкания, вызванные на месте, локальные функции) —
  транзитивно, каждую функцию один раз. Тело замыкания, переданного в
  `Flow.effect`, — сам эффект, его не проверяют, как и то, что вызывается
  только из таких тел. Чужие пакеты и SDK не обходят.
- **Что считается нарушением** (по разрешённому элементу, не по тексту):
  - `DateTime.now`, `DateTime.timestamp`, конструктор `Stopwatch`;
  - конструкторы `Random` из `dart:math` (`Random()`, `Random(seed)`,
    `Random.secure()`) — сид делает ряд воспроизводимым, но `Random(seed)`
    ничем не отличить от `Random()` по смыслу правила, проще — эффект;
  - любой элемент библиотеки `dart:io` (класс, конструктор, функция,
    геттер верхнего уровня, статический член), кроме `stdout`, `stderr` и
    членов `Stdout`/`IOSink`, вызванных на них, констант (геттеры и поля
    `const`, значения перечислений: `HttpStatus.ok`, `FileMode.append`) и
    конструкторов и членов экземпляра исключений (классов, среди супертипов
    которых `Exception` или `Error` из `dart:core`: `HttpException(…)`,
    `e.message`) — они мира не касаются.
- **Не нарушение:** `print`, `stdout`/`stderr`, таймеры и `Future.delayed`
  (ожидание данных снаружи не приносит), всё из чужих пакетов.
- **Текст и место.** В теле функции графа — `side effect outside an effect:
  <исходник выражения>` на месте выражения. Внутри вызываемой функции пакета
  — на месте вызова в функции графа: `side effect outside an effect:
  <исходник вызова> reaches <исходник выражения> at <путь:строка>` (первое
  нарушение, до которого вызов дотягивается, по порядку обхода). Каждое
  предупреждение — один раз (по месту и тексту), в общий список `warnings`
  файла графа.

## 4. Переименование: шаг → эффект

Везде, где понятие — «шаг»: `step` → `effect`, `steps` → `effects`, в том
числе в составных именах.

| Где | Было | Станет |
| --- | --- | --- |
| API | `f.step(name, body)` | `f.effect(name, body)` |
| Модель | `Step`, `StepState`, `StepStatus`, … | `Effect`, `EffectState`, `EffectStatus`, … |
| Журнал | `step-started`, `step-finished`, `step-failed`, поле `stepId` | `effect-started`, `effect-finished`, `effect-failed`, `effectId` |
| Файлы | `steps/<время>-<имя>-<id>/step.json`, `step.log` | `effects/<время>-<имя>-<id>/effect.json`, `effect.log` |
| Лента | `step-added`, `step-changed` (поле `step`) | `effect-added`, `effect-changed` (поле `effect`) |
| Читатель | `stepLog`, `stepPath`, … | `effectLog`, `effectPath`, … |
| Файл графа | узел `"kind": "step"`, `StepNode`; `"format": 1` | `"kind": "effect"`, `EffectNode`; `"format": 2` |
| Библиотека | `StepLog`, `KeyedStep`, … | `EffectLog`, `KeyedEffect`, … |
| `describe` | тексты предупреждений о шагах | об эффектах |
| UI | классы (`StepList`, `StepPlaces`, `ShownSteps`, …) и тексты («Step», «2 steps», «Open step in details view», …) | `EffectList`, `EffectPlaces`, `ShownEffects`, …; «Effect», «2 effects», «Open effect in details view», … |
| Документы | спека code-first, README, `docs/ui-spec.md`, `docs/graph-layout.md`, README пакетов, примера и e2e: «шаг» | «эффект» |

- Ключ эффекта (`upload#1@…`) не меняется: типа в нём нет.
- `format` файла графа — 2: UI, встретив файл другого формата, говорит, что
  файл не читается, как с любым неверным файлом; `describe` пишет 2.
- Старые сессии в `runs/` и старые файлы графа не читаются — релиза не было,
  миграции нет. Сессии примера (`examples/review/runs/`, не в git)
  удаляются; файлы графа примера и фикстур переписывает `describe`.
- Не меняются: история (`docs/superpowers/` кроме спеки code-first, которую
  правят по этому документу), `prototypes/`, макеты `docs/design/`.
- Узел `call` / `copies` и прочие имена без «step» — как были.

## 5. Пройденные развилки

### 5.1. Переходы

Уровень — тело, которое нарисовано (функция графа, тело копий, рамка на
месте). Позиция эффекта на уровне — узлы уровня, на которых или в которых
он (как сейчас для отметок: узел эффекта по месту и имени, `call` — по
функциям, `copies` — по телу), или «вне уровня». Правила целиком — в
документации библиотеки `passes.dart` (§5.4); здесь и в спеке code-first,
§9, они пересказаны.

**Предшественник.** `after` эффекта — ключ последнего эффекта, результат
которого принял контекст, где эффект вызван (спека code-first, §4.3). После
`await` вызова функции, замыкания, вызванного на месте, или `Future.wait`
контекст идёт дальше с прежним `after` — если ожидаемое не отдало ему ровно
результат эффекта, как `return f.effect(…)`: эффект после них идёт после
эффекта до них, как и их первые эффекты. Эффекты сессии — дерево: каждый под
тем, за которым идёт. Эффект не на графе (без места или без узла)
пропускается: предшественник P эффекта E — эффект на графе, к которому
ведёт цепочка `after` от E (или никакого).

**Концы перед эффектом.** Код перед эффектом E кончился на эффектах под P
(без P — под тем же, под чем E), за которыми не идёт ни один эффект на
графе, кончившихся (`effect-finished` или `effect-failed`) не позже первого
`effect-started` E и ведущих к нему по уровню или стоящих с ним в одном
`call`/`copies`: ожидание кончается после всего, что ждёт, вызов — после
всего, что выполнил, а эффекты рядом (и два вызова в одном `Future.wait`)
начинаются раньше, чем кончится любой из них. Они собраны перед E (сам E —
никогда). Конец, собранный перед эффектом, который начался раньше E и
кончился к его началу, пройден: код ушёл от него к тому эффекту, и перед E
он не собирается — `await Future.wait([a(), b()]); if (c) await
Future.wait([x(), y()]); await z();` собирает a и b перед x и y, а перед z —
x и y, не a и b.

Для каждого показанного эффекта E на графе (вся сессия, копия или все
копии — как сейчас для логов и отметок) переход на уровне:

| Когда | Переход на уровне |
| --- | --- |
| есть концы перед E, E на уровне | узлы концов → узлы E; конец в одном `call`/`copies` с E — внутренний, пропускается |
| иначе P нет или вне уровня, E на уровне | начало тела → узлы E |
| P и E на уровне | узлы P → узлы E; оба в одном `call`/`copies` — внутренний, пропускается |
| P на уровне, E вне уровня | узлы P → конец тела |
| P и E вне уровня | нет |

**Вызов за вызовом.** На теле функции, которую вызывают (не воркфлоу и не
копий: в них без рекурсии снова не входят), P и E на уровне, а пути P → E по
телу нет (§5.2) — код вышел из тела и вошёл в него снова, как при двух
вызовах функции подряд без эффекта между ними: переход — два, «узлы P →
конец тела» и «начало тела → узлы E» (отдельный проход, §5.2), и только если
путь есть у обоих, иначе переход ничего не отмечает.

**Конец сессии.** У законченной сессии (`session-finished`) каждый эффект
уровня, за которым не идёт ни один эффект на графе и которого не собрали
перед эффектом (или собрали только перед эффектами, начавшимися в его
миллисекунду, как концы рядом в одном ожидании), даёт ещё переход «его узлы
→ конец тела». Так кончается и
вызов, как копии: после `await call()` следующий эффект идёт после эффекта
до вызова, а последний эффект вызова собран перед ним — это не конец
сессии.

**Переходы, которые ничего не отмечают** — путь, которым код мог пойти
(§5.3):

- через эффект не на графе — от конца, за которым он идёт, или к эффекту,
  который идёт за ним: куда шёл код, не нарисовано;
- от `copies` к концу тела: концы копий не всегда отличишь от копий, что
  пошли дальше; и от конца, собранного только перед эффектами, начавшимися
  в его миллисекунду: он мог идти рядом с ними;
- к эффекту, все концы перед которым пройдены: их могли пройти эффекты рядом
  с ним — два вызова функции подряд оставляют тот же журнал, что
  `Future.wait([x(), helper()])`, когда первый эффект helper начался после
  конца x;
- к эффекту, все концы перед которым — в одном `call`/`copies` с ним:
  эффекты рядом там, кончившиеся в миллисекунду своего начала, собирают
  друг друга.

### 5.2. Путь перехода

Ищутся все простые пути (узел не повторяется) по рёбрам тела, включая
обратные, от узлов-источников к узлам-целям; начало и конец тела — рёбра с
`from`/`to` = `null`. Промежуточными бывают только развилки, `call` и
`copies` (вызов мог не выполнить эффектов, копии пройдены целиком), не узлы
эффектов: между концом перед E (или P) и E эффектов на графе нет — эффекты
вызовов, замыканий и ожиданий между ними собраны в концы (§5.1).

- Развилка, которая есть на **каждом** найденном пути, пройдена этим
  переходом; ребро, которое есть на каждом пути, — пройдено. На теле
  функции, которую вызывают, у перехода между двумя эффектами, которому есть
  и путь «из тела и снова в тело» (§5.3), — только то, что на каждом пути
  обоих: код мог выйти из функции между ними.
- Путей нет (код изменился, эффект не на графе) — переход ничего не
  отмечает, кроме разбиения §5.1.
- Путей больше 1000 — переход ничего не отмечает: тело, чьи развилки множат
  пути между двумя эффектами, до конца не перебирается. Выходы, которыми он
  мог пойти, не темнеют.
- Число проходов развилки — число запусков кода через неё; переходы одного
  запуска — один проход:
  - от одного предшественника;
  - от начала тела снова после одного предшественника (§5.1 «Вызов за
    вызовом»);
  - к эффектам после одного ожидания — от всех собранных им;
  - к концу тела — от эффектов, к которым код пришёл одним запуском: от
    общего предшественника, после одного ожидания.

  Переход от начала тела к эффекту, предшественника которого на уровне нет, —
  свой запуск у каждого эффекта: так в тело входят каждая копия и каждый
  вызов; но в тело воркфлоу код входит один раз, и такие переходы эффектов с
  одним `after` — один запуск. Число проходов — то, что различает журнал: при
  ожиданиях и вызовах (в циклах и без них) оно может расходиться с тем,
  сколько раз условие вычислялось на самом деле.

### 5.3. Как это видно

- **Развилка** с проходами — в облике пройденного эффекта (зелёная рамка,
  галочка); проходов больше одного — `2×` над ней, как над эффектом.
- **Стрелки.** У пройденной развилки тоном `untaken` (темнее) — выходы,
  которыми код не мог пойти: их нет ни на одном пути (узлы могут
  повторяться: через развилки, `call` и `copies`), которым он мог пройти:
  - пути всех переходов, и тех, что ничего не отмечают (§5.1);
  - на теле функции, которую вызывают, — «A → конец тела» и «начало тела →
    B» для каждого перехода A → B и каждой пары P → E (оба на уровне, не в
    одном `call`/`copies`), когда есть оба, даже если есть и путь A → B: код
    мог выйти из функции и войти в неё снова;
  - у сессии, которая идёт, упала или прервана, — от каждого кончившегося
    эффекта, за которым не идёт ни один эффект на графе и которого не
    собрали (кроме как перед эффектами, начавшимися в его миллисекунду),
    куда угодно: код мог уйти от него, прежде чем остановился (от
    идущего — ещё никуда); на теле функции, которую вызывают, — и от начала
    тела: мог начаться вызов. Темнее у такой сессии только то, куда код не
    мог пойти до сих пор;
  - соседние ветки `Future.wait` у выхода развилки (рёбра одного исхода
    развилки к разным узлам): код идёт по ним вместе.

  Остальные выходы — обычным тоном. Выход тела функции, которую вызывают,
  темнеет, только если ни на одном его узле эффекта нет больше одного
  показанного эффекта, иначе не темнеет ни один (развилки отмечаются и
  считаются, как прежде): функция могла идти больше раза, а ожидание не
  сдвигает `after`, и вызов, не берущий результата эффекта, оставляет все
  свои эффекты после последнего эффекта вызывающего — концы прежнего вызова
  могут читаться собранными перед эффектом следующего, и путь из тела,
  которым тот вызов ушёл, теряется. Это условие нужно, но его мало
  («Пределы» ниже). Прочие стрелки — как сейчас
  (у выбранной копии темнее стрелки к узлам, где она не была).
- **Все копии:** развилка отмечена, если её прошла хоть одна копия, без
  `2×`; тон стрелок не меняется (решение 11: путь не подсвечивается).
  Функция, открытая из тела копий, где показаны все, и вызов, раскрытый в нём
  на месте, — тоже все копии.
- **Одна копия:** только её переходы.
- **Current graph:** ничего.

**Пределы** — чего журнал не говорит и какие отметки от этого неверны:

- **Эффекты рядом читаются ожиданием** — ложные пройденные рёбра, ложные
  пройденные развилки и темнее выходы, которыми код прошёл. Эффект, кончившийся
  до начала другого под тем же — раньше или в ту же миллисекунду, как быстрые
  эффекты, — хотя код того его не ждал, и ведущий к нему по уровню, читается
  собранным перед ним: по циклу; в узел `call` функции, которую вызывают снова
  после ожидания; из узла `call` функции, нарисованной не раз, — эффект стоит на
  каждом. Так у настоящей библиотеки `await Future.wait([e0(), e1()]); if (mode
  == 'deep') { await quickSub(); if (mode.length > 3) await g(); } await
  Future.wait([quickSub(), e4()]);` (quickSub — один быстрый эффект, mode —
  `flat`) может показать `mode.length > 3` пройденной: quickSub ожидания,
  кончившийся в миллисекунду начала e4, читается вызовом из ветки deep,
  собранным перед e4. Быстрые эффекты рядом в цикле читаются собранными друг
  перед другом по нему, проходят друг друга и встают на место пути в цикл:
  `await (() async { await Future.wait([e0(), e1(), e2()]); })(); while (i < 1)
  { await Future.wait([e3(), e4()]); i++; } await e5();` может затемнить выход
  цикла к e5, которым код прошёл.
- **Эффекты рядом, кончившиеся в миллисекунду начала**, в одном `call` или
  `copies` — каждый читается собранным перед другим и, раз тот кончился,
  пройденным. Эффект после них, у которого других концов нет, находит все
  концы пройденными: ничего не отмечает, и путь, которым к нему пришёл код,
  может оказаться темнее — и у законченной сессии. Так у настоящей
  библиотеки `h66 { await e3(); await e4(); await Future.wait([e5(), e6()]);
  }`, вызванная в замыкании и ещё раз, а за ней `while (i < 1) { await e1();
  await e2(); i++; }`, может затемнить путь цикла к e1, когда e5 и e6
  кончаются в миллисекунду начала.
- **Концы прежнего вызова** — на теле функции, которая шла больше раза,
  концы прежнего вызова читаются собранными перед эффектом следующего:
  ложные пройденные рёбра; изредка ложная пройденная развилка — тот же код
  в функции helper, с медленным sub вместо quickSub, вызванной дважды с
  mode `flat`, показывает `mode.length > 3` пройденной; и темнее выходы,
  которыми ушёл прежний вызов, когда его ожидания или замыкания шли на
  разных узлах эффектов, по эффекту на узел (условие «Стрелок» выше его не
  ловит): два вызова, подряд или рядом, `if (c) await Future.wait([x(),
  y()]); else await Future.wait([u(), v()]); if (k) await z();`, первый с c
  и без z, второй без c и с z, темнят `k>`, которым ушёл первый; так же два
  вызова `await (() async { if (!first) { await e4(); await e5(); } else {
  await e6(); } })(); if (!first) await e7();`, сперва с first, потом без,
  темнят выход из тела, которым ушёл первый.
- **Счёт проходов** (§5.2) — меньше или больше того, сколько раз
  вычислялось условие. Эффект, все концы перед которым — в одном `call` или
  `copies` с ним, приходит путём, который ничего не отмечает, и его путь к
  концу — того запуска, которым он пришёл, а не ожидания: это тоже сдвигает
  счёт в обе стороны.
- **Больше 1000 путей** (§5.2) — переход ничего не отмечает.

### 5.4. Где живёт

Чистый модуль `apps/nanoflow_ui/lib/state/passes.dart`: по уровню, местам
эффектов, сессии и показанным эффектам — проходы развилок и пройденные
рёбра. `GraphMarks` даёт развилкам отметки (`NodeMarks`), `CanvasMarks` —
тон стрелок. Спека code-first, §9, получает пункт «Развилки» по §5.

## 6. Тесты

- **`describe`:** образцы с каждым видом нарушения в воркфлоу; нарушение в
  функции пакета, вызванной из воркфлоу (предупреждение на месте вызова);
  нарушение внутри замыкания `effect` и в функции, вызванной только оттуда
  (нет предупреждения); `print`, `stdout.writeln`, `Future.delayed` (нет).
- **Переименование:** все наборы тестов зелёные под новыми именами; файл
  графа примера переписан и проходит `--check`; e2e читает запись
  библиотеки под новыми именами; поиск по коду и документам (кроме
  истории) не находит «step» в значении «шаг».
- **Проходы (`passes.dart`):** `if`/`else` — пройденный выход; цикл
  примера `review` (`inspect → fix → inspect → publish`) — развилка цикла
  `2×`, оба её выхода пройдены; `switch`; две развилки, сходящиеся до
  следующего эффекта, — общие развилки отмечены, разошедшиеся выходы нет;
  вход в функцию и выход из неё на уровне функции; конец законченной
  сессии; у идущей и упавшей — без перехода к концу; `call` без эффектов
  по дороге; копии — у каждой свой путь, все копии — объединение; путь не
  найден — ничего. Журналы — с `after`, как их пишет библиотека (после
  вызова и ожидания — эффект до них).
- **Проходы на случайных программах:** функции из эффектов, развилок,
  циклов, вызовов, замыканий на месте, `Future.wait` эффектов и вызовов,
  `return` и эффектов не на графе нарисованы, как рисует `describe`, и
  выполнены, как выполняет библиотека (журнал с её `after`); у законченной
  сессии и оборванной в случайный миг всякая отмеченная развилка и всякое
  пройденное ребро — на пути кода, и ни один выход, которым код прошёл, не
  темнее. Четверть эффектов кончается в миллисекунду начала, как быстрые
  эффекты библиотеки. Число проходов не проверяется; не проверяются и
  сессии, которые по самому прогону попадают в предел §5.3: эффекты рядом,
  читаемые ожиданием; концы прежнего вызова; эффекты рядом, кончившиеся в
  миллисекунду начала и проходящие друг друга. Доля каждых ограничена
  сверху; вне их на всех испробованных сидах ничего не отмечено неверно, но
  это не доказательство, что других пределов нет.
- **На записи библиотеки, вызов:** вызов функции с двумя эффектами подряд и
  замыкание на месте с ними же, потом развилка с выходом к концу тела
  (`record_calls`): эффект после них — после эффекта до них, развилка
  пройдена раз.
- **На записи библиотеки:** сессия примера `review`, записанная настоящей
  библиотекой (как `record_copies`), — развилки и стрелки отмечены как в
  тесте выше.
- **UI:** виджет-тесты отметок развилок и тона стрелок; золотая картинка
  законченной сессии `review` — посмотреть глазами.
