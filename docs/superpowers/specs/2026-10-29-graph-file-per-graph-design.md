# Файл на граф

Решено 2026-10-29. Вместо одного `nanoflow.graph.json` на пакет у каждого
графа свой файл графа рядом с Dart-файлом, где он объявлен. Подграф — не
копия, а путь к его файлу. Отменяет «один файл на пакет»
([code-first](2026-10-03-code-first-design.md), §3, §4.7, §6, §7) и
закрывает «файл на граф» из [только графов](2026-10-29-nodes-only-design.md)
(«Не цели»).

## 1. Что решено в разговоре

- У каждого графа свой файл; подграф — путь к его файлу, без копий.
- Отдельного поля зависимостей нет: их видно по узлам `call`.
- Файлы пишет describe; ручной миграции нет: describe перезапускают.
- В снимок сессии идут граф и все его подграфы; старые снимки одним
  файлом читаются как раньше.
- Файл лежит рядом с Dart-файлом, где граф объявлен; имя — имя графа:
  `lib/src/generate/generateIdeas.graph.json`.
- UI открывает отдельный файл.
- `sources` графа — его Dart-файл и всё, что тот импортирует внутри пакета,
  по цепочке: правка в `develop_graph.dart` не делает устаревшим
  `generateIdeas`.
- «Файлы одной версии» — каждый файл совпадает с кодом по своим `sources`;
  отдельной проверки нет. Родитель импортирует файл подграфа, так что
  `sources` подграфа — часть `sources` родителя: подграф, переписанный
  после родителя, делает родителя устаревшим.
- describe — один запуск на пакет, один анализатор; каждый файл — из
  своего графа и его `sources`: свои предупреждения, свои ошибки
  компиляции.

## 2. Файл графа (формат 4)

`<каталог Dart-файла>/<имя графа>.graph.json`; символы, которых не бывает в
имени файла (`/ \ : * ? " < > |` и управляющие), — `_`.

```json
{
  "format": 4,
  "package": "ideas_flow",
  "name": "generateIdeas",
  "place": "lib/src/generate/generate_graph.dart:24",
  "doc": "Thinks up ideas for a project.",
  "body": {
    "nodes": [
      { "id": "1", "kind": "effect", "name": "survey", "place": "lib/src/generate/generate_graph.dart:26", "doc": null },
      { "id": "2", "kind": "call", "graph": "lib/src/compress/compressIdea.graph.json", "place": "lib/src/generate/generate_graph.dart:27" }
    ],
    "edges": [ { "from": null, "to": "1", "label": null } ]
  },
  "warnings": [ { "place": "lib/src/generate/generate_graph.dart:40", "message": "…" } ],
  "fingerprint": "sha256:…",
  "sources": { "lib/src/compress/compress_graph.dart": "sha256:…", "lib/src/generate/generate_graph.dart": "sha256:…" },
  "builds": {}
}
```

- `name`, `place`, `doc`, `body` — как у записи `functions` формата 3; узел
  `call` — `graph`: путь к файлу подграфа от корня пакета, как `place` и
  `sources`.
- `warnings` — без `function`: файл и есть граф. В файл идут предупреждения
  в объявлении графа (`Graph(…)`) и те, что ни в чьём объявлении, но в
  файлах его `sources`. Предупреждения подграфа — в его файле.
- `sources` — Dart-файл графа, файлы его библиотеки (`part`) и всё, что они
  импортируют и экспортируют из исходников пакета, по цепочке;
  `fingerprint` — их отпечаток (code-first, §6.2).
- `builds` — как раньше, у каждого файла.
- `workflows` нет: describe больше не ищет `Flow.start`; файл открывают —
  показывается его граф.

## 3. describe

- Один запуск читает пакет анализатором и пишет файл каждого графа.
  Файл графа, в чьих `sources` есть ошибка компиляции, не пишется — остаётся
  прежний; остальные пишутся; ошибки — в stderr, код 1.
- Файлы `*.graph.json` под `lib/` и `bin/`, которых describe не пишет (граф
  удалили или переименовали), и прежний `nanoflow.graph.json` в корне
  удаляются — только когда пакет компилируется целиком: граф, не
  прочитанный из-за ошибки, не теряет файл. Строка `removed <файл>`.
- `--check` — код 1, если какой-то файл не тот, что был бы записан
  (`builds` не сравниваются), какого-то нет, есть лишний или прежний
  `nanoflow.graph.json`.
- `stamp <бинарник>` — все файлы должны совпадать с исходниками, иначе
  код 1 и ничего не пишется; `builds[<имя>]` дописывается в каждый, и копия
  каждого кладётся рядом с бинарником по тому же пути:
  `build/lib/src/generate/generateIdeas.graph.json`.
- `--watch` — как раньше, переписывает изменившиеся файлы.

## 4. Библиотека

- **Файл графа** — `<каталог проекта>/…/<имя графа>.graph.json` под `lib/`
  или `bin/` (каталоги на `.` и `build` пропускаются), первый по пути.
- **Снимок** — граф и все подграфы, по узлам `call`, собранные в одно целое
  в форме формата 3: `functions` по пути файла, `workflows` — путь файла
  графа, `fingerprint`, `sources`, `builds` — его файла, `warnings` — всех
  файлов. Подграф без файла не попадает. Снимки старых сессий и новые
  читаются одним кодом. Нет файла графа — `graph: null`.
- **Хэш кода** без сборки — отпечаток `sources` файла графа, как они сейчас;
  без файла — отпечаток всего пакета, как раньше. Правка вне `sources` графа
  — не «продолжена на изменённом коде». В сборке — хэш бинарника, как раньше.

## 5. UI

- Открывает `*.graph.json` формата 4 — и по-прежнему `nanoflow.graph.json`
  формата 3. Вместе с файлом читает файлы подграфов по узлам `call`
  и собирает их, как библиотека снимок; перечитывает при изменении любого.
  Подграф, чей файл не прочесть, рисуется вызовом без тела.
- **Каталог проекта** файла (рядом — `runs/`, от него — места в коде и
  свежесть): каталог над ближайшим `lib/` или `bin/` выше файла, у которого
  есть `pubspec.yaml`; нет такого — над ближайшим; нет `lib/` и `bin/` —
  каталог файла.
- Сессии — графа файла по его имени. Заметки «сессии воркфлоу, которых нет в
  файле» у файла одного графа нет: в `runs/` лежат сессии и других графов.
- Название на стартовом экране — имя графа (`generateIdeas`); у
  `nanoflow.graph.json` — каталог проекта, как раньше.

## 6. Миграция

- `examples/review`, ideaforge (`packages/ideas_flow`), scheduleme
  (`nanoflow-task-graph/workflow`): describe перезапускается, прежний
  `nanoflow.graph.json` удаляется им же.

## 7. Мои решения

- Ссылка на подграф — путь от корня пакета, а не от файла: так же пишутся
  `place` и `sources`.
- Снимок в сессии остаётся формы формата 3: UI и библиотека читают старые и
  новые снимки одним кодом, id функции в новом — путь файла.
- Библиотека находит файл по имени графа поиском под `lib/` и `bin/`, а не
  по месту объявления: `Graph` не знает своего файла.
- Хэш кода сессии — по `sources` её графа, иначе снимок нового графа всегда
  говорил бы «шла на другом коде».
- Удалять лишние файлы — только при целиком компилирующемся пакете.
- Открытый файл подграфа показывает только сессии, где граф шёл сам; сессии
  родителей, как у «открыть как граф», не ищутся.
