# Только графы из узлов

Решено 2026-10-29. Отменяет «два равных способа» ([граф из узлов](2026-10-25-graph-node-objects-design.md),
анти-цель «способ кодом ломается»): воркфлоу пишется одним способом — графом
из узлов. Способ «кодом» — async-функция `(Flow f, I input)` с `f.effect(…)`
([code-first](2026-10-03-code-first-design.md)) — больше не поддерживается:
написанные так воркфлоу переписываются графами, код, который их рисует и
показывает, удаляется.

## 1. Зачем

- Один основной путь создать граф. Второй способ стоит денег в каждом
  решении: в файле графа, в UI, в документации — последним поводом был
  вопрос, получают ли функции-воркфлоу свои файлы при «файле на граф».
- Всё, что умеет только функция, — `Future.wait` копиями, циклы, `try`,
  вызовы функций с эффектами — держит в describe и UI тысячи строк, которыми
  графы не пользуются.

**Цели.**

- Запустить можно только граф: `flow.start(graph, input)`, `flow.run`,
  `flow.resume`, `flow.unfinished` берут `Graph`.
- describe рисует только графы; UI показывает только то, что дают графы.
- Все воркфлоу-функции в проектах пользователя переписаны графами.

**Не цели.**

- Менять движок: ключи эффектов, журнал, продолжение после падения, `exec`.
  Граф исполняется на нём — узел есть эффект, граф есть функция воркфлоу
  для движка; это остаётся внутри библиотеки.
- «Файл на граф» — отдельный проект после этого.
- Читать в UI старые сессии воркфлоу-функций особым образом.

**Анти-цели.**

- Публичный способ написать воркфлоу функцией, пусть и «нерисуемый».
- Сломать графы: ни ключи, ни журнал, ни рисунок графов не меняются.

## 2. Библиотека `nanoflow`

- `Flow.start<I, R>(Graph<I, R> graph, I input, {String? id})`,
  `Flow.run(graph, input)`, `Flow.resume(graph, sessionId)`,
  `Flow.unfinished(graph)`. Имя сессии — имя графа, как сейчас.
- `Flow.effect` и `Graph.run` не публичны. Движок запускает функцию
  воркфлоу внутри (`src/`): граф — его `run`. Тесты движка (ключи, журнал,
  продолжение) остаются на функциях и берут их из `src/` — это проверки
  движка, а не способ писать воркфлоу.
- `nanoflow.dart` экспортирует `Flow`, `FlowSession`, `Graph`, `Part`,
  `Node`, `Next`, `node`, `exec` и исключения.

## 3. Файл графа и describe

- `functions` — только графы; `workflows` — графы, переданные в
  `start`/`run`/`resume`/`unfinished`. Узел `call` — граф, служащий узлом.
- Вида узла `copies` нет: его давал только `Future.wait` в функции.
  `CopiesNode` удаляется из модели. Формат остаётся 3: файл без копий тот
  же; файл или снимок с `copies` больше не читается (UI: файл или снимок не
  читается, как любой неверный).
- describe больше не разбирает тела функций: эффекты, циклы, `try`,
  `Future.wait`, вызовы функций с эффектами, протягивание `switch`,
  функции вне исходников. Остаётся то, чем читаются переходы: точки тела,
  развилки, `switch` и его подписи, схождение, отрисовка.
- Предупреждения функций уходят (имя эффекта — не литерал, эффекты в
  замыкании и в локальной функции, эффекты вне исходников, `catch`).
  Побочные эффекты вне эффекта проверяются только в переходах.

## 4. UI

- Уходят рамки копий: `copies`-узлы, переключатель копий, выбор копии,
  копии в журнале и в логах.
- Остаётся всё, что нужно графам: развилки по журналу, вызовы графов,
  прогоны вызова, открытие вызова как графа.
- Тестовые записи сессий, снятые с функций (`calls`, `review`), остаются
  как данные журнала — UI читает их, как любую сессию; запись `copies` и её
  тесты удаляются. Инструменты, которые их снимали функциями, удаляются.

## 5. Миграция

- `examples/review`: функция `review` удаляется, пример — граф
  `reviewGraph`; e2e-тесты примера — на графе.
- ideaforge: вызовы `flow.start(developIdea.run, …)` и подобные —
  `flow.start(developIdea, …)`; файл графа перегенерируется.
- scheduleme, ветка `test`: воркфлоу `chain` и `task` — функции; ветка
  `nanoflow-task-graph`, выросшая из её вершины, переписала их графами.
  Ветка `test` перематывается на неё, вызовы — на новый API, файл графа —
  заново.

## 6. Документация

README и README пакетов описывают только графы. Спеки — история решений:
в начале code-first и спек, держащихся на функциях, — заметка, что способ
снят этим решением.

## 7. Мои решения

- Движок оставлен как есть, функции воркфлоу в нём — внутренние; тесты
  движка не переписываются на графы.
- Формат 3 не поднимается.
- Записи сессий `calls` и `review` в тестах UI остаются данными.
- `test` в scheduleme перематывается на `nanoflow-task-graph`.
