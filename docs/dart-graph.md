# Граф на Dart

Как граф описывается кодом на Dart. Формат графа, протокол команды и
хранение — в [README](../README.md).

**Статус — реализовано:** библиотека
[`nanoflow`](../packages/nanoflow/README.md), пример —
[`examples/review`](../examples/review/README.md).

## Пример

Граф из README:

```dart
import 'package:nanoflow/nanoflow.dart';

final collect = node((Request r) async => …);
final isEmpty = fork((Change c) async => c.path.isEmpty);
final inspect = node((Change c) async => …);
final verdict = fork((Report r) async => r.findings.isEmpty ? 'accepted' : 'returned');
final fix = node((Report r) async => …);
final publish = node((Report r) async { … });
final notify = node((Report r) async { … });
final discard = node((Change c) async { … });

final graph = Graph([
  Graph.start(collect).next(isEmpty).then(discard).otherwise(inspect),
  Graph.part(inspect).next(verdict).then({
    'accepted': {publish, notify},
    'returned': fix,
  }),
  Graph.part(fix).next(inspect),
]);

void main(List<String> args) => serve(args, graph,
    input: (raw) => Request.fromJson(jsonDecode(raw)));
```

## Узлы

- **Рабочий узел — `node(функция)`, развилка — `fork(функция)`.** Функция —
  работа узла; при объявлении она не вызывается.
- **Типы — из сигнатуры функции.** Тип параметра — `in`, тип результата —
  `out`. Узел без `in` объявляется с параметром `Object?` и подходит после
  любого узла.
- **Имя узла — имя переменной верхнего уровня.** Строкой оно нигде не
  пишется.
- **Методов у узла нет:** стрелки описывает граф. Один узел — одна вершина,
  где бы он ни упоминался.
- **Узел — всегда функция, команд нет.** Работу можно написать и классом:
  метод — тоже функция, `node(Inspect(model: 'opus').run)`.
- **В описании графа** на месте команды узла — место его объявления:
  `graph.dart:12`. Его и показывает UI под плиткой.

### Внешние программы

Программу — `claude -p`, `jq`, `git` — функция запускает сама, через
`exec` из библиотеки:

```dart
final inspect = node((Change c) async {
  final out = await exec('claude', ['-p', prompt(c)]);
  return Report.fromJson(jsonDecode(out));
});
```

- **`exec` возвращает stdout программы,** stderr пишет в лог шага и
  останавливает программу вместе с шагом.
- **Выход программы проверяет функция** — так, как сочтёт нужным: здесь
  `Report.fromJson`.
- **Спросить в терминале программа не может.** Её группа процессов в
  терминале `nanoflow run` — фоновая, поэтому программа, которая
  спрашивает там пароль или ключ хоста, — `git`, `ssh`, `sudo`, —
  останавливается: вопрос в терминале виден, но ответ до неё не доходит, и
  шаг стоит до Ctrl+C. Такие программы запускают так, чтобы они не
  спрашивали, — тогда они сразу завершаются с ошибкой и пишут причину в лог
  шага. Окружения у `exec` нет, переменную задаёт `env`:

  ```dart
  await exec('env', ['GIT_TERMINAL_PROMPT=0', 'git', 'push']);
  await exec('ssh', ['-o', 'BatchMode=yes', host, 'uptime']);
  await exec('sudo', ['-n', 'true']);
  ```

  stdin тут ни при чём: спрашивают они не через него, а через терминал.
- **SIGPIPE — как из shell:** писатель, чей читатель вышел, завершается, но
  лишь при следующей записи. В `tail -f server.log | grep -m1 listening`
  grep выходит на первой найденной строке, а `tail -f` — когда в лог допишут
  ещё одну; если после найденной строки лог молчит, конвейер не кончится,
  как и в shell. Строки о готовности ждут без `tail -f`:
  `until grep -q listening server.log; do sleep 0.2; done`. Dart игнорирует
  SIGPIPE, и программы, которые он запускает, наследуют это; shell этого не
  отменит, а perl может, поэтому `exec` запускает программу через
  `/usr/bin/perl` — он есть в macOS и в Debian и Ubuntu (`perl-base`). Без
  него программа стартует с игнорируемым SIGPIPE: писатель вместо сигнала
  получает ошибку записи, и тот, кто на ней не останавливается, —
  `tail -f` в macOS, цикл shell, — не кончается никогда. Тогда ожидание
  кончают сами, например `echo … || break` в цикле.
- **`exec` — в изоляте шага.** Программу, которую `exec` запустил в
  другом изоляте (`Isolate.run`, `Isolate.spawn`), шаг не останавливает:
  она его переживает. Программы запускает сама функция узла.

### Данные

- **Между узлами данные проверяют типы Dart:** выход создан типизированным
  кодом, следующий шаг разбирает его тем же классом.
- **Вход запуска — функцией [`input`](#программа-графа),** до создания
  сессии.
- **Всё внешнее** — вывод программ, HTTP, файлы — проверяет сама функция.
- **stdout `--call` — канал данных,** пишет в него только библиотека, в
  конце шага. `print` внутри функции библиотека перехватывает и отправляет
  в лог шага; прямой `stdout.write` из функции ломает данные.
- **Перехватывается только `print` из вызова функции узла или `input`.**
  Обработчик, подписанный до `serve`, выполняется там, где подписан, даже
  когда его вызывает функция узла. Так работает слушатель `package:logging`,
  настроенный в `main`: его `print` уходит в stdout и ломает данные каждого
  шага. Поэтому такой слушатель должен писать в stderr — это и есть лог
  шага:

  ```dart
  Logger.root.onRecord.listen(
    (r) => stderr.writeln('${r.level.name}: ${r.message}'),
  );
  ```
- **`print` — в изоляте шага.** Код в другом изоляте (`Isolate.run`,
  `Isolate.spawn`) библиотека не перехватывает: его `print` уходит в
  stdout и ломает данные. Там пишут в `stderr`.

## Развилки

| Функция возвращает | Форма  | Куда при совпадении                                           |
| ------------------ | ------ | ------------------------------------------------------------- |
| `bool`             | if     | `.then(цель)` — при `true`                                    |
| другой тип         | switch | `.then({исход: цель, …})` — ключи того же типа, что результат |

- **`.otherwise(цель)` — иначе.** Необязателен: без него, как в README, if
  заканчивает прогон, а switch останавливает его ошибкой маршрута.
- **`.then` и `.otherwise` оставляют кусок на развилке,** поэтому пишутся
  подряд. После развилки цепочка не продолжается.

## Граф

- **Кусок — плоская цепочка стрелок.** `Graph.start(узел)` начинает кусок с
  узла, с которого стартуют прогоны; `Graph.part(узел)` — с любого другого.
  Стартовый узел может начинать несколько кусков — например, по куску на
  исход стартовой развилки, — с `Graph.start` или `Graph.part`, и остаётся
  одним стартовым узлом: стартовых узлов столько, сколько разных узлов в
  `Graph.start`.
- **`.next(цель)` у рабочего узла** — стрелка; кусок переходит к цели.
- **Цель — узел или множество узлов,** принимающих то, что передаёт узел.
  Множество — разветвление: `{publish, notify}`; множество из одного узла —
  сам этот узел. Кусок целью не бывает: продолжение ветки — отдельный кусок,
  петля — ссылка на узел.
- **`Graph([…])` собирает куски** в любом порядке. Граф из одного куска не
  оборачивается: `final graph = Graph.start(fetch).next(inspect).next(publish);`
- **Граф — значение, объявленное отдельно от `main`:** тесты импортируют
  граф. Что он собирается, тест проверяет через `graphErrors(graph)` — с
  теми же проверками, что у `--graph`: пустой список, если ошибок нет.
- **Работу узла тест вызывает через её функцию:** методов у узла нет.
  Работу, которую стоит проверить, объявляют именованной функцией —
  `final collect = node(collectChange);` — и тест вызывает `collectChange`.

## Программа графа

`main` отдаёт управление `serve`. Прогон ведёт движок, а `serve` отвечает на
его вызовы программы:

| Движок вызывает | `serve`                                                               |
| --------------- | --------------------------------------------------------------------- |
| `--graph`       | Печатает описание графа.                                              |
| `--input`       | Проверяет вход запуска функцией `input` и печатает её результат.      |
| `--call <узел>` | Выполняет шаг: разбирает вход, вызывает функцию узла, печатает выход. |

- **`input` — проверка входа запуска.** Получает stdin `nanoflow run` как
  есть и возвращает значение того типа, что принимает стартовый узел, —
  это проверяет компилятор. Как разбирать и насколько строго, решает
  пользователь.
- **Вызывается один раз — до создания сессии.** Упала — `run` печатает
  ошибку, сессии нет. Вернула значение — его `toJson()` движок сохраняет
  как вход запуска. На шагах, в петлях и при `--resume` не вызывается.
- **У стартового узла нет входа — `input` не нужна,** stdin не читается.
- **`--graph --watch` следит из самой программы,** поэтому на старте она
  должна компилироваться: ошибка компиляции при запуске — сообщение
  компилятора и ненулевой код. Правки после запуска — как в README: пока
  программа не компилируется, не печатается ничего.

## Проверки

**Компилятор** ловит типы и форму записи: цель не принимает данные, исход не
того типа (с `enum` — и опечатку в исходе), `.then` у рабочего узла или
`.next` у развилки, продолжение после развилки или множества, кусок как
цель.

**Сборка графа** — `--graph` и `nanoflow check`, до любого прогона:

- каждый выход объявлен один раз: `next` у узла, каждый исход и `otherwise`
  у развилки — в том числе между кусками;
- есть хотя бы один `Graph.start`;
- до каждого узла можно дойти по стрелкам от узла какого-нибудь
  `Graph.start`: кусок, к которому не ведёт ни одна стрелка, — ошибка
  `<узел>: unreachable from Graph.start`;
- имена узлов уникальны во всей программе.

Повтор исхода в одной карте Dart схлопывает раньше, чем граф его увидит;
его ловит анализатор, если поднять предупреждение до ошибки:

```yaml
analyzer:
  errors:
    equal_keys_in_map: error
```

Повтор цели во множестве не ошибка: множество его схлопывает, а если
остался один узел, в описании графа цель — этот узел, без списка.

## Как это устроено

Ограничения Dart, найденные прототипом.

- **Вход узла контравариантен.** Обобщённые классы Dart ковариантны:
  `Node<Special>` считается подходящим вместо `Node<Change>`, а узел без
  `in` — нет, хотя нужно наоборот. Поэтому тип входа хранится как функция,
  `Vertex<void Function(I)>`: параметры функций контравариантны.
  Модификатор `in` из эксперимента `variance` в стабильном Dart недоступен.
- **`node()` и `fork()` — функции, а не конструкторы:** у конструктора нет
  своих параметров типа, а без них `void Function(I)` из сигнатуры не
  получить.
- **Узел — коллекция из одного себя.** `Vertex` реализует `Iterable`,
  поэтому параметр `Iterable<AnyVertex<…>>` принимает и узел, и множество.
  Побочный эффект: у узла в автодополнении видны методы коллекции.
- **Общий предок узлов — `AnyVertex<F>`.** `Vertex` несёт ещё и свой вид —
  рабочий узел или развилка, — и множество из узлов обоих видов Dart вывел
  бы как множество `Object`, целью оно бы не подошло. У `AnyVertex<F>`
  только тип входа, поэтому `{publish, notify}` с рабочим узлом и развилкой
  — множество `AnyVertex` и цель.
- **if или switch выбирает Dart:** расширение на `Part<S, Fork<…, bool>>`
  конкретнее, чем на `Part<S, Fork<…, R>>`.
- **Список кусков — `List<Part<S, Object?>>`,** где `S` — тип входа
  стартовых узлов. С сырым `Part` в контексте Dart выводит тип куска из
  контекста, и методы развилки пропадают.

## Решения

1. **Имена узлов — через `dart:mirrors`.** Генерации кода нет: программа
   графа запускается `dart run`, в `exe` не собирается.
2. **Данные между узлами — классы с `fromJson` и `toJson()`.** `fromJson` —
   именованный конструктор или фабрика, получает разобранный JSON; библиотека
   находит его через `dart:mirrors`. Подходят и примитивы JSON (`String`,
   `int`, `double`, `num`, `bool`), `List<T>`, `Map<String, T>` и `enum` —
   по имени. Параметр `Object?` или `dynamic` — узел без `in`; результат
   `void`, `Null`, `Object?` или `dynamic` — без `out`. Так же и `Never`:
   его Dart выводит для функции, которая не возвращает, — например, всегда
   бросает. Данные не бывают `null`: тип данных с `?` — `Report?`,
   `List<String?>` — и `Object` без `?` сборка отклоняет.
3. **Типы Dart в описании графа.** Данные проверяет Dart, поэтому схема
   класса — только его имя:

   | Тип Dart         | Схема                                                   |
   | ---------------- | ------------------------------------------------------- |
   | `String`         | `{"type": "string"}`                                    |
   | `int`            | `{"type": "integer"}`                                   |
   | `double`, `num`  | `{"type": "number"}`                                    |
   | `bool`           | `{"type": "boolean"}`                                   |
   | `List<T>`        | `{"type": "array", "items": <схема T>}`                 |
   | `Map<String, T>` | `{"type": "object", "additionalProperties": <схема T>}` |
   | `enum E`         | `{"$ref": "#/E"}`, в `types.E` — `{"enum": [имена…]}`   |
   | класс `C`        | `{"$ref": "#/C"}`, в `types.C` — `{"title": "C"}`       |

   В `command` и `decide` — место объявления узла, `graph.dart:12`: путь от
   каталога программы графа. Ключи switch — `name` у `enum`, `toString()` у
   остальных; `--call` печатает исход этим ключом, у if — `true` или
   `false`.
