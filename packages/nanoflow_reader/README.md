# nanoflow_reader

Читатель для UI: следит за всеми сессиями одного графа в каталоге `runs` и
отдаёт [ленту изменений и данные по запросу](../../README.md#чтение).
Раскладка — как в [адаптере файловой системы](../../README.md#адаптер-файловой-системы).
Движок пишет те же файлы пакетом `nanoflow_store`; этот пакет его не
импортирует.

## Что внутри

- **`FsReader`** — каталог `runs` и имя графа. Сессии графа — каталоги, имя
  которых подходит под `isSessionDirOf`: сессии графа `review-x` графу
  `review` не принадлежат. Имена с точкой пропускаются везде: под ними
  хранилище собирает файлы и каталоги.
- **`changes()`** — лента: сначала всё, что уже есть, потом новое. Один
  подписчик; отписка останавливает слежение. Каталога `runs` может ещё не
  быть — лента начнётся, когда он появится. За один проход по дереву, для
  каждой сессии по порядку имён: `session-added`, затем для каждого прогона —
  `run-added`, новые шаги, новые полные строки журнала, затем новые
  документы.
  - Строка журнала без `\n` не выдаётся: место чтения стоит после последней
    полной строки, так что обрезанную при `--resume` строку читатель не
    заметит. Если журнал всё же стал короче прочитанного, чтение идёт с конца
    последней оставшейся полной строки, а не с начала файла.
  - Полная строка, которая не JSON-объект со строковыми `runId`, `time` и
    `event`, — `log-corrupted` с номером строки (с 1) и текстом; незнакомое
    событие — `event-added` с `UnknownEvent`.
  - `step-changed` — один раз, когда в `step.json` появляется `outputId`,
    который уже есть в `step-finished` этого шага.
  - Файл, который не читается как своя модель, приходит ошибкой в ленту один
    раз; сущность выдаётся, когда файл исправят, остальное идёт дальше.
- **По запросу:** `sessionGraph`, `documentValue` и `stepLog` — лог шага:
  накопленный текст, потом дописанный, UTF-8 на стыках кусков не рвётся;
  пока `command.log` нет, ничего не выдаётся. Сущности находятся и до того,
  как лента их выдала.
- **Пути** — `sessionPath`, `runPath`, `stepPath`, `logPath`,
  `documentPath`: известны, когда лента выдала сущность, до того — `null`.
- **Слежение** — события файловой системы (`Directory.watch`) и опрос раз в
  `pollInterval`: события бывают с задержкой и склеиваются. Проходы не
  накладываются: сигнал во время прохода — ещё один проход после него.
  Запись в `command.log` проход ленты не вызывает: лог идущей команды
  меняется постоянно, а ленте он не нужен — его читает `stepLog`.
