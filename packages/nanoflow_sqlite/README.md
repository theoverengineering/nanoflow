# nanoflow_sqlite

Адаптер хранилища на SQLite: сессии воркфлоу живут в базе приложения, рядом с
его таблицами. Реализует порт из `nanoflow_model` — запись (`SqliteStore`,
для `Flow(store: …)`) и чтение (`SqliteReader`, для UI и приложений).
Поведение — то же, что у файловых адаптеров: это проверяет `tests/contract`.
Зависит от `nanoflow_model`, `nanoflow_process` и `sqlite3`; от `nanoflow` и
файловых адаптеров — нет.

```dart
final flow = Flow(store: SqliteStore('/Users/me/.app/app.db'));
final reader = SqliteReader('/Users/me/.app/app.db');
```

## Таблицы

Схема — часть формата nanoflow, как раскладка `runs/`; приложение таблицы
`nanoflow_*` только читает — через `SqliteReader`.

| Таблица              | Столбцы                                                        |
| -------------------- | -------------------------------------------------------------- |
| `nanoflow_meta`      | `key`, `value` — `schema` = `1`                                |
| `nanoflow_sessions`  | `seq`, `id`, `workflow`, `created` (время создания), `json` — `session.json` |
| `nanoflow_events`    | `seq`, `session_id`, `json` — строка `log.jsonl`               |
| `nanoflow_effects`   | `seq`, `id`, `session_id`, `rev`, `json` — `effect.json`       |
| `nanoflow_documents` | `seq`, `id`, `session_id`, `json` — документ                   |
| `nanoflow_logs`      | `seq`, `effect_id`, `bytes` — лог эффекта кусками              |
| `nanoflow_owners`    | `session_id`, `json` — запись `.owner.lock`; нет строки — владельца нет |

- **JSON — текстом, тем же, что в файлах,** только без отступов.
- **Ничего не удаляется, кроме строки владельца.** `seq` — rowid: растёт в
  порядке коммитов, писатели SQLite идут по одному. `rev` эффекта —
  `max(rev) + 1` при каждой записи эффекта.
- **Таблицы создаёт запись** (`CREATE TABLE IF NOT EXISTS`), вместе с
  каталогом и файлом базы; читатель ничего не создаёт. Версия таблиц новее
  `schemaVersion` — `SchemaVersionException` и у записи, и у чтения.

## Запись

- **`SqliteStore(path, {processes, clock})`** открывает базу при первой
  записи: WAL, `busy_timeout` 5 с — базу пишут и читают несколько процессов
  сразу. `close()` закрывает её.
- **По транзакции на запись:** сессия создаётся одной — сессия, документ
  входа, `session-started`, владелец; дальше событие, документ, эффект — по
  одной, как файлы в `runs/`. События, данные разом, пишутся в порядке
  вызовов: запись синхронная.
- **Id** — заданный или новый; не id — `ArgumentError`, занятый —
  `SessionExistsException`, ничего не записано.
- **Владелец — строка `nanoflow_owners`, а не блокировка.** `openSession` в
  одной транзакции смотрит строку: нет её или ОС говорит, что процесса
  владельца нет (pid и время старта через `Processes`), — пишет нового
  владельца; процесс идёт или этого не узнать (нет времени старта, ОС без
  адаптера) — `SessionBusyException`. Сессию, которую держит этот изолят, —
  тоже `SessionBusyException`. `release` удаляет строку. Упавший процесс
  строку оставляет, её занимает следующий. Без `owner` строки нет: от других
  процессов сессию не закрывает ничто — `Flow` владельца передаёт всегда.
- **Сбой** — `SqliteException`; запись, которой нет (сессию удалили, пока
  процесс её вёл), — `RecordNotFoundException`; событие — не JSON-объект —
  `StoreCorruptedException` с `<база>#<id сессии>` и номером события.
- **Лог эффекта** (`SqliteEffectLog`) пишется в фоне: что добавлено, пока
  идёт запись, уходит после неё одной строкой; ошибку отдаёт `failed`.

## Чтение

- **`SqliteReader(path, {pollInterval, processes})`** — лента и данные по
  запросу, как у `FsReader`. Базы ещё нет или в ней нет таблиц nanoflow —
  ничего не выдаёт и ждёт.
- **Живые изменения:** уведомлений между процессами у SQLite нет. Раз в
  `pollInterval` (по умолчанию 250 мс) читатель спрашивает
  `PRAGMA data_version`, а изменилось — в одной читающей транзакции
  дочитывает то, что после прочитанного: новые сессии (новые первыми),
  эффекты по `rev` (`effect-added` или `effect-changed`), события по `seq`
  (строка — не JSON-объект со строковыми `time` и `event` — `log-corrupted`
  с номером события), документы, затем владельцев сессий, журнал которых не
  кончился (`owner-changed` через `Owners` из `nanoflow_process`). Выход
  процесса-владельца тоже будит чтение. Строка, которая не своя модель, —
  ошибка в ленту, один раз.
- **По запросу:** `documentValue`; `effectLog` — накопленное, потом
  дописанное, раз в `pollInterval`.
- **Путей нет:** `sessionPath`, `effectPath`, `logPath`, `documentPath` —
  `null`.
- **Читатель можно запускать в процессе-владельце:** блокировки, которую
  чтение сняло бы, нет.
