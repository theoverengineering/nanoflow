# nanoflow_describe

Извлекатель графа: читает код пакета анализатором Dart (`package:analyzer`),
ничего не выполняя, и строит файл графа `nanoflow.graph.json`, который рисует
UI ([формат](../../README.md#файл-графа)). Приложение подключает пакет как
`dev_dependency`, чтобы анализатор не попал в его зависимости.

## Команда

```bash
dart run nanoflow_describe            # пишет nanoflow.graph.json в корне пакета
dart run nanoflow_describe --watch    # и перезаписывает при каждой правке lib/ и bin/
dart run nanoflow_describe --check    # код 1, если файл не тот, что был бы записан
dart run nanoflow_describe stamp build/review   # builds + копия файла рядом с бинарником
```

- Корень пакета — текущий каталог или `--package <каталог>`; имя пакета —
  из его `pubspec.yaml`. Незнакомые аргументы и флаг на месте значения
  `--package` или `stamp` — справка в stderr, код 2.
- Файл пишется, только если байты изменились, и атомарно (временное имя с
  `.` и переименование); на каждую запись — строка `wrote <файл>`. Ошибки
  компиляции — в stderr, код 1, файл не трогается.
- `builds` файла остаются, пока исходники те же (отпечаток совпадает), и
  `--check` их не сравнивает: проштампованный файл свежий.
- `stamp <бинарник>` сверяет `fingerprint` файла с исходниками (не совпал —
  код 1, ничего не пишется), дописывает `builds[<имя бинарника>]` (по
  порядку имён) и пишет тот же файл рядом с бинарником.
- `--watch` пишет файл, затем перечитывает пакет после правок (пачка правок
  за 200 мс — одна; исходники, которые уже были описаны, не читаются
  заново). Где каталог нельзя наблюдать целиком (Linux), — смотрит на
  отпечаток исходников раз в 500 мс. Строка на каждую запись и
  `describe failed: <первая ошибка>` на каждую неудачу — и тогда, когда
  чтение пакета бросило что угодно (анализатор или извлекатель споткнулся
  о код): `--watch` идёт дальше и описывает пакет снова при следующей
  правке. Останавливается по SIGINT.
- `--watch` описывает пакет заново, только когда изменились исходники.
  Неудача, которую исправляют не в исходниках, — пакеты не поставлены, —
  так и остаётся: после `dart pub get` (или другой смены конфигурации
  пакетов) `--watch` перезапускают.
- `runDescribe(аргументы, {cwd, out, err, stop, poll, describe})` — то же
  из кода; `stop` заканчивает `--watch` вместо SIGINT, `poll` включает
  опрос, `describe` читает пакет вместо `describePackage` (для тестов).

## Что внутри

- **`describePackage(каталог, {packageName})`** — исходники пакета
  (`packageSourcePaths` из `nanoflow_model`: `.dart` под `lib/` и `bin/`) с
  разрешёнными типами. Ошибка компиляции хоть в одном — графа нет, в
  `errors` строки `путь:строка:колонка: сообщение`. Имя пакета —
  `packageName` или `name:` из `pubspec.yaml`. `fingerprint` и `sources` —
  те же функции модели, что у библиотеки; `builds` пуст; `functions` и
  `sources` — по ключу, так что файл одинаков байт в байт.
- **Функции с эффектами** — функции и методы исходников, где есть вызов
  `Flow.effect` (из `package:nanoflow`) или вызов функции с эффектами;
  рекурсия — просто вызов. В `functions` они и воркфлоу (функции, переданные
  первым аргументом в `Flow.start`/`run`/`resume`), по id `путь#имя` или
  `путь#Класс.имя`; граф функции описан один раз. У безымянного расширения
  имени нет: его методы — `путь#<extension>.имя`, методы второго
  безымянного расширения того же файла — `путь#<extension 2>.имя` и т. д.,
  по порядку в файле, так что одноимённые методы разных расширений не
  смешиваются.
- **Документация** (`docText`) — `doc` функции: её комментарий
  документации (`documentationComment` объявления); `doc` эффекта: строки
  `///` (или блок `/** */`) прямо перед вызовом `f.effect`, перед
  выражением, которое с него начинается, или перед простым оператором —
  выражением, объявлением переменной, `return`, `yield`, — если в нём это
  единственный эффект. Подъём к оператору не выходит из тела функции и из
  элемента `for`/`if` списка; комментарий перед `if`, циклом и другим
  составным оператором эффекту не достаётся. Ряд `///` прерывает обычный
  комментарий, пустые строки — нет. Текст — без `///` и пробела за ним
  (у блока — без `/**`, `*/` и `*` в начале строк), без пустых строк по
  краям; пустой — `null` ([спецификация](../../docs/superpowers/specs/2026-10-10-node-docs-design.md), §2).
- **Граф тела** — поток управления, сведённый к узлам: эффект, развилка
  (`if`/`if-case`, `while`, `do`, `for(;;)`, `?:`, `&&`/`||` с эффектами справа
  — `true`/`false`; `for … in` — `each`/`done`; `switch`, и оператор, и
  выражение, — исходник случая и `default`, если `switch` не исчерпывающий по
  `enum`/`bool`/`sealed` или записи из них и в нём нет `case _`), `call` (вызов
  функции с эффектами; вызов метода интерфейса — все реализации с эффектами) и
  `copies` (`Future.wait` над элементом `for` или над `map`). Элементы списка
  `Future.wait` (первый позиционный аргумент, и после именованного, как в
  `Future.wait(eagerError: true, [ … ])`) и поля записи в `(a, b).wait` — ветки.
  Замыкание, вызванное на месте, рисуется на месте вызова. `return`, `break` и
  `continue` из `try` идут через `finally`: он рисуется по разу на каждый такой
  выход. `throw` (и ветка `?:` или `switch`-выражения, которая бросает) кончает
  путь: у этого исхода развилки ребра нет. Брошенное внутри `try` решает первая
  ветка `catch`, к которой оно точно подходит (без типа или с типом, к которому
  подходит статический тип брошенного): кончается её блок обычно — путь идёт
  дальше после `try`, через `finally` (тот же, что у обычного конца тела);
  кончается `return` — выход из функции; `rethrow` или `throw` — брошенное идёт
  к `try` вокруг, через `finally`. Нет такой ветки — тоже к `try` вокруг; нет и
  его — путь кончается. Сами ветки `catch` не рисуются. Не рисуются оператор без
  эффектов и прыжков наружу и развилка, все исходы которой ведут в одно и то же.
  Подписи — код как написан, переносы строк свёрнуты. `switch` по локальной
  переменной или параметру: путь, на котором её последнее присваивание —
  константа (значение `enum`, `true`/`false`, литерал числа или строки, `null`)
  или новый экземпляр класса (`Write(launch)`), идёт стрелкой прямо в тело
  первого случая, который точно подходит (`case Stage.write`,
  `case Write(:final launch)`, `default`), а развилка `switch` рисуется только
  для путей, значение на которых не известно или случай которых нельзя
  выбрать точно (`when`, шаблон с условием на поле); в `while (true)`, тело которого — такой `switch`,
  так же идут `continue` и конец тела, голова цикла путей не склеивает.
  Переменная, которую присваивает замыкание, локальная функция или
  выражение не в своём операторе, не прослеживается. Чего ни один путь от
  входа не достигает — случай, в который никто не идёт, развилка, которую
  все обошли, — не рисуется.
- **Графы из узлов** (`lib/src/graphs.dart`) — переменные верхнего уровня,
  которые делает `Graph(имя, [...])` из `package:nanoflow`. Читаются куски
  `Graph.start`/`part`/`join` и цепочки `.next(цель, otherwise: …)`, цели —
  ссылки на функции и графы, литералы множеств и карт. Граф — запись
  `functions` с id `путь#<переменная>`, `name` — литерал имени (не литерал —
  имя переменной и предупреждение), тело — из прежних узлов: функция одного
  параметра — `effect` с её именем и местом графа, функция воркфлоу или граф —
  `call` (функция воркфлоу попадает в `functions`, даже без эффектов), карта —
  `fork` `switch (<узел>)` с рёбрами-ключами и `otherwise`; карта не на все
  значения `bool`, перечисления, `sealed` (все неабстрактные подклассы) или
  первого поля пары и без `otherwise` — ребро `otherwise` в конец; узел, чей
  выход никуда не идёт, — ребро в конец. Вызов графа из функции
  (`review(f, x)`, `review.call(f, x)`) — `call`, и функция с ним — функция с
  эффектами; граф, переданный в `Flow.start`/`run`/`resume` (`review.call`),
  — воркфлоу. Тела узлов-функций на побочные эффекты не проверяются: каждый
  — эффект.
- **Предупреждения** с местом, каждое по разу: имя эффекта — не литерал; эффекты
  в замыкании, переданном дальше, и в локальной функции; вызов функции с
  эффектами вне исходников; ветки `catch`; побочный эффект вне эффекта. У
  графов: имя графа — не литерал; граф не в переменной верхнего уровня;
  кусок, который не прочесть; узел — не функция верхнего уровня, не
  статический метод и не граф; цель не принимает груз стрелки
  (`needsChange takes Change, not the Report of check`, у схождения — запись
  выходов); ключ, который никогда не совпадёт
  (`key Square never matches: switch (judge) takes Verdict`).
- **Побочный эффект вне эффекта** (правило «любой побочный эффект, кроме
  логов, — внутри `effect`»; `lib/src/side_effects.dart`). Что: по
  разрешённому элементу — `DateTime.now`, `DateTime.timestamp`, конструктор
  `Stopwatch` (`dart:core`), конструкторы `Random` (`dart:math`), любой
  элемент `dart:io`, кроме `stdout`, `stderr` и их членов, констант
  (`HttpStatus.ok`, `FileMode.append`, значения перечислений) и исключений
  с их членами (`HttpException(…)`, `e.message`); `static final` — не
  константа (`ContentType.json`).
  Конструктор, оторванный от вызова (`File.new`, `DateTime.now`), — тоже. У
  цепочки (`File('x').readAsStringSync()`) — первое звено (`File('x')`).
  Где: в телах функций графа, с замыканиями в них, — на месте выражения; в
  функциях, методах, конструкторах, геттерах и сеттерах исходников, которые
  не функции графа, вглубь, каждая по разу, — на месте вызова (или передачи
  без вызова) о первом нарушении по порядку кода: `… loadConfig() reaches
  File('config.json') at lib/config.dart:6`. Функции, вызывающие друг друга
  по кругу, называют одно нарушение на всех: первое, до которого
  дотягивается обход от той из них, в которую он вошёл первой (функции
  обходятся по порядку объявлений и вглубь по вызовам), заходя в каждую по
  разу. Не проверяет: тело,
  переданное в `Flow.effect` (это сам эффект), и то, что вызывается только
  оттуда; `print`, `stdout`/`stderr`, таймеры, `Future.delayed`; код других
  пакетов и SDK; реализации метода интерфейса, функции в переменных,
  инициализаторы полей и переменных верхнего уровня, операторы. Замыкание,
  которое становится телом эффекта не прямо в `Flow.effect`, а через
  переменную или функцию-помощник, проверяется как любое другое и
  предупреждает.
- **Эффекты вне исходников.** Код другого пакета не рисуется. Предупреждение
  `effects of <имя> are not drawn: it is outside the package sources` получает
  вызов функции или метода вне исходников (кроме `package:nanoflow`), у
  которой есть параметр типа `Flow` и в теле которой, там, где оно
  выполняется, есть вызов `Flow.effect`. Без предупреждения остаются эффекты,
  которые так не видны: класс вне исходников держит `Flow` в поле, а не
  берёт параметром; эффекты на вызов глубже (внешняя функция передаёт `Flow`
  дальше); вызванный метод без тела (абстрактный, интерфейса).

## Тесты

```bash
dart test
```

Пакеты-образцы — `test/fixtures/<имя>/` (`lib/`, `bin/`, без
`pubspec.yaml`): `package:nanoflow` находится через конфигурацию пакетов
workspace. Ожидаемые графы записаны в тестах JSON-литералами. Тесты команды
копируют образец `review` с `pubspec.yaml` в `test/fixtures/.tmp-<…>/`
(внутри workspace, но в точечном каталоге, которого не видят другие образцы)
и удаляют копию после теста.
