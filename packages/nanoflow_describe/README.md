# nanoflow_describe

Извлекатель графа: читает код пакета анализатором Dart (`package:analyzer`),
ничего не выполняя, и строит каждому графу файл графа `<граф>.graph.json`
рядом с его Dart-файлом, который рисует UI ([формат](../../README.md#файл-графа);
[файл на граф](../../docs/superpowers/specs/2026-10-29-graph-file-per-graph-design.md)).
Приложение подключает пакет как `dev_dependency`, чтобы анализатор не попал
в его зависимости.

## Команда

```bash
dart run nanoflow_describe            # пишет файл каждого графа рядом с его Dart-файлом
dart run nanoflow_describe --watch    # и перезаписывает при каждой правке lib/ и bin/
dart run nanoflow_describe --check    # код 1, если файлы не те, что были бы записаны
dart run nanoflow_describe stamp build/review   # builds + копии файлов рядом с бинарником
```

- Корень пакета — текущий каталог или `--package <каталог>`; имя пакета —
  из его `pubspec.yaml`. Незнакомые аргументы и флаг на месте значения
  `--package` или `stamp` — справка в stderr, код 2.
- Файл пишется, только если байты изменились, и атомарно (временное имя с
  `.` и переименование); на каждую запись — строка `wrote <файл>`. Ошибки
  компиляции — в stderr, код 1; файл графа, в чьих исходниках ошибка, не
  трогается, файлы остальных графов пишутся.
- Файлы `*.graph.json` под `lib/` и `bin/` графов, которых нет, и прежний
  `nanoflow.graph.json` в корне удаляются — только когда пакет компилируется
  целиком; строка `removed <файл>`. `--check` — код 1, пока они есть
  (`is no graph of the package`), и если какого-то файла нет или он не тот.
- `builds` файла остаются, пока его исходники те же (отпечаток совпадает),
  и `--check` их не сравнивает: проштампованный файл свежий.
- `stamp <бинарник>` сверяет `fingerprint` каждого файла графа с его
  исходниками (не совпал — код 1, ничего не пишется), дописывает в каждый
  `builds[<имя бинарника>]` (по порядку имён) и пишет его рядом с
  бинарником по тому же пути (`build/lib/review.graph.json`).
- `--watch` пишет файлы, затем перечитывает пакет после правок (пачка правок
  за 200 мс — одна; исходники, которые уже были описаны, не читаются
  заново). Где каталог нельзя наблюдать целиком (Linux), — смотрит на
  отпечаток исходников раз в 500 мс. Строка на каждую запись и
  `describe failed: <первая ошибка>` на каждую неудачу — и тогда, когда
  чтение пакета бросило что угодно (анализатор или извлекатель споткнулся
  о код): `--watch` идёт дальше и описывает пакет снова при следующей
  правке. Останавливается по SIGINT.
- `--watch` описывает пакет заново, только когда изменились исходники.
  Неудача, которую исправляют не в исходниках, — пакеты не поставлены, —
  так и остаётся: после `dart pub get` (или другой смены конфигурации
  пакетов) `--watch` перезапускают.
- `runDescribe(аргументы, {cwd, out, err, stop, poll, describe})` — то же
  из кода; `stop` заканчивает `--watch` вместо SIGINT, `poll` включает
  опрос, `describe` читает пакет вместо `describePackage` (для тестов).

## Что внутри

- **`describePackage(каталог, {packageName})`** — исходники пакета
  (`packageSourcePaths` из `nanoflow_model`: `.dart` под `lib/` и `bin/`) с
  разрешёнными типами. Ошибки компиляции — в `errors` строками
  `путь:строка:колонка: сообщение`; исходник, который сам или через то, что
  импортирует, не компилируется, не читается, и графов из него нет. Имя
  пакета — `packageName` или `name:` из `pubspec.yaml`; без него графов нет.
  `graphs` — графы по id, `warnings` — с графом, в чьём объявлении каждое;
  `files` — файл каждого графа по пути (`describe.dart`):
  - путь — каталог Dart-файла графа и `graphFileNameOf(имя)`; путь, общий
    двум графам, достаётся первому по id;
  - узел `call` — путь файла подграфа;
  - `sources` — Dart-файл графа, файлы его библиотеки (`part`) и всё, что
    они импортируют и экспортируют из исходников пакета, по цепочке;
    `fingerprint` — их отпечаток; те же функции модели, что у библиотеки;
  - `warnings` — в объявлении графа и вне объявлений графов, но в его
    `sources`, без `function`;
  - `builds` пуст; ключи по порядку, так что файл одинаков байт в байт.
- **Графы** (`lib/src/graphs.dart`) — переменные верхнего уровня, которые
  делают `node(имя, тело)` и `Graph(имя, [...])` из `package:nanoflow`.
  Граф — запись `functions` с id `путь#<переменная>`, `place` — строка
  имени переменной, `name` — литерал имени (не литерал — имя переменной и
  предупреждение), `doc` — комментарий над переменной; других записей в
  `functions` нет.
- **Документация** (`docText`) — `doc` графа и узла: комментарий
  документации над его переменной, строки `///` или блок `/** */`. Текст —
  без `///` и пробела за ним (у блока — без `/**`, `*/` и `*` в начале
  строк), без пустых строк по краям; пустой — `null`
  ([спецификация](../../docs/superpowers/specs/2026-10-10-node-docs-design.md), §2).
- **Тело графа** — из кусков `Graph.start`/`part`/`join` и `.next(переход)`;
  переход — литерал функции или ссылка на функцию верхнего уровня, читается
  его тело (`lib/src/routes.dart`):
  - **узел** — `effect` с `name` — именем узла, `place` — строкой, где
    граф впервые называет узел (начало куска, член схождения или вызов в
    переходе; у одного узла в двух графах места разные), `doc` —
    комментарием над переменной узла; граф, служащий узлом, — `call`;
  - **переход** — `switch`, и выражение, и оператор, которым переход решает
    первым, сразу после узла, — выходы самого узла, ребро на каждый случай,
    подписанное его шаблоном без того, что он связывает (`Write` для
    `case Write(:final launch)`, `Draft(text: '')` как есть, `when` — как
    написан), и ребро `default`, если оператор `switch` не исчерпывающий по
    `enum`/`bool`/`sealed` или записи из них и в нём нет `case _`; любой
    другой `switch` — `fork` `switch (<предмет>)` с такими же рёбрами; `?:` и
    `if`/`if-case`, которыми переход решает первым, — тоже выходы самого
    узла: ребро, когда условие верно, подписано исходником условия, другое —
    `else` (`if` без `else` ведёт по `else` туда, куда код после него); `?:`
    и `if` в таком `else` — выходы того же узла, по порядку кода; любые
    другие `?:` и `if` — `fork` с исходником условия и рёбрами
    `true`/`false`; каждый `узел(…)` или `граф(…)` в том, что переход
    возвращает, — ребро к этому узлу; множество — рёбра к каждому, а
    элемент `for` в нём (`{for (final r in rs) узел(r)}`) — ребро к узлу,
    который он запускает на каждый элемент, с полем `each` — заголовком
    цикла (`for r in rs` или `for (…)` как написано), без развилки; `for` с
    телом не из одного вызова узла — предупреждение. Вызов с лимитом,
    `узел(r, limit: …)` или `узел.call(r, limit: …)`, в `for` и без него, —
    ребро с полем `limit`: выражение лимита как написано (`2`,
    `night.parallel`); вычисляемый лимит не предупреждение. `null` и конец
    тела — ребро в конец; `throw` кончает путь без ребра. Оператор без
    `return` и `throw` пропускается;
  - **схождение** — рёбра от каждого его узла к развилке или узлу его
    перехода, без перехода — в конец; узел без стрелок и не из схождения —
    ребро в конец;
  - развилка, все исходы которой ведут в одно место, не рисуется: у узла,
    чьи выходы все ведут в одно место, — одно ребро без подписи; подписи —
    код как написан, переносы строк свёрнуты;
  - id узлов — по порядку появления в объявлении, рёбра — по
    узлу-источнику в порядке id.
- **Предупреждения** с местом и графом, в чьём объявлении (`Graph(…)`) оно
  (`function`; ни в чьём — `null`), каждое по разу:
  - узел или граф не в переменной верхнего уровня; имя — не литерал строки;
  - два графа одного имени: сессия и эффекты узлов находятся по имени
    графа;
  - два узла одного имени в графе;
  - кусок графа, который не прочесть;
  - переход, который не прочесть: не литерал функции и не функция верхнего
    уровня (в том числе `.next(узел)` через `call`); оператор в нём с
    `return` или `throw` внутри, кроме блока, `if` и `switch`;
  - переход — `async` или генератор: он вернул бы `Future` или `Iterable`, а
    не `Next`, и граф упал бы при выполнении (`route is async or a
    generator: …`); его рёбра не рисуются, как у непрочитанного перехода;
  - значение перехода, которое не прочесть как переход к узлу: не `узел(…)`,
    не `граф(…)`, не множество их и не `null`;
  - узел, до которого не дойти, — он нарисован всё равно; если в графе
    что-то не прочлось, об этом не предупреждают;
  - тип параметра перехода после схождения не совпадает с записью выходов
    его узлов (`the route of the join takes (String, int), not the record
    of its nodes' outputs`) — поэтому тип пишут явно;
  - граф, который служит узлом другого графа и может кончиться несколькими
    концами сразу (параллель без схождения, несколько стартов): его
    результат — «последний по времени» — при продолжении может оказаться
    другим;
  - побочный эффект в переходе.
- **Побочный эффект вне эффекта** (правило «любой побочный эффект, кроме
  логов, — внутри `effect`»; `lib/src/side_effects.dart`). Узел — эффект,
  так что проверяются только переходы. Что: по разрешённому элементу —
  `DateTime.now`, `DateTime.timestamp`, конструктор `Stopwatch`
  (`dart:core`), конструкторы `Random` (`dart:math`), любой элемент
  `dart:io`, кроме `stdout`, `stderr` и их членов, констант
  (`HttpStatus.ok`, `FileMode.append`, значения перечислений) и исключений
  с их членами (`HttpException(…)`, `e.message`); `static final` — не
  константа (`ContentType.json`).
  Конструктор, оторванный от вызова (`File.new`, `DateTime.now`), — тоже. У
  цепочки (`File('x').readAsStringSync()`) — первое звено (`File('x')`).
  Где: в телах переходов, с замыканиями в них, — на месте выражения; в
  функциях, методах, конструкторах, геттерах и сеттерах исходников, которые
  не переходы, вглубь, каждая по разу, — на месте вызова (или передачи без
  вызова) о первом нарушении по порядку кода: `… loadConfig() reaches
  File('config.json') at lib/config.dart:6`. Функции, вызывающие друг друга
  по кругу, называют одно нарушение на всех: первое, до которого
  дотягивается обход от той из них, в которую он вошёл первой (функции
  обходятся по порядку объявлений и вглубь по вызовам), заходя в каждую по
  разу. Не проверяет: тела узлов и то, что вызывается только оттуда;
  `print`, `stdout`/`stderr`, таймеры, `Future.delayed`; код других пакетов
  и SDK; реализации метода интерфейса, функции в переменных,
  инициализаторы полей и переменных верхнего уровня, операторы.

## Тесты

```bash
dart test
```

Пакеты-образцы — `test/fixtures/<имя>/` (`lib/`, `bin/`, без
`pubspec.yaml`): `package:nanoflow` находится через конфигурацию пакетов
workspace. Ожидаемые графы записаны в тестах JSON-литералами. Тесты команды
копируют образец `graphs` с `pubspec.yaml` в `test/fixtures/.tmp-<…>/`
(внутри workspace, но в точечном каталоге, которого не видят другие образцы)
и удаляют копию после теста.
