# nanoflow_process

Порт ОС: когда процесс стартовал и когда его не стало. Нужен, чтобы знать
владельца сессии — процесс, который её ведёт, — и жив ли он. Процесс
узнаётся по pid и времени старта: pid один не уникален, ОС отдаёт номер
умершего процесса другому. Зависит от `ffi` и `nanoflow_model` (модели
владельца и `owner-changed`).

## Что внутри

- **`Processes`** — порт. `startOf(pid)` — время старта по ОС, UTC, до
  миллисекунд (младшие разряды отброшены); `null`, если процесса нет или
  адаптер не умеет. `exitOf(pid)` завершается, когда процесса нет, — сразу,
  если его нет уже; с ошибкой, если адаптер не может следить за процессом.
  `close()` останавливает наблюдение: ни ждущие, ни новые `exitOf` больше не
  завершатся. `supported` — умеет ли адаптер это всё.
  `Processes.forPlatform()` — адаптер этой ОС.
- **`MacProcesses`** — macOS, FFI к libc. Время старта — `sysctl`
  (`CTL_KERN, KERN_PROC, KERN_PROC_PID`): `p_starttime` в начале
  `kinfo_proc`, пустой ответ — процесса нет. Выход — kqueue: pid
  регистрируется (`EVFILT_PROC`, `NOTE_EXIT`, `EV_ONESHOT`) из вызывающего
  изолята, нет процесса (`ESRCH`) — `exitOf` завершается сразу. Ждёт один
  фоновый изолят на адаптер, его запускает первый `exitOf`: `kevent` ждёт
  не дольше 500 мс за раз и ждёт снова, а событие кончает ожидание сразу;
  pid вышедших — через `SendPort`; изолят остановился — ждущие `exitOf`
  завершаются с ошибкой. `close` будит его событием `EVFILT_USER`, ждёт его
  конца и закрывает kqueue (не разбудить — изолят убит, как только вернётся
  из `kevent`).
- **Когда программа кончается.** Ждущий `exitOf` держит программу, как
  любое ожидание ОС, а `close` — пока не кончился фоновый изолят; больше
  адаптер её не держит, закрыт он или нет. Dart VM, завершаясь, ждёт каждый
  изолят, а остановить может только вернувшийся из ОС, — фоновый изолят
  возвращается не позже чем через 500 мс. Так и приложение Flutter, которое
  адаптер не закрыло, выходит, а не виснет; закрытый адаптер не задерживает
  выход и на эти 500 мс.
- **`UnsupportedProcesses`** — остальные ОС: `supported == false`, `startOf`
  — `null`, `exitOf` не завершается.
- **`Owners`** — владельцы сессий для читателей хранилища: из записи
  владельца (`observe(sessionId, record)`, запись каждый читатель достаёт по-
  своему — `.owner.lock`, строка базы) и ответов ОС даёт `owner-changed`;
  выход процесса будит читателя через `news`. Общий у файлового читателя и
  SQLite; как он сообщает — в [чтении](../../README.md#чтение).
- **`FakeProcesses`** (`package:nanoflow_process/testing.dart`) — для тестов:
  `start(pid, started)` и `exit(pid)` вручную.

## Новая ОС

Новый адаптер в `lib/src/` — класс, реализующий `Processes`, — и ветка для
этой ОС в `Processes.forPlatform()`. Остальное не меняется.

## Тесты

```bash
dart test
```

Тесты `MacProcesses` запускают настоящие процессы и идут только на macOS.
Когда кончается программа, смотрят на фикстурах из `test/fixtures/`,
собранных `dart compile exe`, как код приложения: такая программа кончается
быстрее, чем под `dart run`.
