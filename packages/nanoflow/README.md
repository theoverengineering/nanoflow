# nanoflow

Библиотека для [графа кодом](../../README.md#программа-графа): файл на Dart с
ней сам и есть программа графа. Как пишется граф — в
[графе на Dart](../../docs/dart-graph.md).

## Что внутри

- **Узлы.** `node(функция)` — рабочий узел, `fork(функция)` — развилка;
  функция при объявлении не вызывается. Тип параметра — `in`, тип результата
  — `out`. Параметр `Object?` или `dynamic` — узел без `in`; результат
  `void`, `Null`, `Object?` или `dynamic` — без `out`. Исход `bool` — форма
  if, любой другой тип — switch.
- **Граф.** `Graph.start` и `Graph.part` начинают кусок, `.next` — стрелка
  рабочего узла, `.then` и `.otherwise` — выходы развилки, `Graph([…])`
  собирает куски. Цель — узел или множество узлов; множество может смешивать
  рабочие узлы и развилки. Ошибки формы ловит компилятор: цель не принимает
  данные, исход не того типа, `.then` у рабочего узла, `.next` у развилки,
  продолжение после множества или развилки, кусок как цель.
- **Имена узлов** — имена переменных верхнего уровня, через `dart:mirrors`:
  программа графа запускается `dart run`, не AOT.
- **Типы данных** (`src/dart_types.dart`). `String`, `int`, `double`, `num`,
  `bool`, `List<T>`, `Map<String, T>`, `enum` (по имени) и классы с
  конструктором `fromJson` и методом `toJson`. `schemaOf` даёт схему типа для
  `in` и `out`, `decodeAs` разбирает JSON в значение типа (`FormatException`
  с местом, если не подходит), `encodeValue` пишет значение в JSON.
- **Сборка** (`src/build.dart`). `buildGraph` проверяет граф и даёт узлы по
  имени и граф в JSON; `describe` — описание графа `{file, graph}`, где
  `command` и `decide` — место объявления узла относительно каталога
  программы: `graph.dart:12`. Узлы — в порядке объявления. Ошибки —
  `GraphBuildException`, по строке на каждую: нет `Graph.start`, выход
  объявлен дважды (в том числе в разных кусках), узел не в переменной
  верхнего уровня или в двух, два узла с одним именем, тип данных без
  JSON-формы. Данные не бывают `null`: тип данных с `?` (`Report?`,
  `List<String?>`) и `Object` без `?` — тоже ошибки.
- **Программа графа** (`src/serve.dart`). `main` отдаёт аргументы `serve`:
  `--graph` печатает описание, `--graph --watch` — его же и новое после
  каждой правки `.dart`-файлов в каталоге программы (`src/watch.dart`;
  следит сама программа, поэтому на старте она должна компилироваться:
  ошибка компиляции при запуске — ненулевой код, а после запуска, пока
  программа не компилируется, не печатается ничего),
  `--input` проверяет вход запуска функцией `input` (что она возвращает тип
  входа стартового узла, проверяет компилятор), `--call <узел>` выполняет шаг
  (`src/call.dart`). Файл программы — исходник корневой библиотеки, а не
  `Platform.script`: у исполняемого файла пакета (`dart run :граф`) это
  снапшот pub в `.dart_tool`. stdout пишет только библиотека; `print` во
  время `serve` — в функциях узлов и в `input` — уходит в stderr, а `print`
  до `serve`, например в инициализаторе переменной верхнего уровня, попадает
  в stdout. Конец stdin, SIGINT и SIGTERM останавливают шаг.
- **Внешние программы** (`src/exec.dart`). `exec` запускает программу через
  `sh -c` с `set -m` в своей группе процессов, отдаёт её stdout, а stderr —
  в лог шага по мере поступления; ненулевой код — `ExecException`, stdout не
  в UTF-8 — `FormatException`. Запускается всегда программа, а не встроенная
  команда shell с тем же именем. Шаг их не переживает: как бы он ни
  кончился — остановкой, возвратом функции или её исключением, в том числе
  тем, которое никто не ждал, — группам ещё идущих программ уходит SIGTERM,
  через 5 с — SIGKILL.
- **Какой shell.** Своя группа нужна, чтобы остановить программу с
  потомками, а даёт её shell, который не выключает управление заданиями без
  терминала. Так делает bash, поэтому `exec` берёт `/bin/bash`, если он
  есть, иначе `/bin/sh`. dash (`/bin/sh` в Debian и Ubuntu) без терминала
  управление заданиями выключает: тогда `exec` до запуска первой программы
  бросает `StateError` с просьбой поставить bash, а не запускает программу,
  которую остановка не догонит. stdin программе shell передаёт явно, через
  дескриптор 4, поэтому он доходит и без управления заданиями.

Публичная точка `lib/nanoflow.dart` отдаёт только то, чем пишут граф, и
`serve`, `exec`, `ExecException`.

## Тесты

```bash
dart test
```

`test/serve_test.dart` запускает программы из `test/fixtures/` через
`dart run`, как их запускает движок.

`test/exec_test.dart` запускает dash, если он есть, и
`test/fixtures/exec_through.dart` без управляющего терминала: так dash
выключает управление заданиями.

`test/compile_errors_test.dart` запускает `dart analyze` на программах из
`test/fixtures/compile_errors/` и сверяет ошибки по строкам; из анализа
пакета эти программы исключены в корневом `analysis_options.yaml`.
