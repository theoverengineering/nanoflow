# nanoflow

Воркфлоу на Dart — обычной функцией. Эффект — вызов `f.effect`, его результат
сохраняется, и после падения сессия продолжается с готовыми эффектами. Граф
читается из кода статически, UI показывает его вместе с сессиями.

Почему так, а не иначе, — в [журнале решений](docs/superpowers/specs/2026-10-02-code-first-decisions.md);
полная постановка — в [спецификации](docs/superpowers/specs/2026-10-03-code-first-design.md).

## Что это

- **Воркфлоу — обычная асинхронная функция Dart**,
  `Future<R> Function(Flow f, I input)`. Эффект — вызов
  `f.effect('имя', () => …)`. Развилки — `if` и `switch`, петли — циклы,
  параллельность — `Future.wait`: своего языка графа нет.
- **Или граф из узлов.** Узел — `node('имя', (вход) async { … })`: единица
  работы, которая выполняется как эффект и не знает, что до неё и что после;
  что за чем, говорит объявление `Graph`, а ветвит обычная функция Dart —
  переход, который зовёт следующий узел с тем, что ему нужно
  ([граф из узлов](#граф-из-узлов)). Код и узлы — два равных способа, функция
  и граф вкладываются друг в друга.
- **Сессию ведёт библиотека в процессе приложения.** Сессия — один вызов
  воркфлоу: вход, каждый эффект с результатом и результат воркфлоу пишутся в
  [`runs/`](#хранение). Отдельного движка нет.
- **После падения сессию продолжает `resume`.** Функция идёт заново с
  сохранённым входом; готовый эффект отдаёт сохранённый результат и не
  выполняется. Сохраняются только эффекты: код между ними выполняется заново.
- **Результаты хранятся как JSON.** JSON-типы — как есть, свой класс — через
  `toJson` и `addCodec(Report.fromJson)`.
- **Внешние программы запускает `exec`:** его результат — stdout программы,
  stderr — в лог эффекта; программа останавливается вместе с сессией и умирает
  вместе с процессом.
- **Граф читается из кода, код не выполняется.** `nanoflow_describe`
  разбирает код анализатором Dart и пишет [файл графа](#файл-графа)
  `nanoflow.graph.json`. Исполнению граф не нужен: приложение только кладёт
  его снимок в сессию.
- **UI только читает** файл графа и сессии рядом с ним и показывает граф,
  сессии и эффекты вживую. Он ничего не запускает и не знает, на каком языке
  написан воркфлоу: файл графа и хранение от языка не зависят.

## Пример

Граф ревью: взять изменение ветки; пустое — `discard`; иначе `inspect`, и
пока он что-то находит — `fix`; ничего не нашёл — `publish` и `notify`
рядом.

```dart
Future<void> review(Flow f, String branch) async {
  var change = await f.effect('collect', () => collect(branch));
  if (change.path.isEmpty) {
    await f.effect('discard', () => print('nothing to review'));
    return;
  }
  while (true) {
    final report = await f.effect('inspect', () => inspect(change));
    if (report.findings.isEmpty) {
      await Future.wait([
        f.effect('publish', () => print('published ${report.change.path}')),
        f.effect('notify', () => print('${report.change.id}: accepted')),
      ]);
      return;
    }
    change = await f.effect('fix', () => fix(report));
  }
}

Future<void> main(List<String> args) async {
  final flow = Flow()
    ..addCodec(Change.fromJson)
    ..addCodec(Report.fromJson);
  final session = await flow.start(review, args.single);
  print(session.id); // по нему сессию продолжают: flow.resume(review, id)
  await session.result;
}
```

Целиком — с `Change`, `Report`, `inspect` через `exec`, Ctrl+C и `--resume` —
в [examples/review](examples/review/README.md).

## Граф из узлов

Тот же ревью графом: узел — `node('имя', тело)`, а что за чем, говорят
переходы — обычные функции Dart, которые зовут следующий узел. Это второй
способ написать воркфлоу, а не замена функции: оба равны. Дизайн — в
[спецификации](docs/superpowers/specs/2026-10-25-graph-node-objects-design.md).

```dart
sealed class Collected {}
final class Empty implements Collected { Empty(this.branch); final String branch; }
final class Found implements Collected { Found(this.change); final Change change; }

/// The change of the branch, or Empty when it changes nothing.
final collect = node('collect', (String branch) async { … });   // Collected: Empty | Found
final inspect = node('inspect', (Change change) async { … });   // Report
final fix = node('fix', (Report report) async { … });           // Change
final discard = node('discard', (String branch) async => print('nothing to review'));
final publish = node('publish', (Report report) async { … });   // String
final notify = node('notify', (Report report) async { … });     // String
final report = node('report', ((String, String) sent) async { … });

/// Reviews the change of a branch.
final review = Graph<String, void>('review', [
  Graph.start(collect).next((collected) => switch (collected) {
    Empty(:final branch) => discard(branch),
    Found(:final change) => inspect(change),
  }),
  Graph.part(inspect).next((r) => r.findings.isEmpty
      ? {publish(r), notify(r)}
      : fix(r)),
  Graph.part(fix).next((change) => inspect(change)),
  Graph.join([publish, notify]).next(((String, String) sent) => report(sent)),
]);

await flow.run(review.run, 'feature/parse-config');
```

- **Узел** — `node<I, O>(name, body)` в переменной верхнего уровня.
  Выполняется эффектом с именем `name`: результат пишется в журнал кодеком
  типа `O` (как у `f.effect<O>`) и при продолжении берётся из него; узел, не
  кончившийся до падения, выполняется заново целиком. Внутри — обычный Dart
  (`exec`, лог эффекта), своих эффектов нет: у тела нет `Flow`. Имена узлов
  графа различны; документация узла — `///` над его переменной; `узел.body` —
  тело, чтобы вызвать работу узла в тесте без графа. Один узел может быть в
  нескольких графах.
- **Переход.** `Graph.start(узел)` — откуда граф начинается (стартов может
  быть несколько, они идут рядом), `Graph.part(узел)` — кусок от любого узла,
  `.next((выход) => …)` — единственный вид стрелок. Переход получает выход и
  говорит, что дальше:
  - `узел(вход)` или `граф(вход)` — дальше он, с этим входом; вызов ничего не
    выполняет, узел выполняет библиотека;
  - множество `{a(x), b(y)}` — все они, рядом;
  - `null` — ветка кончается, выход идёт в результат графа;
  - что-то другое — `StateError`.

  Ветвят обычные `switch`, `if`, `?:`: компилятор проверяет полноту `switch`
  и тип аргумента следующего узла. Стрелки узла объявляются один раз; узел
  без стрелок кончает ветку.
- **Переход чистый:** при продолжении он вычисляется заново по выходу из
  журнала и по тому же выходу должен дать то же. Всё, что меняет мир, — в
  узлах.
- **Схождение** `Graph.join([a, b])`: переход после него получает запись
  выходов в порядке списка, когда каждый дал выход; в петле — по разу на
  полный набор; неполное схождение не наступает, и граф кончается. Узлов — от
  двух до шести, разных. Кусок схождения не знает типа записи, поэтому тип
  параметра перехода пишется явно: `((String, String) sent) => report(sent)`.
- **Граф — воркфлоу:** `flow.start(review.run, …)`, `run`, `resume`,
  `unfinished`; имя сессии — имя графа. Из функции воркфлоу граф запускают
  как `await review.run(f, x)`. Вызов `review(x)` — переход, как у узла:
  граф может быть узлом другого графа и выполняется на месте, его узлы — свои
  эффекты в журнале. Узлом бывает только узел `node(...)` или граф; функция
  воркфлоу узлом не бывает.
- **Результат** — выход, который никуда не пошёл, последним: узла без стрелок
  или узла, чей переход дал `null`; обычно граф `void`. Узел схождения без
  своих стрелок концом не считается. Ошибка узла или перехода — ошибка графа,
  когда кончились остальные ветки.
- **Выход узла раскодируется при `resume` по `O`:** `Node<String, Collected>`
  — кодеком `Collected`. Перечисления — `flow.addEnum(Verdict.values)`, записи
  из двух полей пишутся списком.
- **Создание проверяет граф:** нет старта, стрелки узла объявлены дважды, два
  разных узла одного имени, схождение не из 2–6 разных узлов — `ArgumentError`
  со списком. «До узла не дойти» библиотека не проверяет — переходы ей
  неизвестны, пока не выполнены, — это предупреждение `describe`.
- **`Nodelike` не экспортируется.** Это общий тип `Node` и `Graph`, который
  принимают `Graph.start`, `part` и `join`: в подписях он есть, а назвать его
  в своём коде нельзя — и не нужно.
- **Ограничения:** данные идут только через выходы и аргументы переходов;
  параллель — объявленная (множество, схождение), копий «по элементу списка»
  нет; два перехода к одному узлу без схождения — два запуска, на рисунке это
  не отличить от схождения.

Pub workspace: общие `pubspec.lock` и `analysis_options.yaml` в корне,
каждый каталог из таблицы — отдельный Dart-пакет.

| [`packages/nanoflow_describe`](packages/nanoflow_describe/README.md) | извлечение графа, команды `describe` и `stamp`                              | `nanoflow_model`, `analyzer`                           |

| `tests/e2e`                                                          | пример процессом, падение и продолжение, договор хранилища и читателя       | всё, кроме UI                                          |

- **Пакеты не зависят от программ.** Общий у всех только `nanoflow_model`.
- **`nanoflow_store` и `nanoflow_reader` друг друга не импортируют.** Что
  записанное одним читается другим, проверяет `tests/e2e`.
- **Хранилище не спрашивает ОС.** Кто владелец сессии, `nanoflow` узнаёт
  через `nanoflow_process` и передаёт `nanoflow_store`; тот от
  `nanoflow_process` не зависит.
- **Анализатор не попадает в приложение.** `nanoflow` не зависит от
  `analyzer`, а `nanoflow_describe` приложение подключает как
  `dev_dependency`.
- **UI импортирует из репозитория только `nanoflow_model` и
  `nanoflow_reader`.** Раскладка графа (`apps/nanoflow_ui/lib/layout/`) не
  импортирует Flutter: её тесты — на чистом Dart.
- **UI — вне workspace**, со своим `pubspec.lock` и зависимостями `path:`;
  ставит их `flutter pub get` в его каталоге.
- **У каждого пакета своё:** публичная точка `lib/<имя>.dart`, остальное — в
  `lib/src/`, README и тесты.
- **`prototypes/`** — прототипы ключей эффектов (`step_keys`) и извлечения
  графа (`static_graph`), доказательства решений; в workspace не входят.
- **`docs/`** — [ТЗ интерфейса](docs/ui-spec.md),
  [раскладка графа](docs/graph-layout.md), макеты в `docs/design/`,
  спецификации и планы в `docs/superpowers/`.

## Каталог проекта

Каталог, где лежат файл графа `nanoflow.graph.json` и каталог сессий
`runs/`.

- **При разработке** — корень пакета приложения, где `pubspec.yaml`:
  `describe` пишет туда файл графа, библиотека — `runs/`.
- **У собранного приложения** — каталог бинарника: `stamp` кладёт туда копию
  файла графа, библиотека пишет туда `runs/`.
- **Как его находит библиотека:** `Flow(directory: …)`, если задан; иначе в
  собранной программе (`dart.vm.product`) — каталог
  `Platform.resolvedExecutable`; иначе под `dart run`, `dart run <пакет>` и
  `dart run :main`, которые запускают снимок из
  `<корень>/.dart_tool/pub/bin/<пакет>/`, — каталог пакета по
  `.dart_tool/package_config.json` (в pub workspace `.dart_tool` лежит в
  корне workspace); иначе — ближайший к `Platform.script` предок с
  `pubspec.yaml`, а если такого нет — каталог `Platform.script`.

## Библиотека

```dart
final flow = Flow()
  ..addCodec(Change.fromJson)
  ..addCodec(Report.fromJson);

final session = await flow.start(review, 'feature/parse-config');
final result = await session.result;                // результат воркфлоу
await flow.run(review, 'feature/parse-config');     // start, потом result
await flow.resume(review, sessionId);               // после падения
await flow.unfinished(review);                      // id незаконченных сессий
flow.stop();                                        // эффекты больше не стартуют

flow.addEnum(Verdict.values);                       // перечисление пишется именем
await flow.run(reviewGraph.run, 'main');            // граф — так же, через .run
```

Подробно — в [README пакета](packages/nanoflow/README.md).

- **Имя воркфлоу — имя функции.** Воркфлоу — функция верхнего уровня или
  статический метод: имя другой функции не узнать, это `ArgumentError`.
- **Ключ эффекта находит его результат при продолжении:** `collect#1@<хэш>` —
  имя, номер среди эффектов с этим именем и хэш контекста, в котором эффект
  вызван. Ключ одинаков при каждом запуске того же кода, как бы ни шли
  параллельные копии, — кроме эффекта, путь к которому решает тайминг
  (`Future.any`, гонки), и эффекта, вызванного прямо из обратного вызова
  таймера или микрозадачи рядом с чтением потока в своём темпе: такой эффект
  при продолжении может выполниться заново, но чужой результат не получит.
  Устройство — `packages/nanoflow/lib/src/context.dart`, доказательство —
  `prototypes/step_keys`.
- **У эффекта есть предшественник `after`** — ключ последнего эффекта, результат
  которого принял код, вызвавший эффект; `null`, если такого нет.
- **Эффект из журнала** — у его ключа есть `effect-finished`, предшественник тот
  же, и сохранённый результат раскодируется нынешним типом: тело не
  выполняется, в журнал ничего не пишется. Иначе эффект выполняется вживую — в
  прежнюю запись эффекта, если она есть.
- **Законченная сессия не выполняется:** `resume` отдаёт сохранённый
  результат или `SessionFailedException`.
- **Сессию ведёт один владелец:** исключительная блокировка ОС байта в
  `.owner.lock`, которую ОС снимает с упавшего процесса. Занятая сессия —
  `SessionBusyException`. В сам файл владелец пишет себя — pid и время
  старта процесса — и очищает его, отпуская сессию
  ([`.owner.lock`](#файлы)).
- **Остановка (`stop()`) и сбой хранилища** останавливают программы `exec`;
  эффекты больше не стартуют, в сессию ничего не пишется — её можно продолжить.
- **Хэш кода** пишется в сессию: под `dart run` — [отпечаток
  исходников](#отпечаток-исходников), в собранной программе — `sha256:`
  байтов бинарника; не удалось посчитать — `null`.

### Правило

> **Любой побочный эффект, кроме логов, — внутри `effect`.**

- **Побочный эффект** — всё, чем код касается мира за пределами функции:
  читает время, случайные числа, окружение, файлы, сеть; пишет файлы, ходит
  в сеть, запускает программы.
- **Логи** (`print`, логгер) — где угодно: на путь не влияют, при
  продолжении сессии просто печатаются ещё раз.
- **Следствие:** код между эффектами при тех же входе и выходах эффектов
  идёт тем же путём. Продолжение на том же коде идёт тем же путём; развилки
  выводятся из журнала
  ([спецификация, §9 «Развилки»](docs/superpowers/specs/2026-10-03-code-first-design.md#9-ui)).
- **Правило — соглашение;** `describe` предупреждает об очевидных нарушениях
  ([спецификация, §7.1](docs/superpowers/specs/2026-10-03-code-first-design.md#71-извлечение)).
  Рантайм ничего не запрещает.

## Хранение

Формат один для любого языка: что пишет библиотека, читает UI. Модели и
раскладка — в [`nanoflow_model`](packages/nanoflow_model/README.md), запись —
[`nanoflow_store`](packages/nanoflow_store/README.md), чтение —
[`nanoflow_reader`](packages/nanoflow_reader/README.md).

### Файлы

```text
runs/
  review-2026-10-03T10-00-00-<id>/         сессия: <воркфлоу>-<время создания>-<id>
    session.json
    log.jsonl                               журнал сессии
    .owner.lock                             владелец сессии и его блокировка
    documents/<id>.json                     вход, выходы эффектов, результат, снимки графа
    effects/
      2026-10-03T10-00-00-482-collect-<id>/ эффект: <время>-<имя>-<id>
        effect.json
        effect.log                          print эффекта и stderr его программ
```

- **Время в именах — UTC**, у эффекта с миллисекундами; монотонно растёт в
  пределах сессии. Знаки имени вне `[A-Za-z0-9._-]` — `_`.
- **Каталог находят по id** — последние 36 знаков имени. Остальное в имени —
  для человека и сортировки.
- **Записанное не бывает половинчатым.** Файл пишется под временным именем с
  `.` в том же каталоге и переименовывается; сессия и эффект собираются под
  `.tmp-<id>` и переименовываются целиком. Эти временные имена читатели
  пропускают.
- **JSON-файлы** — с отступом в 2 пробела и переводом строки в конце;
  `log.jsonl` — по объекту в строке.
- **`.owner.lock` — владелец сессии,** процесс, который её ведёт:
  `{"pid":4242,"started":"2026-10-03T07:43:34.651Z"}` — одной строкой, без
  перевода строки. Пара pid и времени старта — ключ процесса: один pid не
  уникален, ОС отдаёт номер умершего процесса другому.
  - **`started`** — время старта процесса по ОС в формате времени событий,
    младшие разряды отброшены; `null`, когда адаптер ОС его не знает. Ключи
    — в этом порядке, оба всегда есть.
  - **Пустой файл** (или его нет) — владельца нет: сессия отпущена или её
    писала прежняя версия. Упавший процесс файл не очищает.
  - **Блокировка — байт по смещению `ownerLockOffset` (`1 << 30`),** а не
    весь файл: содержимое не под ней и читается и там, где блокировки
    обязательные. Запись — с позиции 0, потом файл обрезается по её длине;
    отпуская сессию, владелец обрезает файл до нуля, потом закрывает.
  - **Читать файл в процессе-владельце нельзя:** блокировка ОС — на процесс,
    и закрытие любого его дескриптора файла снимает её. Его читает другой
    процесс — UI.

### Модели

У модели всегда есть все поля, в этом порядке; нет значения — `null`. Id —
UUID v4 в нижнем регистре.

| Модель   | Поля                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| Сессия   | `id`, `workflow` (имя функции), `graph` (снимок файла графа или `null`), `inputId`                            |
| Эффект   | `id`, `sessionId`, `name`, `key`, `after` (ключ предшественника), `place`, `outputId`, `log` (`"effect.log"`) |
| Документ | `id`, `sessionId`, `value`                                                                                    |

- **`place`** — где вызван `f.effect`: `путь:строка`. Файл внутри каталога
  проекта — путь от него; файл библиотеки самого пакета
  (`package:<пакет>/x.dart`) — `lib/x.dart`; другой — как в стеке. Не
  удалось узнать — `null`.
- **`outputId` эффекта** появляется после `effect-finished`: сначала пишется
  документ выхода, потом событие, потом `effect.json`. Итог эффекта — событие, а
  не `effect.json`.
- **Повтор эффекта в прежней записи** (упал, не закончился, другой
  предшественник) пишет новый `effect-started` в ту же запись, а при другом
  предшественнике и переписывает её `after`.

### События

Строка `log.jsonl`. У любого события `time` (UTC, ISO-8601, ровно три знака
дробной части, `Z`) и `event`; остальные поля — свои.

| `event`            | Свои поля                    | Когда                                                                                                 |
| ------------------ | ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| `session-started`  | `code`                       | первое событие, пишется при создании                                                                  |
| `session-resumed`  | `code`, `graphId`            | каждое продолжение; `graphId` — документ с новым снимком графа, если хэш кода изменился, иначе `null` |
| `effect-started`   | `effectId`                   | эффект начал выполняться вживую                                                                       |
| `effect-finished`  | `effectId`, `outputId`       | эффект вернул значение                                                                                |
| `effect-failed`    | `effectId`, `error`, `stack` | эффект бросил исключение                                                                              |
| `session-finished` | `outputId`                   | функция воркфлоу вернула значение                                                                     |
| `session-failed`   | `error`, `stack`             | функция воркфлоу бросила                                                                              |

- **`code`** — хэш кода, который выполнял сессию; `null` — не посчитан.
- **Снимок графа при продолжении** пишется, только если хэш кода изменился и
  файл графа есть; иначе `graphId` — `null`.
- **`error`** — одна строка: `toString()` исключения, переводы строк заменены
  на пробелы. **`stack`** — текст стека.
- **`session-finished` и `session-failed` — последнее событие сессии.**
- **Незнакомое событие читается как есть;** событие с неверными полями — как
  незнакомое.

### Состояние

Не хранится: его даёт проигрывание журнала (`replaySession`), незнакомые
события пропускаются.

- **Сессия:** `running`, пока нет последнего события, иначе `finished` или
  `failed`. `startedAt` — время `session-started`, `finishedAt` — последнего
  события у законченной. `codes` — хэши кода по порядку (`session-started`,
  потом каждый `session-resumed`), `graphIds` — документы снимков.
- **Эффект:** порядок — по первому `effect-started`. `status` — по событию после
  последнего `effect-started`: нет — `running`, `effect-finished` — `finished`,
  `effect-failed` — `failed`. `starts` — число `effect-started`.

## Файл графа

`nanoflow.graph.json` в каталоге проекта, один на пакет. Пишет его
[`describe`](#извлечение-графа), читают библиотека (снимок в сессию) и UI.
Образец формата — не файл `examples/review`, у того предупреждений нет:

```json
{
  "format": 3,
  "package": "review_example",
  "fingerprint": "sha256:7d3e…",
  "sources": { "bin/main.dart": "sha256:aa11…", "lib/review.dart": "sha256:9f2c…" },
  "builds": { "review": "sha256:c07e…" },
  "workflows": ["lib/review.dart#review"],
  "functions": {
    "lib/review.dart#review": { "name": "review", "place": "lib/review.dart:48", "doc": "Reviews the change of [branch].", "body": { "nodes": [], "edges": [] } }
  },
  "warnings": [ { "place": "lib/review.dart:40", "message": "effects in a closure passed on are not drawn" } ]
}
```

- **`functions`** — функции с эффектами по id `путь#имя` (метод —
  `путь#Класс.имя`). Граф функции описан один раз, сколько бы раз её ни
  вызывали. Граф из узлов — тоже запись здесь: id `путь#<переменная>`,
  `name` — имя графа, `place` — строка переменной, `doc` — комментарий над
  ней.
- **`workflows`** — функции и графы, переданные первым аргументом в
  `Flow.start`, `Flow.run` или `Flow.resume` (граф — его `run`:
  `review.run`); у каждого есть запись в `functions`, даже без эффектов.
- **`warnings`** — что извлечение не нарисовало, с местом.
- **`place`** — `путь:строка` от корня пакета.
- **`doc`** — у функции и у эффекта: текст его комментария документации
  `///` без `///`, Markdown как есть; нет комментария — `null`
  ([извлечение графа](#извлечение-графа)).
- **`format`** — 3. Формат 2 — тот же файл без `doc`: его и снимки сессий,
  начатых до формата 3, UI читает с `doc: null`. `describe` пишет формат 3.

### Тело

`body` — граф одного уровня:

```json
{
  "nodes": [
    { "id": "1", "kind": "effect", "name": "collect",             "place": "lib/review.dart:49", "doc": "Takes the change of the branch." },
    { "id": "2", "kind": "fork",   "label": "change.path.isEmpty", "place": "lib/review.dart:50" },
    { "id": "3", "kind": "call",   "functions": ["lib/release.dart#publish"], "place": "lib/release.dart:23" },
    { "id": "4", "kind": "copies", "label": "pkg in packages",     "place": "lib/release.dart:20", "body": { "nodes": [], "edges": [] } }
  ],
  "edges": [
    { "from": null, "to": "1", "label": null },
    { "from": "2",  "to": "3", "label": "true" },
    { "from": "2",  "to": null, "label": "false" }
  ]
}
```

- **Узлы:** `effect` — вызов `f.effect` (`name` — литерал имени или исходник
  выражения); `fork` — развилка (`label` — исходник условия); `call` — вызов
  функции с эффектами (несколько `functions` — реализации метода интерфейса);
  `copies` — тело, которое `Future.wait` выполняет копиями (`label` —
  `<переменная> in <выражение>`, `body` — тело копии). id — строки,
  уникальные в теле.
- **`from: null`** — вход в тело, **`to: null`** — выход из него (`return`
  или конец).
- **Подписи рёбер из развилки:** `if`, `while`, `for(;;)`, `&&`/`||`, `?:` —
  `true`/`false`; `for … in` — `each`/`done`; `switch` — исходник случая или
  `default`. У остальных рёбер `label: null`.
- **Несколько рёбер из узла с одной подписью** — ветки `Future.wait`; узел,
  в который они входят, ждёт все.
- **Тело графа из узлов** — из тех же видов. Узел `node(...)` — `effect`:
  `name` — имя узла, `place` — строка, где граф впервые называет узел (по
  ней UI находит эффекты узла; у одного узла в двух графах места разные),
  `doc` — комментарий над переменной узла. Граф, служащий узлом другого
  графа, — `call`.
- **Переход сводится к узлам тела** по правилам извлечения функции: его
  `if`, `switch` и `?:` — `fork` (`label` — условие или
  `switch (collected)`; рёбра — `true`/`false` или исходник шаблона случая,
  `Empty(:final branch)`, с `when`, если он есть); каждый `узел(…)` или
  `граф(…)` в том, что переход возвращает, — ребро к этому узлу; множество —
  рёбра к каждому; `null` — ребро в конец. Развилка, все исходы которой ведут
  в одно место, не рисуется, поэтому простая стрелка — одно ребро.
- **Схождение** — рёбра от каждого его узла к развилке или узлу его
  перехода; узел без стрелок и не из схождения — ребро в конец.

### Отпечаток исходников

Исходники пакета — файлы `.dart` под `lib/` и `bin/`, кроме каталогов,
начинающихся с `.`, и `build/`.

- **`sources`** — хэш каждого: `sha256:` + sha256 содержимого с `\r\n` →
  `\n`, по пути от корня пакета через `/`.
- **`fingerprint`** — `sha256:` + sha256 строк `<путь> <хэш>\n`,
  отсортированных по пути.
- **`builds`** — хэши собранных бинарников по имени файла: их дописывает
  `stamp`.

Хэш кода сессии должен найтись в `fingerprint` или `builds` её снимка — так
UI видит, что сессия шла на том коде, из которого прочитан граф.

## Извлечение графа

[`nanoflow_describe`](packages/nanoflow_describe/README.md) приложение
подключает как `dev_dependency` и запускает из корня пакета (или с
`--package <каталог>`):

```bash
dart run nanoflow_describe            # пишет nanoflow.graph.json
dart run nanoflow_describe --watch    # и перезаписывает при каждой правке исходников
dart run nanoflow_describe --check    # код 1, если файл не тот, что был бы записан
dart run nanoflow_describe stamp build/review   # хэш бинарника в builds, копия файла рядом с ним
```

- **Код не выполняется:** граф потока управления каждой функции с эффектами,
  сведённый к узлам [тела](#тело), и тело каждого графа из узлов,
  объявленного в переменной верхнего уровня. Что извлечение понимает, — в
  README пакета.
- **Графы проверяются:** узел, до которого не дойти; два узла одного имени;
  переход, который не прочесть, или значение перехода, которое не прочесть
  как переход к узлу; тип параметра перехода после схождения не совпадает с
  записью выходов; побочный эффект в переходе; граф, который служит узлом и
  может кончиться несколькими концами сразу, — предупреждения в `warnings`.
- **Документация — `doc` функций и эффектов:** у функции — её комментарий
  `///` (или `/** */`) над объявлением; у эффекта — `///` прямо над ним,
  над выражением, которое с него начинается, или над простым оператором
  (выражение, объявление переменной, `return`, `yield`), где он
  единственный эффект. Комментарий над оператором с несколькими эффектами,
  над `if`, циклом и другим составным оператором эффектам не достаётся;
  документацию функции из своего замыкания эффект не берёт.

  ```dart
  /// Takes the change of the branch: the one file named after it.
  var change = await f.effect('collect', () => collect(branch));
  ```

- **Переход по `switch`:** путь, который знает значение локальной переменной
  `switch`, идёт стрелкой прямо в её случай; `stage = X; continue loop` в
  `while (true) switch (stage)` — стрелка в узел X, без развилки.
- **Файл пишется, только если изменился;** пока отпечаток тот же, `builds`
  остаются, и `--check` их не сравнивает.
- **`stamp`** сначала сверяет `fingerprint` с исходниками: не совпал — код 1,
  ничего не пишется.
- **`--watch` описывает заново только после правки исходников.** Не
  описал, потому что пакеты не поставлены, — после `dart pub get` (или
  другой смены конфигурации пакетов) его перезапускают.

## Чтение

`FsReader(runsDir: …)` из [`nanoflow_reader`](packages/nanoflow_reader/README.md)
следит за всеми сессиями `runs/`: лента изменений и данные по запросу.

| `change`         | Свои поля                     | Когда                                                                          |
| ---------------- | ----------------------------- | ------------------------------------------------------------------------------ |
| `session-added`  | `session`                     | появилась сессия                                                               |
| `effect-added`   | `effect`                      | появилась запись эффекта                                                       |
| `effect-changed` | `effect`                      | запись эффекта переписана: появился `outputId` или при повторе — новый `after` |
| `event-added`    | `sessionId`, `event`          | в журнал дописано событие                                                      |
| `document-added` | `sessionId`, `documentId`     | документ записан целиком                                                       |
| `log-corrupted`  | `sessionId`, `line`, `text`   | строка журнала — не событие, номер с 1                                         |
| `owner-changed`  | `sessionId`, `owner`, `alive` | сменился владелец сессии или узнано, жив ли он; только пока журнал не кончился |

- **Сначала всё, что есть, потом новое.** События сессии — в порядке
  журнала, недописанная строка не выдаётся.
- **По запросу:** значение документа, лог эффекта — накопленный, потом
  дописанное.
- **Сессия закончена,** когда прочитано её последнее событие.
- **`owner-changed` — владелец и жив ли он.** `owner` — запись из
  `.owner.lock` или `null`. `alive`: `true` — идёт процесс с этим pid и этим
  временем старта; `false` — владельца нет, процесс вышел или pid у другого
  процесса; `null` — не узнать (нет времени старта, ОС не macOS, следить не
  вышло).
- **`owner-changed` — только пока журнал не кончился:** в первом чтении
  сессии — после её прочих изменений, потом при каждой смене пары (`owner`,
  `alive`). Владелец пишет последнее событие до того, как отпустит сессию
  или выйдет, поэтому штатно законченная сессия даёт `session-finished`, а
  не `alive: false`.
- **Выход процесса читатель узнаёт от ОС, без опроса:** порт `Processes` из
  [`nanoflow_process`](packages/nanoflow_process/README.md) (macOS —
  kqueue), `FsReader(processes: …)`; по умолчанию — адаптер этой ОС.
- **Читатель не запускают в процессе, который ведёт сессии** того же
  `runs/`: чтение `.owner.lock` сняло бы его блокировку.

## UI

[`apps/nanoflow_ui`](apps/nanoflow_ui/README.md) — приложение для macOS,
[ТЗ](docs/ui-spec.md).

- **Открывается файл графа** `nanoflow.graph.json`; сессии — из `runs/`
  рядом. Файл перечитывается при изменении.
- **Граф — функция воркфлоу:** вызовы — плитки-стопки, двойной клик
  проваливается в функцию, кнопка раскрывает её на месте; копии — рамка-стопка
  с переключателем копий.
- **Свежесть:** исходники рядом с файлом графа против `sources`, бинарник
  рядом против `builds`, код сессии против её снимка; предупреждения
  извлечения — списком.
- **Эффекты на графе — по месту вызова** (`place` эффекта и узла).
- **Пройденные развилки — по журналу**, без вычисления условий: эффект и
  код перед ним — переход по рёбрам уровня; развилка на каждом его пути
  пройдена и выглядит как пройденный эффект, `2×` — больше одного прохода;
  выход, которым код пойти не мог, темнее
  ([спецификация, §9 «Развилки»](docs/superpowers/specs/2026-10-03-code-first-design.md#9-ui)).
- **Interrupted:** незавершённая сессия, владельца которой нет
  (`owner-changed` с `alive: false`), — не «Running», а «Interrupted»; её
  можно продолжить.

## Проверки

```bash
tool/ci.sh
```

- **Workspace:** `dart pub get`, `dart format`, `dart analyze --fatal-infos`,
  `dart test` каждого участника из `pubspec.yaml` и
  `nanoflow_describe --check` примера.
- **UI:** `flutter pub get`, `flutter analyze`, `flutter test` в
  `apps/nanoflow_ui`.
- **`tests/e2e`:** пример запускается процессом под `dart run` и собранным,
  Ctrl+C и `--resume` доводят его сессию до конца; программа, убитая в эффекте
  (SIGKILL), продолжается другим процессом без повтора готовых эффектов; убитого
  в эффекте примера читатель за секунды называет ушедшим владельцем, а после
  `--resume` — живым новым, и после `session-finished` о владельце молчит;
  второй владелец сессии получает отказ; сессию, записанную хранилищем,
  читатель читает в те же модели; граф примера совпадает с ожидаемым.
