# nanoflow

Движок воркфлоу. Граф лежит в одном файле, узел — обычная команда, стрелка
может вести назад.

## Что это

- **Узел — команда.** Что она запускает, движок не знает: скрипт, программу,
  что угодно.
- **Узлов два типа:** рабочий узел и развилка.
- **Стрелка ведёт в любой узел**, в том числе в пройденный: отказ
  возвращает работу назад.
- **Данные между узлами типизированы.** Типы описаны JSON Schema; движок
  проверяет, что узел вернул обещанное, и что выход одного узла подходит
  входу следующего.
- **Команда может идти днями.** Таймаута нет, состояние лежит на диске, после
  перезапуска незавершённая команда выполняется заново.
- **Прогон может ветвиться.** Следующим можно назвать список узлов: прогон
  делится на независимые. Ветки не сливаются.
- **Прогоны независимы.** Пока один ждёт решения, остальные идут.
- **В графе нет вычислений**, условий и подстановок. Всё динамическое живёт
  внутри команд.

## Формат

Один файл YAML.

```yaml
start: collect

types:
  Request:
    {
      type: object,
      required: [branch],
      properties: { branch: { type: string } },
    }

  Change:
    {
      type: object,
      required: [id, path],
      properties: { id: { type: string }, path: { type: string } },
    }

  Report:
    {
      type: object,
      required: [change, findings],
      properties:
        {
          change: { $ref: "#/Change" },
          findings: { type: array, items: { type: string } },
        },
    }

nodes:
  collect:
    command: nodes/collect/run.sh
    in: { $ref: "#/Request" } # вход запуска
    out: { $ref: "#/Change" }
    then: is-empty # безусловный переход

  is-empty: # if
    decide: nodes/is-empty/run.sh
    in: { $ref: "#/Change" }
    then: discard
    else: inspect

  inspect:
    command: nodes/inspect/run.sh
    in: { $ref: "#/Change" }
    out: { $ref: "#/Report" }
    then: verdict

  verdict: # switch
    decide: nodes/verdict/run.sh
    in: { $ref: "#/Report" }
    then:
      accepted: [publish, notify] # разветвление
      returned: fix

  fix:
    command: nodes/fix/run.sh
    in: { $ref: "#/Report" }
    out: { $ref: "#/Change" }
    then: inspect

  publish:
    command: nodes/publish/run.sh
    in: { $ref: "#/Report" }

  discard:
    command: nodes/discard/run.sh
    in: { $ref: "#/Change" }

  notify:
    command: nodes/notify/run.sh
    in: { $ref: "#/Report" }
```

### Граф

| Поле    | Что значит                                                                                                |
| ------- | --------------------------------------------------------------------------------------------------------- |
| `start` | Цель, с которой начинается прогон. Вход даёт запуск, и движок сверяет его с `in` каждого стартового узла. |
| `types` | Именованные типы данных.                                                                                  |
| `nodes` | Узлы: рабочие и развилки.                                                                                 |

Цель — имя узла или список имён. Каждый узел списка получает те же данные.
Пустой список — никуда: прогон на этом заканчивается.

### Рабочий узел

| Поле      | Что значит                                         |
| --------- | -------------------------------------------------- |
| `command` | Что запускается: команда shell.                    |
| `in`      | Тип данных, которые узел получает. Необязателен.   |
| `out`     | Тип данных, которые узел возвращает. Необязателен. |
| `then`    | Цель. Без него прогон заканчивается.               |

### Развилка

| Поле     | Что значит                                                  |
| -------- | ----------------------------------------------------------- |
| `decide` | Что запускается: команда shell, которая решает, куда идти.  |
| `in`     | Тип данных, которые читает команда. Необязателен.           |
| `then`   | Цель или карта «исход → цель».                              |
| `else`   | Цель, если исход не совпал. Необязателен.                   |

Форма `if` — в `then` цель, форма `switch` — в `then` карта.

| Форма    | Исход совпал | Не совпал, `else` есть | Не совпал, `else` нет |
| -------- | ------------ | ---------------------- | --------------------- |
| `if`     | в `then`     | в `else`               | прогон заканчивается  |
| `switch` | в цель ключа | в `else`               | ошибка                |

Исход сравнивается с ключами `then` по точному значению. У `if` ключ один —
`true`: `"true"`, `1`, `null` и всё остальное не совпадают. Пустой
`else: []` — тоже `else`: ошибки нет.

Исходом может быть любое JSON-значение. Данные идут к целям сквозь развилку
без изменений, даже если `decide` их не читает.

### Типы

- **Типы — обычная JSON Schema.** В `in` и `out` всегда стоит схема;
  ссылка на тип из `types` — обычная её часть.
- **Совместимость — равенство.** `out` подходит к `in`, если после
  раскрытия ссылок схемы совпадают.
- **В `types` только сущности.** Массив пишется прямо в `in` или `out`
  узла, отдельным типом не объявляется.
- **Ссылка — `#/Имя`.** Корнем при валидации служит содержимое `types`.

## Протокол команды

Для каждой команды движок готовит каталог шага и передаёт путь к нему в
переменной окружения `NANOFLOW_STEP`. Протокол один на всех: прочитай
`input.json`, напиши `output.json`. Движок доставляет только объявленное:
без `in` нет `input.json`, у рабочего узла без `out` файл `output.json` не
ждут и не читают.

| Файл          | Рабочий узел                                              | Развилка                                                                                |
| ------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `input.json`  | Данные от предыдущего узла.                               | Данные, которые идут сквозь развилку.                                                   |
| `output.json` | Сюда команда пишет свои данные. Движок сверит их с `out`. | Сюда команда пишет исход: `true` или `"accepted"`. Движок ищет его среди ключей `then`. |

Остальное:

- **Команда запускается через `sh -c`** в каталоге файла графа: относительные
  пути в ней считаются от него.
- **Сбой** — ненулевой код завершения. То же самое — нулевой код, когда
  `output.json` ждут, а его нет, в нём не JSON, в том числе пустой файл, или
  данные не проходят `out`. Сбой — не исход: прогон он останавливает всегда,
  `else` его не ловит.
- **stdout и stderr** — логи. Оба потока идут в один файл `command.log` в
  том же каталоге, в порядке появления. В данные движок их не превращает,
  поэтому печатать можно что угодно.

Каталог шага — запись о нём: что пришло, что вышло.

## Хранение

Каталог `runs` по умолчанию лежит рядом с файлом графа, путь можно
переопределить при запуске.
Имя сессии — имя графа, время, короткий идентификатор.

```text
runs/
  workflow-2026-09-20T14-03-11-a1b2/      сессия
    k7f2/                                 прогон
      log.jsonl                           журнал событий прогона
      steps/
        2026-09-20T14-03-11-482-collect/  шаг: время начала и имя узла
          input.json                      вход запуска, настоящий файл
          output.json
          command.log                     stdout и stderr команды в порядке появления
        2026-09-20T14-05-40-117-is-empty/
          input.json                      симлинк на output.json шага collect
          output.json
          command.log
        2026-09-20T14-05-41-030-inspect/
    c3d4/                                 прогон после разветвления, устроен так же
```

- **Имя шага начинается со времени его начала** в UTC, с миллисекундами.
  Сортировка по имени совпадает с порядком шагов, и предела на их число нет.
- **Ничего не перезаписывается.** Повторный заход в узел — новый шаг, и
  история прогона читается по именам сверху вниз.
- **Сессию ведёт один процесс движка.** Поэтому при его старте незавершённый
  шаг не идёт, а оборван. Есть `output.json` — движок дописывает
  `step-finished` и идёт дальше. Нет — запускает команду заново в том же
  каталоге, `command.log` дописывается.
- **Вход запуска лежит в первом шаге**, если у стартового узла объявлен
  `in`. Положить его туда — ответственность запускающего.
- **`input.json` — относительный симлинк** на файл, где эти данные
  появились. Настоящий файл может быть только у стартового узла.
- **У прогона всегда один исполняемый шаг.**
- **Разветвление создаёт новые прогоны** в той же сессии, а прежний на этом
  заканчивается.

Состояние отдельно не хранится: оно получается проигрыванием `log.jsonl`
прогона. Движок в журнал только дописывает, по строке JSON на событие.

### События

Каждая строка `log.jsonl` — одно событие. Два поля есть у любого события:

| Поле    | Что значит                             |
| ------- | -------------------------------------- |
| `time`  | Время события в UTC, с миллисекундами. |
| `event` | Имя события.                           |

#### `run-started`

Прогон создан. Первая строка журнала.

| Поле     | Что значит                                                                   |
| -------- | ---------------------------------------------------------------------------- |
| `id`     | Идентификатор прогона. Совпадает с именем его каталога.                      |
| `graph`  | Абсолютный путь к файлу графа.                                               |
| `parent` | Идентификатор родительского прогона. У прогона, начатого запуском, — `null`. |
| `node`   | Узел, с которого прогон начинается.                                          |

#### `step-started`

Команда запускается.

| Поле   | Что значит         |
| ------ | ------------------ |
| `step` | Имя каталога шага. |
| `node` | Имя узла.          |

#### `step-finished`

Команда завершилась.

| Поле       | Что значит                                                                          |
| ---------- | ----------------------------------------------------------------------------------- |
| `step`     | Имя каталога шага.                                                                  |
| `exitCode` | Код завершения команды. `null`, если шаг закрыт после перезапуска по `output.json`. |

#### `run-split`

Путей дальше несколько: цель — список. Пишется после того, как созданы новые
прогоны. Своих полей нет: потомков находят по их `parent`. Если движок упал
посреди разветвления, после перезапуска он создаёт только недостающих
потомков.

#### `run-finished`

Идти некуда: у узла нет `then` или цель пуста. Своих полей нет.

#### `run-failed`

Сбой команды или ошибка маршрута.

| Поле    | Что значит                        |
| ------- | --------------------------------- |
| `step`  | Шаг, на котором это случилось.    |
| `error` | Одна строка о том, что случилось. |

Шаг с `step-started` без `step-finished` не завершён. Перезапуская его
команду, движок пишет новый `step-started`. `run-split`, `run-finished` и
`run-failed` — последняя строка журнала: без них прогон не закончен.

## Запуск

```bash
nanoflow create-session <граф> [--runs <каталог>]   # создаёт сессию и печатает её путь
nanoflow run <граф или сессия> [--runs <каталог>]   # ведёт сессию до конца
```

- **`run` от графа сам создаёт сессию** и сразу ведёт её. Этого хватает,
  когда у стартовых узлов нет `in`.
- **`create-session` нужен, когда есть вход.** Команд он не запускает, только
  создаёт сессию: по прогону на каждый узел из `start`, у каждого — каталог
  первого шага. Запускающий кладёт туда `input.json` и зовёт `run` от сессии.
- **`run` сверяет вход с `in` стартового узла.** Файла нет или он не
  проходит — прогон получает `run-failed`, команда не запускается.
- **Повторный `run` от сессии продолжает её** после падения движка.

## `nanoflow check`

**Структура файла** проверяется JSON Schema самого формата: она ловит
опечатки в ключах и не тот тип значения.

**Смысл**, которого схема не выражает:

- `$ref` указывает на существующий тип в `types`.
- Все цели — в `start`, `then`, `else` — называют существующие узлы.
- В списке целей нет повторов и не одно имя.
- `start` не пуст.
- Если у узла объявлен `in`, то у каждого рабочего узла, из которого в него
  можно прийти — напрямую или сквозь развилки, — объявлен `out`, и он
  совместим с этим `in`. Узел без `in` законен после любого.
- До каждого узла можно дойти по стрелкам от какого-нибудь узла из `start`.

Тот же код работает при старте: движок не идёт по невалидному графу.
